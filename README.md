# 옹기봇 · Alpha 0.1 (alpha.14 소스)

바탕화면에서 꼬물꼬물 움직이는 작은 친구에게 질문하고, 로컬 Codex CLI의 답변을 말풍선으로 받는 Electron 앱입니다. 캐릭터는 실행 코드가 없는 팩으로 교체합니다. 현재 실행 검증 환경은 macOS Apple Silicon이며 Windows를 고려한 창·아이콘 처리를 포함합니다. Windows 네이티브 실행·배포는 아직 검증하지 않았습니다.

미니 말풍선·스킨·캐릭터별 Markdown 말투 모드를 추가했습니다. [최신 사례 비교·설계·검증 보고서](docs/BUDDY_MODES_REVIEW.md)

alpha.14/build29은 이미지·파일 첨부와 일반/미니 대화의 선입선출 대기열을 지원합니다. 입력창의 `이미지 첨부`·`파일 첨부`로 선택한 뒤 보내면 질문과 첨부 사본을 함께 보관합니다. 작업 중 전송한 질문은 최대 10개까지 대기하며 앞 작업의 종료 저장 후 차례대로 실행합니다. [구현·검증·제한](docs/ATTACHMENTS_AND_QUEUE_2026-10-10.md)을 참고합니다.

alpha.13/build28에서 추가한 연결 복구·로그인 안내와 생성 이미지 표시도 포함합니다. 연결이 끊기면 한 번 자동 복구를 시도하며, 대화창의 `다시 연결`·`ChatGPT로 로그인`·`자동으로 다시 찾기`로 직접 복구할 수 있습니다. 이미지가 빠진 기존 대화는 `결과 다시 확인`으로 CLI 기록을 읽어 복원합니다. [변경 내용·검증·사용 방법](docs/CONNECTION_AND_IMAGES_2026-10-08.md)을 참고합니다.

이미지 decode·정숙/절전·MD 관리·팩 미리보기/업데이트/보관/복원·v2 눈 깜빡임·배율을 지원합니다. 이전 버전의 수정/측정/전달은 [검토 이력](docs/history/README.md)에 모았습니다. 현재 구조와 제한은 [ARCHITECTURE](docs/ARCHITECTURE.md)를 따릅니다.

이 PC의 일반 실행 경로는 `dist/OnggiBot-darwin-arm64/OnggiBot.app`입니다. 이전 앱의 보존 위치와 현재 패키징 검증은 [첨부·대기열 적용 기록](docs/ATTACHMENTS_AND_QUEUE_2026-10-10.md)을 따릅니다. Windows 실기 검증은 남아 있습니다.

## 실행

이 PC용 최신 Apple Silicon 앱: `dist/OnggiBot-darwin-arm64/OnggiBot.app`을 실행합니다. 이미 실행 중이면 바탕화면 버디나 메뉴 막대에서 대화창을 엽니다.

- 캐릭터 또는 작은 말풍선을 클릭하면 대화창이 열립니다.
- 캐릭터 하단의 대화·잠자기·설정 메뉴는 마우스를 올리면 나타나고 3초 뒤 숨습니다. 다시 캐릭터에 마우스를 올리면 나타나며, 메뉴에 포커스가 남아 있어도 계속 표시하지 않습니다.
- 바탕화면 캐릭터는 기본 50%, 설정에서 35/50/65%로 표시합니다. 기본 캐릭터는 75×95px입니다. 초기 대기 안내는 3초 후 사라집니다. 캐릭터에 마우스를 올리면 유지하고, 치운 뒤 3초 후 숨깁니다. 작업 중·승인 대기 안내는 해당 상태 동안 유지합니다.
- 캐릭터 본체를 누른 채 드래그하면 원하는 위치로 옮깁니다. 이동 중에는 안내와 흔들림을 숨기고 마지막 위치를 저장합니다. 기본 캐릭터 창은 안내 유무와 관계없이 120×143px이며, 안내는 별도 196×52px 투명 창에 표시합니다. 투명 여백은 뒤쪽 앱의 클릭을 통과시킵니다.
- Dock/작업 표시줄 영역이나 화면 밖으로 이동할 수 있습니다. 안내가 열려도 캐릭터 위치는 유지합니다. 보이지 않으면 트레이/메뉴 막대의 `버디 위치 초기화`로 되돌립니다. 재실행·화면 구성 변경 시 보이지 않는 위치는 자동 복구합니다. [플로팅 동작·검증 범위](docs/FLOATING_PET_UPDATE.md)
- macOS의 `⌘ + Shift + Space`로 대화창을 엽니다. Windows 대응 키는 `Ctrl + Shift + Space`이며 Windows 실기 검증은 후속 작업입니다. 단축키 충돌 시 트레이/메뉴 막대 아이콘을 사용합니다.
- `Enter`로 보내고 `Shift + Enter`로 줄을 바꿉니다. 한글 조합 중 Enter는 전송하지 않습니다.
- 입력창은 여러 줄에 맞춰 높이가 늘어나고, 지난 답변을 읽을 때 나타나는 `맨 아래로`로 최신 내용에 돌아갑니다. 여백·정렬·글씨와 작은 창 구성을 개선했습니다. [UI·UX 변경과 검증](docs/UI_UX_REFINEMENT.md)
- 긴 대화는 최근 최대 100개/약 256KiB 텍스트부터 표시하고, 위쪽의 `이전 내용 더 보기`로 앞선 메시지를 추가합니다. 저장 기록은 삭제하지 않습니다.
- `이전 대화`에서 옹기봇 대화만 검색·선택하고 같은 대화를 이어갑니다. 항목 오른쪽 `삭제`→확인 창의 `영구 삭제`로 로컬 기록과 연결된 실제 CLI 세션을 삭제합니다. CLI 파생 세션도 삭제되며 기존 복구 백업은 유지합니다. [삭제 범위·실패/재시도](docs/DELETE_CONVERSATIONS.md)를 참고합니다. 새 대화를 만들어도 지난 기록은 보존합니다.
- 입력창 안쪽 하단에서 말투는 왼쪽, 모델·추론 표시는 보내기 버튼 바로 앞에 배치합니다. 반복 단축키 문구는 제거했고 보내기 버튼에 마우스를 올리면 안내가 나타납니다. 테두리 없는 작은 모델 버튼을 누르면 모델·추론 단계·Standard/Fast 속도와 목록 새로고침을 팝업에서 선택합니다. Fast는 번개로 표시합니다. 팝업 밖을 누르거나 Esc로 닫고, 변경은 다음 질문부터 적용하며 대화는 이어집니다. 모델 조회/오류 안내는 필요할 때만 표시합니다.
- 앱 기본 모델은 `gpt-5.6-luna`, 추론 단계는 `high`입니다. 직접 선택한 설정은 이후 실행에도 유지됩니다.
- 답변은 Markdown 제목·목록·표·인용·코드·링크로 표시합니다. 전체 `복사`는 원문, `코드 복사`는 해당 코드 블록입니다.
- 상단은 `대화`·`이전 대화`이며 우측 톱니바퀴로 설정을 엽니다. `수신 대답속도 측정`을 켜면 새 질문의 입력→앱 수신→CLI 전송→응답 완료→화면 반영 시간과 첫 응답·큐 대기·전체를 `mm:ss.ffff`로 표시합니다. [측정 기준과 제한](docs/RESPONSE_TIMING.md)을 참고합니다.
- 설정의 `화면과 대화`에서 종이와 올리브·고요한 밤·흑백 갤러리 스킨과 `미니 말풍선 열기`를 선택합니다. 미니 말풍선은 최근 한 쌍의 질문/답변을 표시하고 `↗`로 같은 대화를 넓게 펼칩니다.
- 입력창 하단 왼쪽에서 친절·상냥한 장문·핵심 단답·퉁퉁이 모드를 바꿉니다. 두 기본 캐릭터에 각각 독립된 기본 성격과 네 모드가 있습니다. 설정의 접힌 Markdown 편집에서 수정하거나 `MD 폴더`를 열어 파일을 직접 수정합니다.
- 설정에서 저장된 MD를 복제하고 사용자 말투의 이름 변경·보관·복원을 합니다. 기본 내용 복원은 선택한 MD를 백업한 뒤 제공 템플릿으로 돌립니다. 편집 초안은 MD 저장 전까지 메모리에만 있습니다.
- 캐릭터 팩은 먼저 미리보기로 검사합니다. 업데이트는 편집 MD를 유지하며 제거는 원본 팩을 보관합니다. 내보내기는 참조 이미지/manifest/MD만 포함하고, 편집 말투 포함은 기본 꺼짐입니다.
- 정숙은 장식 움직임과 자동 승인창 열기를 줄이고, 일상은 대기 안내를 숨깁니다. 생동감은 v2 눈 깜빡임 팩에서 프레임 동작을 켭니다. 잠금은 동작/표시 ACK를 억제하고, 절전은 현재 작업을 중단하며 복귀 후 대기 질문은 `계속`을 눌러 재개합니다.
- 설정에서 캐릭터, 움직임 줄이기, 배터리 움직임 절약, 항상 위에 표시, 작업 폴더, Codex 실행 파일을 선택합니다.
- 설정의 `친구 이름`에 1~20자를 입력하고 `저장`하면 버디의 표시 이름을 바꿉니다. 상단·답변 이름·입력 안내·트레이 설명에 적용하고 재실행·캐릭터 변경 후에도 유지합니다. 기본값은 `옹기봇`이며 대화 원문과 실제 CLI 입력은 변경하지 않습니다.
- 처음에는 실제 Codex 모드입니다. `체험 모드`를 켜면 모델 호출 없이 UI를 체험합니다.
- 대화창의 `×`와 `Esc`는 창을 숨깁니다. 프로그램 종료는 메뉴 막대의 `종료`입니다.

macOS 직접 설치용 로컬 알파 빌드이며 서명·공증하지 않았습니다. 다른 PC에 배포할 서명된 설치 프로그램은 후속 작업입니다.

개발 환경은 Node.js 22.13 이상(22.x) 또는 24 이상과 npm이 필요합니다. 검증한 환경은 Node.js 24.21.0입니다. OS별 준비·실행·패키징·결과물·Windows 검증 한계는 [macOS·Windows 빌드 가이드](docs/BUILD_GUIDE.md)를 참고합니다.

```sh

npm start
```

모델 호출 없는 체험 실행:

## Codex 준비

실제 대화에는 설치된 Codex CLI와 해당 제공자의 인증이 필요합니다. 앱이 CLI 위치·작업 폴더·인증·모델 목록을 확인하고 문제가 있으면 대화창에 해결 버튼을 보여줍니다. 연결만 끊겼다면 `다시 연결`, 로그인이 필요하면 `ChatGPT로 로그인`을 누릅니다. 설치 위치가 달라졌다면 `자동으로 다시 찾기`를 사용합니다. 못 찾으면 `설치 안내`를 열어 Codex를 설치한 뒤 다시 찾습니다. 작업 폴더가 없어졌다면 `작업 폴더 선택`으로 바꿉니다.

로그인은 기본 브라우저의 공식 HTTPS 주소에서 진행하고 완료를 앱이 확인합니다. 기존 CLI 로그인은 재사용합니다. 로그인 취소·5분 대기 만료는 해당 로그인 시도만 취소하며 공용 CLI 계정에서 로그아웃하지 않습니다. CLI 위치 변경은 이전 대화를 보존하고 새 대화를 준비합니다. 최초 연결 검토의 현재 구현·남은 범위는 [갱신 기록](docs/FIRST_RUN_REVIEW.md)을 참고합니다.

터미널로 확인할 때:

```sh
codex --version
codex login
codex login status
```

이번 연결·이미지 확인에 사용한 CLI는 `codex-cli 0.162.0-alpha.2`입니다. 이전 실제 대화 검증은 0.160.0에서 수행했습니다. GUI로 실행된 앱의 PATH는 터미널과 다를 수 있어 절대 실행 파일 경로도 지원합니다. 초기 작업 폴더는 앱 데이터 아래의 빈 `workspace`입니다. 프로젝트 질문을 하려면 설정에서 해당 폴더를 선택합니다. 작업 폴더·CLI 연결을 변경하면 현재 대화를 목록에 보존하고 새 대화를 준비합니다. 이전 대화를 열면 해당 대화의 작업 폴더·CLI 연결도 복원합니다.

연결은 `codex app-server --listen stdio://`의 JSONL 프로토콜을 사용합니다. 사용자 질문은 원문으로 JSON 입력에 전달하며 셸 명령 문자열에 끼워 넣지 않습니다. 계정과 모델 제공자는 로컬 CLI 설정을 사용합니다. 모델·추론 단계는 앱에서 질문별로 지정할 수 있습니다. 앱이 로컬에서 실행돼도 OpenAI 모델 사용에는 네트워크와 계정 이용량이 필요합니다.

`CLI 기본값`과 `기본 추론`을 함께 선택하면 CLI의 유효 설정으로 돌아갑니다. 모델을 직접 선택한 뒤 `기본 추론`을 선택하면 해당 모델의 카탈로그 기본 단계를 사용합니다. `↻`는 모델 목록과 CLI 기본 설정을 다시 조회하며 모델을 호출하지 않습니다. 목록과 모델별 추론·Fast 옵션은 CLI 응답을 사용합니다. 대화창을 열거나 포커스·모델 선택 영역에 접근하거나 질문을 보낼 때 5분 캐시가 만료되면 자동 재조회합니다. CLI 실행 파일이 변경되면 유휴 상태에서 새 프로세스에 연결해 다시 조회합니다. 작업 중에는 CLI 교체를 다음 유휴 사용까지 미룹니다. 표시된 목록이 계정의 모든 모델 실행 권한을 보장하지는 않습니다. 실행 실패 시 다른 모델로 자동 변경하지 않습니다.

Fast는 CLI가 해당 모델에 제공할 때만 선택할 수 있고 사용량이 증가합니다. 속도의 앱 기본값은 Standard이며 CLI 전역 설정은 수정하지 않습니다. 모델 변경으로 기존 속도가 미지원이 되면 Standard로 돌아갑니다.

각 질문은 전송 시 모델·추론 단계·속도를 기록합니다. 실행 중 설정을 바꿔도 이미 대기 중인 질문의 모델은 바뀌지 않습니다. 앱 자체 설정만 저장하며 사용자의 Codex 전역 설정 파일은 수정하지 않습니다. 자세한 확인 결과는 [Markdown과 모델 설정](docs/MARKDOWN_MODELS.md)에 있습니다.

알파는 `read-only`에서 시작합니다. 읽기 범위를 선택한 작업 폴더로 제한한다는 보장은 없습니다. 범위는 Codex CLI 권한 설정을 따릅니다. 명령·파일 변경 승인 요청은 대화창에서 허용·거절·취소할 수 있습니다. 별도 권한 프로필 요청은 알파에서 추가 권한을 부여하지 않습니다. 지원하지 않는 도구 요청은 거절하거나 오류로 응답합니다.

참고: [App Server](https://learn.chatgpt.com/docs/app-server), [Codex 인증](https://learn.chatgpt.com/docs/auth).

## 캐릭터 팩

기본 팩은 클리피의 종이클립 형태를 참고해 직접 작성한 SVG `옹기 클립`, 교체 검증용 `새싹 옹기`입니다. 제공된 참고 이미지 파일을 앱에 복사하지 않았습니다.

`톱니바퀴 설정 → 캐릭터 팩 가져오기`에서 `manifest.json`이 있는 폴더를 선택합니다. 실행 중에도 교체할 수 있으며 대화·Codex 연결은 이어집니다. 자세한 규격과 예시는 [캐릭터 팩 규격](docs/CHARACTER_PACKS.md)에 있습니다.

## 기록과 요청 처리

- 설정·대화 목록을 `state.json`, 대화별 메시지를 `conversations/<id>.json`에 저장합니다. 기존 120개 메시지 제한은 제거했으며 파일 하나의 크기는 32MiB까지입니다.
- 목록은 이 설치의 옹기봇이 기록한 대화만 포함합니다. 다른 Codex 앱·CLI 대화는 가져오지 않습니다. 기존 알파에 남아 있는 현재 대화는 원본 백업 후 자동 이관합니다.
- 제목·최근 내용으로 검색하고 목록에서 열어 같은 Codex 대화를 이어갑니다. CLI 기록 조회가 실패해도 로컬 기록을 표시합니다. 자세한 동작과 복구 범위는 [이전 대화](docs/CONVERSATIONS.md)에 있습니다.
- Codex 대화 ID를 저장해 앱 재시작 후 이어갑니다. CLI 자체 기록은 CLI가 관리합니다.
- 일반·미니 대화 모두 한 번에 한 질문을 처리합니다. 실행 중에도 최대 10개 질문을 대기시키며 첨부·모델·말투는 접수 당시 값으로 보관합니다. 대기줄에 질문 순서·내용·첨부 개수와 개별 취소를 표시합니다.
- 이미지(PNG/JPEG/WebP)·파일을 최대 8개, 각각 16MiB·합계 32MiB까지 첨부합니다. 선택 시 보관한 사본을 보내므로 원본이 바뀌어도 이미 접수한 자료는 유지합니다. 텍스트/코드 파일의 실제 읽기를 검증했고 PDF·Office 등은 CLI의 도구·환경에 따라 읽기 가능 여부가 다릅니다.
- 첨부만 보내면 `첨부한 자료를 확인해주세요.`로 질문합니다. 전송 전 `×`로 제거할 수 있고 채팅 카드에서 이미지 원본 또는 파일 저장본 위치를 엽니다. 체험 모드에서는 첨부를 실제 모델에 보내지 않습니다.
- 대기 질문은 개별 취소할 수 있고, 실행 중 질문은 `중단`으로 취소합니다.
- 종료·절전·연결 중단 후 불확실한 요청은 중단 상태로 남기고 자동 재실행하지 않습니다.
- 대화·목록 파일 교체 중 종료되면 저장 저널을 검사해 복구합니다. 확인값이 맞지 않으면 원본을 보존하고 복구 필요 안내를 표시합니다. 완료 답변 저장 실패 시 다음 대기 질문을 실행하지 않습니다. 자세한 저장 방식은 [로컬 안정화 보고서](docs/LOCAL_STABILITY.md)에 있습니다.
- 상태 파일 자체가 손상되면 백업한 뒤 새 기록으로 시작합니다.
- 설정의 `내 기록 · 캐릭터 폴더 열기`로 실제 저장 위치를 확인합니다. macOS 기본 위치는 `~/Library/Application Support/OnggiBot/`입니다.
- 화면을 숨겨도 진행 중인 작업의 수신은 메인 프로세스가 계속 담당합니다. 숨겨진 캐릭터 애니메이션은 정지합니다.
- CLI의 생성 이미지와 성공한 MCP 도구의 PNG/JPEG/WebP 이미지 응답을 답변 카드에 표시합니다. 미리보기는 최대 512px, `원본 열기`는 수정하지 않은 원본 파일을 엽니다. 이미지 데이터는 `response-images/`에 저장하고 대화에는 참조만 기록합니다.
- 이전 버전에서 이미지가 빠진 대화는 대화 목록에서 열거나 `결과 다시 확인`을 누릅니다. 소유 CLI 기록을 조회하며 새 이미지를 생성하지 않습니다. 생성 실패·사용량 한도·중단·이미지 저장 실패는 해당 카드에 안내합니다.

기록은 평문입니다. 인증 토큰은 앱 기록에 저장하거나 캐릭터 팩에 넣지 않습니다. Codex 로그인을 재사용합니다.

## 검증과 빌드

```sh
npm run check       # 구문, 기본 캐릭터 팩 규격
npm run lint        # JS 미정의/미사용 변수·CSS 구문/값/중복 속성
npm test            # JSONL, 오류 복구, 팩 경계, 저장 복구
npm run smoke:attachments # 이미지/파일 사본·미니 FIFO·취소·기록 복원, 테스트 CLI
npm run smoke:connection-images # 테스트 CLI 로그인/재연결·이미지 표시, 실제 인증/모델 호출 없음
npm run smoke:stability # 화면 복구·숨김 캐시·미니 표시·긴 원문 보존
npm run smoke:resources # 움직임/줄이기/숨김 각 10분, 실제 모델 호출 없음
npm run smoke       # 네이티브 UI, 체험 대화, 교체, FIFO, 취소
npm run smoke:pointer # 수동 마우스 검증: 투명 여백 뒤 주황 버튼 클릭 후 자동 종료
npm run smoke:floating # 플로팅 창·화면 경계·말풍선 앵커 검증
npm run smoke:performance # 1000개 기록·변경분 IPC·추가 로드·용량 경계 검증
npm run smoke:timing # 모델 호출 없이 구간·FIFO 대기·화면 반영·토글 검증
npm run smoke:delete # 테스트 CLI로 삭제·취소·실패·재시도·보존 검증
npm run codex:delete-smoke # 실제 검증용 세션 생성/응답/삭제 (계정 이용량 사용)
npm run smoke:history # 모델 호출 없는 대화 목록·검색·재개·격리·재시작 검증
npm run smoke:models # 모델 호출 없는 테스트 CLI: 모델 변경·추론·대기 질문 고정
npm run codex:smoke # 실제 모델 호출: 응답·재연결·재개·소유 턴 중단·검증 thread 보관
npm run smoke:real  # 실제 모델 호출: 네이티브 UI에서 질문/응답
npm run smoke:integration # 격리 UI 13종, 실패 시 비정상 종료; 실제 모델 호출 없음
npm run verify:package # staging ASAR·worker·아이콘·큰 이미지·첨부 사본 검사
npm run smoke:packaged-resources # staging ASAR 자원 측정, 각 10분
npm run codex:attachments # 실제 Luna/high 이미지·파일 입력 (계정 이용량 사용)
npm run package     # 현재 운영체제/CPU용 앱 생성
```

실제 모델 검증은 계정 이용량을 사용합니다. `smoke`는 실제 모델을 호출하지 않습니다. 검증 화면과 결과는 `artifacts/`에 저장하며 배포 앱에는 포함하지 않습니다.

캐릭터 SVG 재생성: `npm run characters:generate`. 앱/메뉴 막대 PNG와 Windows ICO 재생성: `npm run icons:generate`. 사용자가 제공한 `assets/tray-source.png`를 공통 원본으로 사용합니다. macOS 메뉴 막대는 투명한 18px와 Retina용 36px를 템플릿 이미지로 표시하고, 앱/Windows 트레이는 같은 그림에 밝은 바탕을 넣습니다. 앱 상단 로고도 같은 그림을 스킨 색상으로 표시합니다. macOS `.icns` 재생성은 [개발 구조 문서](docs/ARCHITECTURE.md)를 참고합니다.

통합 검사는 `npm run smoke:integration -- attachments connection-images`처럼 필요한 사례만 선택할 수 있습니다. 새 체크아웃에서도 개인 이미지 기록 없이 실행하며, 출력/프로필은 `ONGGI_SMOKE_ROOT`로 지정합니다. 패키지 검사는 `--archive <app.asar>` 또는 `--installed`, 개인 기록 복원은 base64 이미지 결과가 포함된 JSON에 선택형 `--image-items <items.json>`을 사용합니다. 이 검사는 격리 사본만 만들며 사용자 대화를 수정하지 않습니다. [현재 정리 결과](docs/CLEANUP_RESULT_2026-10-10.md)를 참고합니다.

## 알파 범위와 다음 단계

Slack 연동, 의미 기반 감지, 공용 서버·브로커, 음성, 자동 화면 배회, ZIP 팩 설치, 앱 설치 파일 자동 업데이트는 아직 구현하지 않았습니다. Markdown의 raw HTML과 이미지 자동 로딩, 코드 구문 강조, 수식·체크박스 확장은 미지원입니다. 캐릭터 움직임은 상태별 자세·본체 CSS와 v2 전체 공통 캔버스 눈 깜빡임 프레임을 지원합니다. 임의 스크립트·SVG 내부 CSS·3D 모델·atlas/crop·범용 애니메이션 타임라인은 지원하지 않습니다.

작업 범위·완료 기준·후속 작업은 [TASKS.md](TASKS.md), 검증 근거와 제한은 [알파 검증 보고서](docs/ALPHA_REPORT.md)에 기록합니다.

현재 우선순위는 로컬 대화의 안정화와 긴 기록 처리이며 Slack 호출·키워드 알림은 후순위입니다. 다중 클라이언트 FIFO 서버는 이후 과제입니다. 구조·최적화·남은 이슈와 기술 선택 이유는 [프로젝트 검토 보고서](docs/PROJECT_REVIEW.md)에 정리했습니다.
