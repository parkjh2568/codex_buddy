# Alpha 0.1 (alpha.9) 검증 보고서

alpha.9의 플로팅 창·자유 이동·복구 및 Windows 준비 항목은 [플로팅 버디 보완 보고서](FLOATING_PET_UPDATE.md)에 별도로 기록했다. 아래 표는 이전 알파 기능의 누적 검증 근거이며 Windows 네이티브 결과는 포함하지 않는다.

검증일: 2026-10-06. 환경: 사용자의 macOS Apple Silicon, Node.js 24.21.0, Electron 44.5.1, Codex CLI 0.160.0. 시작 시 프로젝트 폴더는 빈 상태였으며 기존 코드·문서는 없었습니다.

## 완료한 결과

움직이는 클리피 기반 SVG 캐릭터, 교체용 새싹 캐릭터, 투명 캐릭터 창, 말풍선 대화, 로컬 Codex 연결, FIFO 대기·취소, 설정·기록 저장, 폴더형 캐릭터 팩 설치를 구현했습니다. Slack과 공용 서버는 후속 작업입니다.

## 발견한 이슈와 조치

1. 설치 CLI의 생성 스키마와 공식 문서에는 제한된 읽기 `readOnly.access`가 있지만, 실제 `turn/start`에서 해당 필드를 거부했습니다. 지원되는 `readOnly` 설정으로 실행하고 폴더 외부 읽기 제한을 보장하지 않는 점을 UI·README에 명시했습니다. 세부 권한 프로필 지원은 후속 호환성 작업입니다.
2. GUI 앱과 터미널의 PATH 차이를 고려하여 일반 설치 경로를 탐색하고 절대 CLI 경로 선택을 제공했습니다.
3. 캐릭터 데이터를 모든 응답 갱신에 반복 전송하지 않고 카탈로그 변경 때 전송하도록 개선했습니다. 스트리밍 렌더링은 50ms로 묶고 완료는 즉시 예약합니다. 캐릭터 창에는 필요한 상태만 전달합니다.
4. 초기화·턴·서버 승인 요청을 구분하고 대화/턴 ID를 검사합니다. 지원하지 않는 요청을 방치하지 않습니다.
5. 비정상 종료 후 불확실한 작업의 중복 실행을 방지하도록 자동 재시도를 하지 않습니다. 실행 중 부분 화면 응답은 손실될 수 있습니다.
6. 캐릭터 이미지를 50%로 줄인 뒤에도 원래 250×270 창이 남아 있었습니다. 대기 창을 120×143으로 줄이고, 숨겨진 버튼의 클릭 영역을 제거했습니다. 마우스 이동과 정지 시 모두 클릭 통과를 갱신하고 절대 좌표 기반 드래그로 중복 이동을 방지합니다.
7. 기존 한국어 답변의 `**알파인 리눅스(Alpine Linux)**는`이 원래 CommonMark 규칙 때문에 강조되지 않았습니다. CJK 강조 플러그인을 적용하고 코드/이스케이프를 손상하지 않는지 회귀 검사했습니다.

기존 알파의 현재 대화는 백업 후 목록으로 이관합니다. 과거 `새 대화`로 로컬 연결 정보를 잃은 세션은 출처를 확정할 수 없어 자동으로 가져오지 않습니다.

## 현재 제한

- macOS Apple Silicon에서 검증했습니다. Intel·Windows·Linux는 검증하지 않았습니다.
- Markdown 기본 서식을 지원합니다. raw HTML·원격 이미지 자동 로딩·코드 구문 강조·수식·체크박스 확장·첨부 파일·음성·3D·프레임 타임라인은 미지원입니다.
- 임의 권한 프로필 부여는 미지원이며 해당 요청에 빈 권한으로 응답합니다.
- 단일 활성 질문, 최대 10개 대기, 10분 실행 제한, 대화 파일당 32MiB 제한을 사용합니다.
- 서명·공증·자동 업데이트는 미지원입니다. 현재 .app은 이 PC에서 직접 실행하는 로컬 알파입니다.
- 대화별 JSON 파일과 작은 목록 인덱스 저장을 선택했습니다. 장기간 검색·다중 프로세스 저장이 필요할 때 DB 전환을 검토합니다.
- 리소스 사용량의 장시간 벤치마크와 알림 정확도 측정은 아직 하지 않았습니다.

## 코드·문서 정리

사용하지 않는 Slack 모듈, 범용 플러그인 프레임워크, 서버, DB, 브로커를 만들지 않았습니다. Markdown 파서와 정제 라이브러리는 런타임 의존성으로 고정하고, Electron과 패키징 도구는 개발 의존성입니다. 캐릭터/아이콘 생성 스크립트는 재생성 명령과 문서로 연결했습니다. 검증 산출물과 테스트·개발 스크립트는 배포 앱에서 제외합니다.

Codex를 사용하는 이점은 로컬 CLI 인증·모델 설정·대화 재개·도구·승인 체계를 재사용하는 것입니다. 캐릭터 팩은 그 실행 체계와 독립되어 외형 교체 시 연결을 다시 만들 필요가 없습니다.

## alpha.6 보완

상단 대화/이전 대화·설정 톱니바퀴, 선택형 응답 시간 측정, 캐릭터 IPC 최소화, 설정 전용 저장, 모델 선택 중 자동 목록 갱신 보류를 적용했습니다. `artifacts/timing-ui-smoke.json`은 첫/최종 응답·FIFO 대기·형식·합·숨겨진 화면 ACK·옵션 꺼짐·저장을 검증합니다. `artifacts/real-response-timing.json`은 실제 Luna/high 질문의 시각을 기록합니다. 이는 한 번의 왕복이며 평균 또는 Fast 향상 비율이 아닙니다.

신규 UI는 `artifacts/alpha-response-timing.png`로 확인합니다. 자세한 경계는 [RESPONSE_TIMING.md](RESPONSE_TIMING.md), 문제 해석·전제·기술 흐름·데드코드·남은 최적화는 [PROJECT_REVIEW.md](PROJECT_REVIEW.md)에 기록했습니다. GUI 실행의 기본 sandbox에서는 Electron이 SIGABRT로 시작하지 못해 허용된 네이티브 실행 환경에서 검증합니다.

최종 실제 Luna/high·Standard 1회: 입력 0.80ms, 전송 준비 306.02ms, CLI 완료 4897.18ms, 화면 반영 13.91ms, 전체 5217.90ms. 테스트 프로필과 실제 앱 기록은 분리합니다. Fast 비교 벤치마크나 장시간 리소스 검증은 하지 않았습니다.

alpha.6 최종 패키징 앱을 실행하여 대화/이전 대화 두 탭, 설정 톱니바퀴, 측정 옵션(기본 꺼짐), 버전 표기, 기존 대화 보존, GPT-5.6-Luna/high와 사용자가 선택한 Fast 유지, CLI 연결 완료를 네이티브 접근성 트리로 확인했습니다. 현재 앱을 실행 상태로 남겼습니다.

alpha.6 빌드 9에서는 모델·추론·속도의 반복 요약을 정상 상태에서 숨기고 별도 하단 연결 footer를 제거했습니다. 모델 조회/오류 안내는 필요할 때 표시하며, 기존 연결 정보는 상단 연결 표시의 도움말과 설정에 유지합니다. 모델 선택 줄 아래 여백은 10px입니다.

## alpha.7 로컬 안정화

핵심 테스트 23개 통과: 기존 14개 + 저장 실패 등록 롤백·저널 두 교체 지점 복구·변조 거절·초기 설정 저장·대화 전환 실패·32MiB 경계 6개 + 큰/여러/초과 CLI 프레임 3개. 별도 performance UI에서 1000개 기록 보존, 100→200개 추가, 스크롤 위치·재개·변경분·용량 접수 거절·큰 메시지 제한을 검증했습니다. timing UI는 완료 저장 실패 때 다음 질문이 CLI에 전달되지 않는 것도 검증합니다.

모델·기록·시간·Markdown·캐릭터 UI 및 실제 Luna/high 왕복이 통과했습니다. 실제 CLI 프레임 한도는 64MiB이고, 패널의 초깃값은 최대 100개/약 256KiB 텍스트입니다. 자세한 결과와 남은 제한은 [LOCAL_STABILITY.md](LOCAL_STABILITY.md)에 기록합니다. Slack은 후순위로 이동했으며 아직 구현하지 않았습니다.

alpha.7 최종 .app 실행에서 버전, 기존 대화 목록 2개와 메시지 개수, Luna/high·Fast, 켜져 있던 응답 시간 설정, CLI 연결, 간결한 하단 배치를 확인했습니다. 앱을 실행 상태로 남겼습니다. ASAR는 646,017 bytes이며 불필요한 node_modules 원본이 없고 renderer 번들·외부 고지·THIRD_PARTY_NOTICES.txt를 포함하는지 검사했습니다.

## alpha.8 대화 삭제

이전 대화 삭제 버튼/확인 창, 실제 CLI thread/delete와 로컬 JSON/인덱스/임시 파일 제거, pending/부분 완료 삭제 저널을 추가했습니다. 핵심 28개와 삭제 UI 검증을 수행합니다. 실제 CLI 0.160.0에서 검증용으로 생성한 저장된 세션만 삭제해 rollout 파일 제거·재조회 거절을 확인했습니다. 삭제 알림은 응답 이후 도착할 수 있고 반복 삭제는 no rollout 오류를 반환하는 것을 확인해 해당 ID의 부재를 재확인한 경우만 로컬 정리를 계속합니다.
