# 따뜻한 편집 UI 작업 계획

2026-10-22 사용자가 선택한 따뜻한 편집 구성을 대화·기록·설정에 적용했다. WE01–WE10 구현·기본 검사 289개, WE11 대표 화면 행렬·최종 통합 15개, WE12 build42 정적/ASAR 실행을 마쳤다. [구현 결과](../history/WARM_EDITORIAL_UI_RESULT_2026-10-22.md)에 실행 근거와 실기/설치 수용 한계를 기록한다. 아래는 작업의 설계·수용 기준이며, 현재 UI 사용 규칙은 [대화 UI](../UI_UX_REFINEMENT.md)를 따른다.

현재 동작 계약은 [대화 UI](../UI_UX_REFINEMENT.md), 검증된 후보는 [릴리스 현황](../ALPHA_REPORT.md), 실행 상태는 [TASKS](../../TASKS.md#따뜻한-편집-ui)를 따른다. 기존 클래식 대표 화면 검증은 새 UI 수용 증거로 재사용하지 않는다.

## 디자인 결정

- 기본 `paper` 스킨의 팔레트와 현대 화면의 배치를 개선한다. ID는 유지하고 표시 이름은 `따뜻한 종이`로 정리한다. 기존 paper 사용자는 새 팔레트로 표시되며 설정 이관은 추가하지 않는다.
- `night`·`mono`의 팔레트와 `classic`의 노란 말풍선·회색 창·입체 컨트롤은 유지한다. 공통 HTML·CSS·기하 변경의 영향은 4스킨에서 확인한다. 클래식도 탐색·입력 기능의 회귀 대상이다.
- 큰 앱 소개, 반복 안내, 선택 의미가 없는 색 배경과 중첩 카드를 줄인다. 본문·입력·상태는 명확하게 남긴다. 실제/체험 구분과 실패·승인 안내를 장식 정리 대상으로 취급하지 않는다.
- 그림·질감·그라데이션·글꼴 다운로드로 분위기를 채우지 않는다. 이미지와 버디는 원래 색상·비율을 유지한다. 명조 느낌은 짧은 화면 제목에만 제한하고 시스템 한글 fallback을 확인한다. 본문·설정·입력은 기존 시스템 고딕을 사용한다.
- 현재 assistant 본문은 이미 배경·테두리가 없는 구조다. 이를 재구현하거나 완료 작업으로 다시 쪼개지 않고 문단 간격·제목·라벨·본문 폭을 다듬는다.

## 색상과 역할

아래는 paper의 구현 시작 후보다. 10색 데이터 규격을 유지하며 `green`은 기존 강조 역할 키를 그대로 사용한다. 변수 이름만을 위해 스킨 로더·저장 형식을 전면 변경하지 않는다.

| 기존 키 | 후보 | 역할 |
|---|---|---|
| cream | `#F5F2EB` | 전체의 따뜻한 종이 바탕 |
| surface | `#FBF9F4` | 펼친 면·팝업 등 불투명 표면 |
| field | `#FFFEFA` | 입력 면 |
| text | `#2E2925` | 먹갈색 본문·제목 |
| muted | `#6B6259` | 보조 글자·설명 |
| line | `#D9D2C6` | 장식 구분선 |
| wash | `#E9E3D8` | 탐색 바탕·선택의 옅은 면 |
| green | `#6B5B4D` | 엄버 브라운 주 조작·포커스 |
| accentInk | `#FFFEFA` | 강조 버튼 안의 글자 |
| danger | `#9B4F46` | 실패·위험 동작의 붉은 갈색 |

장식선과 조작 경계는 구분한다. 후보 `line`과 바탕의 대비는 약 1.34:1이므로 이것만으로 입력·선택기·체크 상태를 식별하게 하지 않는다. 필요한 조작 경계는 CSS에서 `color-mix(in srgb, var(--text) 60%, var(--surface))`로 파생하는 방식을 시작점으로 삼는다. paper에서 반올림한 값은 `#807C78`이며 다른 스킨도 실제 사용 배경으로 검증한다. 새 JSON 필드나 사용자 설정은 만들지 않는다.

[후보 대비 계산](../../artifacts/warm-editorial-ui-plan-2026-10-22/palette-proposal.json)은 18개 텍스트 조합의 최소 약 4.57:1, 4개 조작 경계 조합의 최소 약 3.24:1이다. 리터럴 후보의 계산이며 합성·투명도·hover·focus·disabled·OS 렌더링까지 검증한 수치가 아니다. 구현에서는 기존 `danger-ink` 합성, 버튼별 배경, 선택/오류/포커스 조합도 포함한다.

## 화면 구성과 정렬

### 상세 대화와 탐색

상단은 작은 버디 이름과 창 조작을 중심으로 줄인다. 대화·이전 대화·설정은 같은 탐색 위치에서 찾을 수 있게 정리한다. 기존 ID·action을 가진 하나의 탐색 컨트롤 집합을 배치하고, 화면별 탐색 복제나 별도 active 상태를 만들지 않는다. 설정 버튼의 이동이 필요하면 ID와 aria 상태를 유지하고 기존 스타일·검사에 미치는 영향을 함께 수정한다.

상세 창 폭 720px를 좌측 탐색 전환의 시작 기준으로 한다. 탐색 폭 88–104px와 본문 양쪽 여백 24–32px를 적용해도 본문에 최소 400px를 확보해야 한다. 이 조건이 깨지는 작업 영역에서는 가로 탐색으로 돌아간다. 390/460px와 심플 모드는 좌측 탐색을 표시하지 않는다. 일반 탭·설정·좁은/넓은 전환에서 초안과 현재 탭, 읽던 위치를 보존한다.

구조 구분은 24/32px 간격을 우선하고 같은 조작 안에는 4/8/12px를 사용한다. 넓은 창도 본문 줄 길이가 무한히 늘지 않도록 실제 남은 콘텐츠 열에서 읽기 폭을 제한한다. 전체 창 폭을 기준으로 한 기존 720px 규칙을 좌측 탐색 도입 뒤 그대로 중첩하지 않는다.

### 본문과 첫 화면

질문은 작은 면 또는 간결한 구분으로 발화자를 식별한다. 답변은 배경 없는 문서 형태와 제목·문단·목록 간격으로 읽는다. 제목에만 명조를 사용하더라도 모델 응답의 원문을 바꾸거나 임의 제목을 자동 추가하지 않는다. 본문 14px와 기존 100/110/120% 배율을 기준으로 읽기 편안함을 조정하고, 중요한 보조 설명은 12px 안팎에서 공간과 가독성을 함께 확인한다.

첫 화면은 작은 버디, 한 문장의 초대, 소수의 예시 질문으로 정리한다. 큰 환영 이미지·소개·보조 제목이 작은 창의 입력 공간을 밀지 않게 한다. 기존 예시 질문 접수 경로를 재사용한다.

### 입력과 심플 말풍선

상세 입력은 얕은 표면과 하단선 중심으로 표현하고 focus 상태를 명확하게 한다. 심플은 16px 여백과 작은 외곽선을 사용해 작은 말풍선 안에서도 입력 영역을 찾을 수 있게 한다. 두 모드의 form·textarea·메시지 노드는 공유한다.

`말투 → + → 모델 → 중단/전송` 순서와 동작을 유지한다. 첨부·목적·스킬은 +에 모으고 선택 결과와 첨부 제거는 입력 가까이에 둔다. 긴 모델/말투는 표시 폭을 줄이되 전체 이름의 접근 가능한 텍스트를 유지한다. 버튼을 줄 밖으로 밀거나 전송·중단을 더 보기 안에 숨기지 않는다. 모드별 버튼은 기존 32/36px 크기를 시작점으로 삼고 기준선과 클릭 영역을 함께 확인한다.

심플 최초 입력, 현재 답변 하나, 이미지 전용 답변, 전달 뒤 30초 전체 숨김과 보호 종료 뒤 새 30초, X 즉시 숨김·버디 재열기를 유지한다. 새 배치나 테마 변경만으로 전달 세대·숨김 타이머를 초기화하지 않는다.

### 설정과 기록

설정은 기본 대화/화면, 친구/움직임, 연결/알림, 관리로 묶는다. 기존 입력 ID·form·저장 동작과 설정 바로가기의 대상 ID를 유지한다. 이름은 커다란 별도 카드 대신 같은 정렬 체계의 입력 줄로 다룬다. 바로가기는 가벼운 텍스트 탐색으로 줄이고 화면 설명을 반복하는 안내는 정리한다.

일반 설정의 라벨/컨트롤은 공통 열과 40px 컨트롤 높이를 유지한다. 긴 팩·모델·경로는 전체 폭 줄로 전환한다. 펼침은 팩·MD 편집·보관·고급 연결처럼 드문 작업에 사용하고 현재 연결 실패/복구는 바로 보인다. 진단의 민감정보 제외, 권한 범위, 위험 동작과 복원 관련 필수 설명은 남긴다. 기존 섹션에 바로가기·포커스로 도달하는 흐름도 보존한다.

기록은 기존 목록 행을 유지하고 제목·날짜·즐겨찾기·더 보기의 기준선과 선택 면을 다듬는다. 열기/즐겨찾기와 제목 변경/내보내기/삭제의 현재 조작 구분, 검색 예산·부분 결과·소유 ID를 유지한다. 생성 이미지·첨부 이미지는 비율·원본 보기·decode 실패 안내를 보존하고, 캡션은 이미지 가까이 둔다.

### 팝업과 예외 상태

모델/+ 팝업, 기록 더 보기, 이름 변경·삭제·팩·MD 충돌 dialog, toast와 별도 notice까지 같은 표면·타이포·조작 역할을 적용한다. 전체를 무테로 만들지 않고 입력·승인·위험 조작을 식별할 경계를 남긴다. 메뉴는 불투명 표면, 최대 크기와 내부 스크롤을 유지한다.

크기 전환은 열린 모델/+ 메뉴를 현재 trigger에 재배치하고 기존 기록 메뉴 닫기 규칙을 따른다. 창 폭/탐색 변경으로 textarea 줄바꿈이 바뀌면 기존 높이 계산 경로를 보완한다. 새 입력 노드 생성, 파일 반복 저장, 별도 polling이나 테마 dispatcher는 추가하지 않는다.

색상 fallback과 실제 paper 데이터, notice의 바탕·꼬리를 일치시킨다. 기존 녹색 glow·고정 shadow·상태 점 등 고정 색상은 해당 용도의 역할로 정리하고, 의미 있는 오류/상태 차이는 유지한다. 추가 override를 끝없이 붙이거나 전체 CSS 재포맷을 변경에 섞지 않는다. 현재 단일 CSS의 lint·번들·패키지 규칙을 유지한다.

단순 높이 계산·aria 갱신은 기존 함수 안에 작성한다. 테마 엔진·범용 스타일 객체·작은 헬퍼의 연쇄로 과분리하지 않는다. 저장·CLI·캐시/quota·원격 조회 최적화와 Slack 등 기존 후속 과제는 이 UI 작업에 섞지 않는다.

| P2 / WE10 | 화면 없는 검사와 기존 테스트 정비 | 의미 있는 대비/팔레트·경계 검사와 기존 단위 통과, `npm run verify` 성공. 같은 구현을 복제하는 중복 테스트 추가 없음 |
| P2 / WE11 | 허용된 시간의 대상 GUI 수용 | 아래 행렬의 geometry/hit/대비/캡처 통과. 실패 수정 뒤 해당 경계 재검증과 최종 통합 1회 |
| P2 / WE12 | 문서·후보 패키지 전달 | 현재 UI 계약/가이드/상태 갱신, 직전 후보 보존 후 새 build 식별, ASAR 바이트/동작 대조와 한계 기록 |

WE01→WE02→WE03을 먼저 확정한다. WE04–WE08을 같은 공통 규칙으로 적용한 뒤 WE09–WE12로 수용한다. 화면 수용이 실패하면 해당 구현 단계로 돌아간다. 이전 build41의 성공을 새 디자인 완료로 표시하지 않는다.

## 검증 행렬

| 축 | 필수 대표 사례 |
|---|---|
| 상세 크기 | 390×580, 460×740, 720×900. 좁은 작업 영역·최소 본문 폭과 탐색 전환 경계의 직전/직후 |
| 심플 크기 | 360px/400px, 초기·답변·이미지 전용, 위/아래 꼬리 |
| 글자 | paper에서 100/110/120%, 긴 한국어·영문·숫자 혼합 이름/모델/경로. 나머지 스킨은 영향 경계 중심 |
| 본문 | 빈 화면, 장문/긴 token, 표·코드의 내부 가로 스크롤, 이미지 decode 대기/실패, 로딩 취소와 부분 기록 |
| 복합 상태 | 8첨부·6줄 초안·3개 대기열·추가 질문/승인·긴 연결/저장 오류, 큐 수정 중 전송/중단/취소 접근 |
| 팝업/모달 | +/모델과 resize·스킨 전환, 기록 메뉴와 검색 대상 제거, 이름 변경 실패·삭제 확인·팩·MD 충돌/복원 |
| 테마/복구 | 4스킨 왕복·선택 저장/복원·실패 rollback, 안내 창/꼬리, 숨김 캐시·renderer 복구·같은 전달 세대 |
| 수명/입력 | Enter/Shift+Enter·합성 composition, 초안/caret/포커스 보존, 보호 해제 뒤 실제 30초·X·버디 재열기 |

합성 조합과 기하 검사는 물리 한글 IME·스크린리더·다중 모니터·잠금/절전·Windows/Intel 수용과 구분한다. 행렬 전체를 모든 스킨·크기·상태의 곱으로 반복하지 않는다. 신규 실패나 코드 변경이 없으면 성공한 기본 검사를 반복하지 않는다.

기본 검증은 화면을 열지 않는 `npm run verify`다. GUI는 해당 시간의 사용자 허용과 `--interactive`를 모두 확인한다. 화면 캡처·포커스·클립보드/OS 동작을 자동으로 확대하지 않는다. 명령·증거 재사용은 [검증 가이드](../BUILD_GUIDE.md#4-검증-명령과-현재-windows-한계)를 따른다.

성능은 같은 fixture/크기/스킨에서 변경 전후를 비교한다. 탭 전환·입력·스트리밍·resize·스킨 전환에서 DOM 교체, Markdown 재파싱, 레이아웃 측정, IPC/저장 횟수와 지연을 관찰한다. 바깥 박스·헤더 배치 같은 단순 조정에 새 상시 계측을 넣지 않으며, 반복 가능한 악화가 있으면 원인을 수정한 뒤 채택한다. 성능 개선률은 실제 측정이 있을 때만 보고한다.
