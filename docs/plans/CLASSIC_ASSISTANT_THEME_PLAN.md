# 클래식 도우미 테마 작업 계획

2026-10-22에 정리한 설계와 수용 기준이다. CT01–CT05의 소스 반영·CT06 기본 검사와 새 후보의 정적 대조를 마쳤다. 사용자 허용 후 CT07 대표 정렬/조작·실제 30초 숨김과 CT08 실제 ASAR 모듈 검사를 통과했다. **CT07의 남은 상태/크기 조합과 일반 앱 설치/독립 실행·장시간 자원 관찰은 별도**이며 전용 캐릭터 CT09는 선택 후속 범위다. [구현 결과](../history/CLASSIC_ASSISTANT_THEME_RESULT_2026-10-22.md)에 실행 근거와 한계를 기록한다. 목표는 작은 버디와 노란 말풍선, 선명한 테두리와 입체 버튼으로 고전 문서 도우미의 분위기를 제공하는 것이다. 실제 모델 응답·체험 구분, 첨부·FIFO·보호 유예를 포함한 30초 숨김은 유지한다.

## 설계 방향과 범위

기존 `skinId`에 `classic`을 추가하는 방식을 우선한다. 사용자는 기존 화면 스킨 선택에서 고르고 기본값 `paper`와 기존 선택은 유지한다. 캐릭터·말투·정숙/일상/생동감 프로필·대화 모드는 별도 설정이다. 테마 선택으로 이 값을 자동 변경하지 않는다.

| 구성 | 1차 결정 | 이유 |
|---|---|---|
| 색상 | `skins/classic.json`, 기존 10색 규격 유지 | 기존 로더·저장·카탈로그 전달을 재사용 |
| 형태 | 본체 CSS의 `[data-skin=classic]` 범위에서 구현 | 테두리·꼬리·버튼은 색상 JSON만으로 표현할 수 없음 |
| 표면 | 안내/심플의 노란 표면, 상세/설정의 회색 창·흰 입력 구분 | 하나의 `cream` 값을 모든 화면 배경에 쓰면 구분이 사라짐 |
| 공통 값 | 필요할 때 표면·모서리·입체 테두리 등 소수의 CSS 변수 추가 | 실제 반복된 값만 모으고 범용 테마 엔진은 만들지 않음 |
| DOM | 기존 ID·form·button·dialog·popover와 노드 소유권 유지 | 새 채팅 UI 복제 없이 초안·선택·포커스와 IPC 계약 보존 |
| 캐릭터 | 기존 팩으로 먼저 수용, 전용 캐릭터는 후속 별도 팩 | UI 완성에 새 이미지 제작·팩 규격 변경을 선행시키지 않음 |
| 의존성 | 기존 Electron/HTML/CSS로 작성 | 98.css는 디자인 참고. 전역 CSS·jQuery·옛 Agent 런타임·CDN 추가 없음 |

1차 범위는 스킨 선택, 안내 말풍선, 심플/상세 대화, 기록, 설정, 팝업과 모달이다. XP 변형·음성·자동 제안·배회·옛 Office 원본 캐릭터 배포는 이번 테마의 필수 범위로 묶지 않는다. CSS 파일 분리는 우선하지 않는다. 현재 lint와 패키지 검사가 단일 `style.css`를 전제로 하므로, 실제 필요가 생기면 로딩·lint·패키지 포함까지 함께 설계한다.

스킨 선택은 이미 동적이므로 새 선택 UI나 별도 `themeId`를 만들 이유가 없다. startup의 미지원 ID fallback과 settings의 미지원 값 거절은 서로 다른 경로이며 둘 다 유지한다. 단순 ID 반영·높이 계산은 기존 함수 안에서 처리하고 테마 dispatcher나 불필요한 헬퍼로 추출하지 않는다.

## 화면 구조와 정렬

심플 화면은 다음 순서를 유지한다. 노란 말풍선과 캐릭터의 시각적 연결을 우선하고 버디/안내/대화 창의 책임은 합치지 않는다.

```text
말풍선
  이름 · 실제/체험 상태                    설정 · 확장 · 닫기
  선택한 답변: 글 / 이미지 / 실패 안내     (답변 전에는 입력 중심)
  승인·추가 질문·연결 오류·대기열           (필요할 때만)
  첨부 사본 · 선택 목적/스킬 · 큐 편집 안내 (필요할 때만)
  흰 입력창
  말투 · +                       모델 · 중단 · 전송
  캐릭터 방향의 꼬리
캐릭터: 클릭으로 열기 / 드래그로 이동
```

상세는 제목/닫기 → 대화·기록 탐색 → 읽기 영역 → 보조 상태 → 입력 순서를 유지한다. 설정은 이름/바로가기 → 화면과 대화 → 친구 모습/움직임 → 연결/사용량 → 팩/말투/보관의 현재 그룹을 클래식 그룹박스와 정렬된 컨트롤로 표현한다. 옛 화면의 조밀한 고정 픽셀 배치를 그대로 적용하지 않는다.

| 영역 | 배치·상태 기준 |
|---|---|
| 표면과 꼬리 | 노란 말풍선/회색 상세 창/흰 입력을 구분. 위·아래 배치 모두 꼬리와 본체 테두리·색상 연결, 화면 끝 잘림 방지 |
| 입력과 작업 줄 | 한글 조합·여러 줄·100/110/120% 배율과 긴 모델명에서도 전송/중단 유지. `+`의 첨부·목적/스킬 구조 보존 |
| 버튼 | 돌출/눌림/포커스/선택/비활성 구분. 아이콘·일반 버튼·위험 버튼에 역할별 적용하며 전역 `button` 규칙으로 동일 크기를 강제하지 않음 |
| 설정·기록 | 라벨/컨트롤 기준선, 이름/저장 높이, 이미지 비율, 긴 경로 줄바꿈과 항목 메뉴 소유 ID 유지 |
| 팝업·모달 | 최상위 popover/dialog에도 테마 적용. viewport 제한·내부 오류·Esc·취소 기본 포커스 유지 |
| 글자·접근성 | 시스템 한글 fallback과 기존 배율 유지. 옛 글꼴 설치/다운로드를 요구하지 않음. 일반 텍스트 대비 4.5:1, 주요 경계/포커스 3:1을 수용 목표로 측정 |
| 애니메이션 | 기존 reduced-motion·정숙·배터리·숨김/잠금 정책 유지. 테마만으로 새 timer·프레임 IPC·소리 추가 없음 |

## 예외와 회귀 검증

- **높이/꼬리:** 스타일 전환은 OS resize와 다르다. 기존 코드는 모드·글자 배율 변경 시 입력 높이를 재계산하므로 테마의 폰트/테두리 변경도 기존 계산 경로에서 확인한다. 열린 `+`/모델 팝업 위치와 안내 클릭 영역도 새 geometry 기준이어야 한다.
- **테마 왕복:** classic→night→paper 반복 후 CSS 변수·꼬리·그림자·색상 모드가 남지 않아야 한다. 숨겨진 패널은 기존 지연 반영을 유지하고 다시 표시할 때 최신 테마를 적용한다.
- **수명:** 같은 답변의 단순 테마 변경을 새 답변 전달로 취급하거나 30초를 무조건 초기화하지 않는다. 불필요한 전체 창 재열기를 피하고 높이/배치만 갱신한다. 실제 표시 준비나 보호 상태가 바뀌면 기존 소유권 검사와 숨김 정책으로 처리한다. 초안/IME/승인/큐/복구 보호 종료 뒤 새 30초, X 즉시 숨김 규칙은 유지한다.
- **실패/권한:** 저장 실패 시 이전 선택·실제 표시 일치, 알 수 없는 스킨 fallback/거절, renderer 복구 후 3창 재적용을 확인한다. 모델 재전송·캐릭터/MD 변경·추가 권한 허용은 발생하지 않아야 한다.
- **측정:** 테마 변경은 팔레트/스타일 적용만 하고 메시지 DOM/Markdown을 통째로 다시 만들지 않는다. 새 polling·네트워크·캐릭터 자산 decode를 추가하지 않는다. 카탈로그는 신규 스킨 1개만 늘고 테마 전환 때문에 전체 카탈로그를 반복 전송하지 않는다. 실제 skin 변경 이벤트만 스타일 재측정하며 반복 publish에서 불필요한 측정을 피한다.

기본 검증은 화면을 열지 않는 `npm run verify`와 필요한 경계 검사다. 문서 계획만 바꾼 단계에서는 링크/앵커·diff·제품 입력 불변을 확인하며 전체 단위·패키지 생성은 반복하지 않는다. GUI는 [작업 규칙](../../AGENTS.md)과 [검증 가이드](../BUILD_GUIDE.md#4-검증-명령과-현재-windows-한계)에 따라 사용자가 시간을 허용한 뒤 `--interactive`로만 실행한다.

화면 수용은 classic에서 심플 360/400px, 상세 390×580/460×740/720×900과 3글자 배율을 우선한다. 기본·이미지 전용·긴 Markdown·큐/첨부/긴 초안 복합·승인·연결/저장 오류·팝업/모달 상태를 분산 배치하고, 기존 3스킨은 공통 CSS를 바꾼 경계 중심으로 회귀한다. 모든 경우의 수에 전체 통합을 곱하지 않는다. 필요한 대상 검사 후 최종 통합 한 번, 실제 30초는 전환/보호 경계의 대표 사례로 확인한다. 합성 IME/geometry를 물리 IME·macOS/Windows 실기 완료로 표시하지 않는다.
