# 옹기봇 이전 대화

`이전 대화` 탭에 이 PC의 옹기봇에서 나눈 대화만 표시합니다. 첫 질문이 제목이 되고 마지막 내용·최근 변경 날짜·메시지 수를 보여줍니다. 검색은 제목과 최근 미리보기를 대상으로 하며 전체 본문 검색은 아직 지원하지 않습니다.

목록에서 선택하면 기록을 읽고 대화 화면으로 돌아갑니다. 이후 질문은 저장된 Codex thread ID로 재개합니다. 조회 자체는 모델을 호출하지 않습니다. 진행 중이거나 대기 중인 질문이 있으면 대화 전환을 막습니다. 완료하거나 취소한 다음 전환합니다. 대화별 입력 초안은 앱 실행 중에만 기억합니다.

모델 설정은 앱 전체에 적용합니다. 이전 대화를 열어도 현재 선택한 모델은 유지되며 다음 질문부터 적용합니다. 과거 메시지의 모델 정보는 보존합니다. 사용자 지정 앱 기본값은 `gpt-5.6-luna / high`입니다. 작업 폴더·CLI 실행 경로·체험 모드는 대화 당시 값으로 복원합니다.

## 저장과 출처

macOS 기본 데이터 위치는 `~/Library/Application Support/OnggiBot/`입니다.

- `state.json`: v2 설정, 활성 대화 ID, 옹기봇 소유 대화 목록.
- `conversations/<local UUID>.json`: Codex thread ID와 대화별 메시지. ID를 목록과 대조한 뒤 파일을 읽습니다.
- 새 Codex 대화에는 `threadSource: onggi_bot`을 지정합니다. 사용자 메시지에는 로컬 ID를 지정하고 turn ID도 저장하여 조회 결과와 대조합니다.

앱 전체 Codex 대화 목록을 불러오지 않습니다. 옹기봇의 로컬 등록부에 있는 thread ID만 읽습니다. Codex 앱에서 같은 세션을 이어간 경우 그 등록된 세션의 텍스트 질문·답변도 조회할 수 있습니다. 도구 실행 로그·추론 내용은 말풍선 기록에 가져오지 않습니다. `thread/read`가 실패하면 로컬에 보관한 내용을 보여주며 안내를 표시합니다. 체험 대화는 로컬 기록만 사용합니다.

파일은 원자적으로 교체하고 평문으로 저장합니다. 기존 최근 120개 메시지 삭제는 제거했습니다. 대화 파일 하나가 32MiB를 넘으면 새 대화를 시작하라는 오류를 표시합니다. build25에서는 불러온 긴 메시지의 원문을 32MiB 파일 한도 안에서 보존하고, 화면 표시만 100,000자로 제한해 생략 안내를 붙입니다. 새 CLI 스트리밍 답변은 항목 전체 합계 100,000자까지만 로컬에 수집하며 한도 초과 시 CLI 원문 확인 안내를 표시합니다. 표시 제한과 수집 제한을 구분합니다. 전체 본문 검색·다른 PC와의 동기화는 아직 제공하지 않습니다. alpha.8부터 대화 삭제를 제공합니다.

## 기존 알파에서 이관

v1 `state.json` 원본을 `state.json.backup-v1-<시간>`으로 백업한 뒤 현재 남아 있는 대화를 목록에 등록합니다. 설정과 기본 모델도 유지합니다. 실행 중이던 요청은 중단 상태로 바꾸고 자동 재전송하지 않습니다.

기존 버전에서 `새 대화`를 눌러 로컬 정보를 잃은 옛 세션이나 이미 120개 제한으로 지워진 메시지는 로컬 파일만으로 복원할 수 없습니다. 현재 등록된 세션은 Codex 기록 조회로 더 긴 텍스트 기록을 보완할 수 있습니다. 미등록 세션은 출처를 확정할 수 없어 자동으로 가져오지 않으며 Codex 앱의 대화 목록에서 확인합니다.

확인 환경: Codex CLI 0.160.0. [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)의 `thread/read`·`thread/resume`와 로컬 생성 스키마, 실제 등록 세션 읽기로 확인했습니다.

## 검증

`npm test`는 v1 백업·자동 이관, 여러 대화 보존·설정 복원·재시작, 140개 메시지 보관, 외부 출처 제외·손상 파일 격리를 검사합니다. `npm run smoke:history`는 별도 프로필과 테스트 CLI로 실제 창에서 목록·검색·동일 세션 재개·실행 중 전환 차단을 검사합니다. 사용자 실제 대화와 테스트 기록은 섞이지 않습니다.

## 저장 복구·긴 화면

대화와 목록의 교체에는 SHA-256 확인값을 가진 저장 저널을 사용해 중간 종료를 복구합니다. 초기 저장 실패는 새 등록을 되돌리고, 대화 전환 실패는 이전 활성 상태를 유지합니다. 완료 저장 실패 시 대기 질문을 실행하지 않습니다. 기존 v2 파일을 유지하며 DB 이관은 없습니다.

화면은 최대 100개/약 256KiB 텍스트 묶음부터 표시하고 이전 내용 버튼으로 추가합니다. 저장 파일에는 전체 기록을 유지합니다. 자세한 순서와 전원 장애/저장 워커·동기 읽기의 한계는 [LOCAL_STABILITY.md](LOCAL_STABILITY.md)에 있습니다.

## 삭제

항목 오른쪽 삭제 버튼으로 로컬 기록과 CLI 실제 세션을 함께 영구 삭제합니다. 현재 대화 삭제 시 새 대화 상태로 돌아가고 다른 대화/설정은 유지합니다. CLI 실패에서는 로컬 기록을 보존하며 부분 완료는 삭제 저널로 복구합니다. 백업 파일은 별도 유지합니다. 자세한 범위와 검증은 [DELETE_CONVERSATIONS.md](DELETE_CONVERSATIONS.md)를 참고합니다.

thread/read의 대화 ID·turn/items/text 구성을 확인하고, 원격 병합 저장 실패에서 기존 로컬 메시지로 되돌립니다. 다른 대화의 응답을 현재 기록에 합치지 않으며 실패 안내에서 로컬 fallback과 저장 복구 필요를 구분합니다. [수정 결과](history/ISSUE_REMEDIATION_RESULT_2026-10-08.md)
