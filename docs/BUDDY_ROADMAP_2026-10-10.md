# my_budy 버디 기능 확장과 에셋 활용 계획

구현 이후 상태는 [alpha.15/build31 확장 결과](history/BUDDY_EXPANSION_RESULT_2026-10-10.md)에 기록했다. 이 문서는 착수 시 정한 우선순위·계약·수용 조건을 보존한다.
2026-10-10 기준 계획이다. `my_budy`는 로컬 Codex CLI와 연결하는 바탕화면 버디이며 현재 제품명은 옹기봇이다. 작은 친구에게 질문을 건네고, 다른 일을 하는 동안 조용히 답변을 기다렸다가 결과를 확인하는 흐름을 우선한다. 캐릭터의 모습과 말투를 사용자가 고르는 경험도 이 흐름의 일부다.

기준은 alpha.14 소스와 Electron 44.5.1, [현재 구조](ARCHITECTURE.md), [캐릭터 팩 규격](CHARACTER_PACKS.md), [작업 목록](../TASKS.md)이다. 코드 재검토를 반영해 선행 결함 BUD00과 실행 단위·저장 계약·복구 조건을 보완했다. 아래 항목은 구현 전 계획이며, 기존 기능의 검증 범위는 [알파 보고서](ALPHA_REPORT.md)를 따른다. 실제 계정의 추가 기능 실행이나 외부 에셋 다운로드·변환은 이 검토에 포함하지 않았다.

## 버디 경험의 기준

- 평상시에는 캐릭터와 짧은 안내를 중심으로 표시한다. 계획·도구 실행·사용량 같은 상세 정보는 펼쳐 볼 수 있게 한다.
- 캐릭터의 반응은 실제 대기·실행·응답·승인·오류 상태와 연결한다. 정숙 설정은 장식을 줄이고, 필요한 승인과 저장 오류는 확인할 수 있게 한다.
- 사용 중인 캐릭터·이름·말투와 대화가 이어지는 느낌을 유지한다. 새로운 작업 목적이나 프로젝트 설정은 질문을 접수할 때 명시적으로 적용한다.
- 동작·소리·알림은 집중을 방해하지 않도록 제한한다. 숨김·잠금·절전·배터리·움직임 줄이기 정책을 함께 적용한다.
- [AGENTS.md](../AGENTS.md)에 따라 단순 상태 변경·검증·표시는 기존 함수 안에 둔다. CLI·저장·첨부·이미지·팩의 실제 실패 경계는 기존 모듈을 재사용한다. 큰 파일 읽기나 decode를 메인 스레드의 동기 작업으로 늘리지 않는다.

## 단계별 상세 작업

### BUD00 기존 텍스트 복사 완료 처리

`copy` 동작의 기존 검증을 유지하고 `clipboard.writeText`를 기다린 뒤 성공을 반환한다. 실패는 기존 `act` 오류 표시로 전달하여 답변/코드의 복사 버튼이 성공 상태로 바뀌지 않게 한다. 단순 변경이므로 별도 클립보드 wrapper나 helper를 만들지 않는다.

**완료 기준:** 지연 Promise가 끝나기 전에 IPC 성공/복사됨이 표시되지 않고, 거절은 실패로 처리된다. 동일한 답변/코드 블록 복사에서 원문을 유지한다. 모의 실패 검사와 실제 OS의 복사·붙여넣기 결과를 구분한다.

### BUD01 이미지 붙여넣기와 파일 드롭

기존 선택창과 같은 초안에 첨부한다. 클립보드는 사용자가 붙여넣기를 실행했을 때만 읽고, 일반 텍스트 붙여넣기는 유지한다. 파일 드롭은 preload에서 Electron의 파일 경로 조회 기능을 좁게 노출하고 메인에서 입력 형식·발신 창·활성 대화를 검증한다. 파일 선택창·드롭·클립보드가 같은 첨부 한도를 공유하게 한다.

기존 `AttachmentStore.import`의 파일 검증·사본 저장과 이미지 decode 경계를 재사용한다. 클립보드 이미지 바이트도 이 경계에 넣을 수 있도록 필요한 입력 형태만 확장한다. 경로·크기·해시 검사를 UI별로 복제하지 않는다. 디스크 저장과 decode를 기다리는 동안 입력과 접수의 수명은 메인이 소유한다.

드롭 입력은 격리 preload가 실제 입력 이벤트의 `File`을 확인하고 제한된 경로 전달 경로로 보낸다. 일반 `action`에 renderer가 임의 경로를 넘겨 파일을 읽는 기능을 추가하지 않는다. `webUtils.getPathForFile`의 빈 경로·예외와 sandbox에서의 실제 동작을 확인한다. 클립보드는 메인에서 비동기로 읽고 허용 MIME의 Blob 크기를 확인한 뒤 이미지 검증에 전달한다. 이미지와 텍스트가 함께 있는 경우 일반 붙여넣기의 텍스트 처리를 유지하고 명시적인 이미지 붙여넣기도 제공한다. [Electron webUtils](https://www.electronjs.org/docs/latest/api/web-utils)

**완료 기준:** 최대 8개·개별 16MiB·합계 32MiB를 유지하고 손상 이미지·폴더·링크·한도 초과를 거절한다. 여러 파일 중 일부가 실패하면 초안에 부분 접수하지 않는다. 가져오기 중 대화 전환·창 종료·원본 변경·저장 공간 부족이 발생해도 기존 텍스트와 첨부 초안을 보존한다. 임시 저장 잔여물은 기록에 연결하지 않으며 실패 복구 정책을 확인한다. PNG/JPEG/WebP 붙여넣기와 실제 파일 드롭을 OS에서 확인한다.

### BUD02 조용한 알림과 캐릭터 피드백

기존 `finishJob`의 결과·이미지·저장 확정 이후에 완료 알림을 만든다. 승인은 실제 요청이 남아 있을 때, 실패는 같은 작업에서 한 번만 알린다. 사용자가 직접 중단한 작업은 기본적으로 실패 알림을 내지 않는다. 창을 보고 있으면 화면의 상태 표시를 우선하고, 숨긴 창에서는 OS 알림으로 돌아올 수 있게 한다.

설정은 완료·승인·실패별 켜기, 소리, 내용 미리보기, 정숙 시간을 제공한다. 기본 소리는 끄고, 정숙 프로필에서는 OS 알림과 장식을 억제한다. 승인 대기는 캐릭터 상태와 창 안의 요청으로 계속 확인할 수 있다. 잠금 중에는 질문·답변 내용이 노출되지 않게 한다. 선택형 효과음은 BUD06의 별도 후속 범위다.

승인 표시 방식은 기존 창 자동 열기를 초기값으로 유지하고, 사용자가 캐릭터 안내/OS 알림 중심 방식을 선택할 수 있게 한다. 창을 자동으로 열었으면 같은 승인 OS 알림을 반복하지 않는다. OS 미지원·서명/권한·표시 실패 시 캐릭터 주의 상태와 대화 열기 동작을 유지한다. 현재 실행의 10분 제한은 승인 대기에도 진행되므로 알림 방식 변경 시 만료 안내와 요청 종료를 확인한다. 첫 변경에서는 제한을 유지하고 대기 시간 분리 여부는 실제 사용 결과로 결정한다.

**완료 기준:** 늦은 완료 이벤트·재연결·기록 재조회에서 같은 알림을 반복하지 않는다. 알림 클릭은 소유 대화 ID를 다시 검증하고 진행 중 작업을 취소하거나 다른 대화로 강제 전환하지 않는다. 삭제한 대화의 알림도 안전하게 처리한다. OS 지원/허용 여부와 표시 실패는 대화를 막지 않으며 기존 캐릭터 안내를 유지한다. 개발 실행과 패키지 앱의 실제 알림을 각각 확인한다.

### BUD03 FIFO 대기열 관리

수동 보류는 현재 작업을 계속하고 다음 작업의 시작을 멈추는 기능으로 정한다. 수동 보류와 절전·로그인·저장 장애의 보류 사유를 구분하여, 사용자의 계속 버튼이 복구되지 않은 장애를 해제하지 않게 한다. 보류 중 새 질문 접수 허용 여부도 사유별로 명시한다. 수동 보류에는 정상 접수를 허용하고 장애 상태에는 기존 접수 제한을 적용하는 방향으로 검증한다.

편집 대상은 실행 전 대기 질문이며 처음에는 텍스트·첨부만 수정한다. 기존 순번·ID·모델·말투·작업 폴더 snapshot을 유지하고 수정 전에 설정 요약을 보여준다. 편집·저장 중 대상이 시작되지 않도록 메인에서 예약하고, 확정 전에 대상 상태를 다시 확인한다. 검증·저장이 실패하면 원래 대기 질문과 편집 초안을 보존한다.

전체 취소는 클릭 시점의 대기 ID를 대상으로 하며 현재 실행과 이후 새 접수를 구분한다. 취소 상태를 저장한 뒤 화면에 확정한다. 별도 큐 프레임워크를 만들지 않고 기존 `admissionTail`·`runQueue`·저장 직렬화 안에서 처리한다.

**완료 기준:** A 실행 중 B/C 편집·취소·D 동시 접수에도 남은 항목의 FIFO가 유지된다. 편집 대상의 실행 시작·완료 저장과의 충돌, 첨부 예약 중복, 저장 실패, 절전·인증 만료가 겹친 경우를 검사한다. 재시작·연결 중단으로 실행 여부가 불확실한 질문은 기존 정책대로 자동 재실행하지 않는다.

### O01 O04 O08 연결 진단과 최초 안내

이미 구현된 상태 카드를 CLI 발견 → 인증 → 작업 폴더 → 모델 준비 순서로 안내한다. CLI 버전과 앱이 필요한 기능의 지원 상태를 함께 표시하고, 구형 CLI의 선택 기능 실패는 해당 기능 안내로 처리한다. 기존 캐시 로그인·외부 제공자·ChatGPT 로그인을 구분한다.

진단 내보내기는 앱/CLI 버전·단계·지원 여부·정제한 오류 코드 등 필요한 항목의 허용 목록으로 만든다. 인증 토큰·전체 환경 변수·대화·원본 설정은 넣지 않고 사용자 경로는 기본 가림 처리한다. 복구는 기존 재탐색·initialize 확인·원래 기록 보존 경계를 따른다.

**완료 기준:** CLI 없음·실행 불가·잘못된 폴더·인증 필요·외부 제공자·모델 목록 실패를 구분하고 로그인 취소·만료·늦은 콜백에서 상태를 복구한다. 실제 미로그인 브라우저 콜백과 새 환경 확인은 기존 O05/O10에 기록한다. O06의 유료 테스트 질문은 비용을 안내한 명시적 선택으로 별도 진행한다.

### BUD04 읽기와 입력 옵션

대화 글자 크기와 캐릭터 배율을 별도로 설정한다. 미니창은 글자·첨부·승인·대기열이 잘리지 않는 범위에서 크기를 조절하고 일반 대화와 초안을 공유한다. 단축키 변경과 Enter 또는 ⌘/Ctrl+Enter 전송을 추가한다. 옵션은 기존 설정의 기본값·복원 검증·저장 경로에 넣는다.

**완료 기준:** 단축키 충돌이나 저장 실패 시 기존 단축키를 복구한다. 한글 IME 조합 중 Enter가 전송되지 않아야 한다. 글자 확대·작은 화면·배율 변경·창 재표시에서 초안과 스크롤을 유지한다. 미니창 확장 때 메시지 DOM 전체를 불필요하게 다시 만들지 않는다. Windows IME·혼합 DPI는 해당 환경의 실기로 확인한다.

### BUD05 생성 이미지 복사와 저장

활성 소유 대화의 검증된 이미지 ID로 복사·다른 이름으로 저장·다시 첨부를 제공한다. 미리보기와 원본을 구분하고 MIME에 맞는 확장자를 사용한다. 다시 첨부는 새 임시 첨부 ID를 발급해 같은 초안·용량·FIFO 정책을 따른다.

**완료 기준:** 사본 삭제·변조·손상 decode·저장 취소·권한/공간 부족에서도 텍스트 응답과 기존 이미지를 유지한다. 외부 Markdown URL이나 모델이 언급한 임의 파일 경로를 자동으로 가져오지 않는다. 문서 등 생성 파일의 결과 보관은 파일 소유 범위와 출력 형식을 정한 후 별도 확장한다.

이미지 복사는 Electron 44의 `ClipboardItem`·비동기 `clipboard.write`로 구현하고 완료까지 기다린다. 다른 이름으로 저장하는 동안 대화/창 수명이 바뀌면 처음 캡처한 소유 메시지·이미지 참조를 다시 검증한다. 내보낸 새 파일만 쓰고 원본 캐시는 변경하지 않는다.

### BUD06 버디 캐릭터 시범과 선택형 효과음

아래 에셋 분석에 따라 자체 Pixelorama 캐릭터 또는 Quaternius 캐릭터 하나를 선택해 시범 팩을 만든다. 대기·입력·생각·응답·주의·오류·쉬기 7개 모습을 같은 캐릭터로 구성하고, 작은 화면에서 눈·표정·실루엣이 구분되는지 먼저 확인한다. 새 외형을 선택해도 버디 이름·편집한 말투·대화가 유지되어야 한다.

v2는 idle 눈 깜빡임만 지원하므로 다른 상태에는 정적 이미지를 사용한다. 시범의 깜빡임은 전체 공통 캔버스의 소수 프레임으로 제작한다. 3D 원본은 제작 단계에서 투명 PNG로 렌더링하고 앱에는 검증된 이미지·manifest·선택적인 MD만 넣는다. 3D 리그·애니메이션이 있더라도 7개 상태와 눈 깜빡임을 모두 제공한다고 가정하지 않는다.

**완료 기준:** 기존 팩 byte/pixel/frame 한도·동일 캔버스·실제 decode를 통과하고 35/50/65%에서 시각적으로 확인한다. 잠금·숨김·절전·드래그·움직임 줄이기·배터리 절약에서 프레임이 멈춘다. 교체 실패·표시 실패·보관·복원·새 프로필 내보내기를 확인한다. 외형만 바꾸는 동작에서 모델을 호출하지 않는다.

효과음은 알림 정책이 안정화된 후 사용자가 켜는 후속 옵션으로 둔다. jfxr로 제작한 짧은 응답/주의 소리를 후보로 하고 반복·동시 재생·큰 음량을 제한한다. 먼저 앱이 관리하는 고정 소리로 검토한다. 현재 캐릭터 팩은 오디오를 지원하지 않으며 팩 오디오 수명·검증·배포 권한은 추가 설계가 필요하다.

### BUD07 대화 제목과 즐겨찾기 및 내보내기

자동 제목과 사용자가 정한 제목을 구분해 후속 저장이 이름을 덮어쓰지 않게 한다. 즐겨찾기는 저장된 대화 metadata와 목록 정렬에 반영한다. Markdown 내보내기는 체험/실제 응답·미완료/오류·첨부와 이미지의 포함 여부를 표시한다. 사용자 경로나 인증 정보가 불필요하게 섞이지 않게 한다.

본문 검색은 큰 기록의 매 입력마다 전체 동기 읽기를 하지 않도록 범위를 정한다. 제목/최근 내용 검색을 유지한 채 사용자가 본문 검색을 선택하게 하고 결과 수·읽기량을 제한한다. 긴 CLI 기록의 페이지 조회는 기존 C09와 연결한다.

**완료 기준:** 기존 version 2 기록을 다시 열고 저장해도 제목·시간·소유권·이미지 참조가 보존된다. 저장/내보내기 실패, 삭제 확인 중인 대화, 없는 첨부, 부분 기록을 처리한다. 이미지 포함 내보내기는 실제 내보낸 사본을 상대 링크로 연결하고 기존 개인 파일의 절대 경로를 노출하지 않는다.

### BUD08 작업 목적과 스킬 선택

말투와 별도로 요약·분석·계획·리뷰 같은 작업 목적을 제공한다. 선택값은 질문별로 고정하며 작업 목적이 권한을 늘리는 근거가 되지 않게 한다. 우선 간단한 목적 템플릿부터 적용하고 계획/전용 리뷰의 응답 항목·추가 질문·완료 처리를 함께 구현한다. 현재 `default` 고정 실행에 선택 메뉴만 추가하는 것으로는 충분하지 않다.

스킬 목록은 작업 폴더별로 조회하고 사용 가능한 항목의 이름·설명·경로로 선택한다. 목록 오류·파일 변경·폴더 변경 때 갱신하고 접수 당시 선택 정보를 기록한다. 대기 중 원본 스킬이 변경되면 동일한 원문을 실행한다고 표시하지 않는다. CLI 공용 설정을 바꾸는 설치·활성화 관리와 캐릭터 데이터 팩은 별도 책임으로 유지한다.

**완료 기준:** 지원하지 않는 메서드·비활성 스킬·잘못된 경로·계획 추가 질문·리뷰 실패를 처리하고 일반 질문을 계속 사용할 수 있게 한다. `plan`·`enteredReviewMode`·`exitedReviewMode` 등 실제 결과 항목을 표시하고 체험 예시와 구분한다. 계획 설정의 실험 기능 호환과 실제 CLI 응답을 확인한다.

먼저 목적 템플릿, 다음으로 계획/전용 리뷰, 마지막으로 명시적 스킬 입력을 전달한다. 리뷰 API의 모델·추론 적용 범위가 일반 `turn/start`와 같은지 가정하지 않고 실제 적용값을 표시한다. 기록 재조회에서도 계획/리뷰 결과를 복원하고, CLI가 생성한 내부 사용자 항목이 앱에서 접수한 질문 원문·첨부를 덮어쓰지 않게 한다.

### BUD09 작업 상태와 사용량

기존 짧은 진행 안내에 접을 수 있는 계획·도구 상태를 추가한다. 소유 thread/turn의 구조화된 이벤트만 반영하고 항목 수·문자 수를 제한한다. 전체 도구 로그를 기본 화면이나 기록에 계속 누적하지 않는다. 진행률이나 남은 시간을 임의로 만들지 않는다.

계정 사용 한도는 사용 비율·초기화 시각·조회 시각을 표시하고 계정 전체에 공유되는 한도임을 알린다. 현재 대화의 토큰 정보는 별도 항목으로 표시한다. 누적 토큰과 현재 문맥 점유율을 혼동하지 않으며 값이 없으면 확인 불가로 처리한다. 초기에는 전송 토큰으로 비용이나 남은 질문 횟수를 계산하지 않는다.

**완료 기준:** 없는 필드·오래된 값·다중 한도·인증 방식 차이·구형 CLI·늦은 다른 턴 이벤트를 처리한다. 빈 계획과 도구 완료를 정상 표시하며 선택 기능 실패로 질문을 막지 않는다. 이벤트 폭주·숨긴 창에서 렌더와 저장 비용이 늘지 않는지 확인한다.

### 보류 전이와 편집 확정

| 상태 | 새 질문 접수 | 다음 작업 시작 | 해제 조건 |
|---|---|---|---|
| 수동 보류 | 정상 준비 상태라면 허용, 최대 10개의 대기+preparing 한도 유지 | 보류 | 사용자가 계속 |
| 편집 예약 | 다른 정상 접수는 허용. 대상은 편집 중으로 표시 | 예약한 항목과 그 뒤의 항목을 추월하지 않음 | 저장 성공 또는 취소/실패 후 기존 상태 복원 |
| 절전/연결 불확실 | 해당 상태에서 접수 제한 | 보류 | 복귀·연결 확인 뒤 사용자 계속. 끊긴 실행은 자동 재전송하지 않음 |
| 인증 필요 | 준비가 안 된 요청은 접수 실패/초안 유지 | 보류 | 인증/모델 준비와 사용자 계속 |
| 저장 차단 | 거절, 화면 원문 보존 | 차단 | 기존 저장 복구 절차. 계속 버튼으로 해제하지 않음 |

여러 사유가 동시에 있으면 하나를 해제해도 나머지 사유를 유지한다. 메인의 첫 await 전에 편집 대상·새 첨부 후보를 예약하고, 예약을 얻기 전에 이미 실행된 질문은 편집 대상으로 받지 않는다. 준비/저장 대기 이후 대상 ID·revision·대화·연결 문맥을 재확인한다. 변경을 저장하는 동안 대상은 시작하지 않으며 저장 성공 후 확정·예약 해제를 한 번 처리한다.

현재 IPC의 전역 저장 대기를 그대로 두면 제어 예약 전에 다음 질문이 시작될 수 있다. 새 제어 동작의 발신 창/프레임 검증과 저장 대기 허용 목록을 함께 조정하여 예약을 먼저 받고, 대화/저장 변경은 기존 직렬 저장을 기다리게 한다. 기존 `send`·`cancel`·`respond`의 즉시 제어 경로와 완료 저장 순서를 회귀 검사한다.

안전하게 되돌릴 수 있는 저장 실패는 원래 질문과 편집 초안을 유지한다. 저널 상태가 불확실하거나 Store가 쓰기를 차단한 경우에는 성공/자동 재실행으로 처리하지 않고 복구 필요 상태로 남긴다. 첨부 사본은 해시로 공유될 수 있으므로 실패 시 기존 사본을 일괄 삭제하지 않는다. 미접수 캐시의 용량 영향과 이번 작업이 만든 임시 파일만의 정리 여부를 함께 검사한다.

### 첫 배포 후보의 통과 조건과 복구

첫 후보는 BUD00, BUD01, BUD02-A, BUD03-A/B와 연결 진단을 중심으로 만든다. 다음 사항을 관련 fixture/UI 검사에서 확인한 후 staging에서 실제 입력과 창 수명을 확인한다.

1. 복사가 지연/실패하면 성공 UI가 먼저 나오지 않고, 붙여넣기/드롭 실패가 기존 초안을 지우지 않는다. renderer가 임의 경로를 입력 경로로 대신 넘길 수 없도록 확인한다.
2. A 실행 중 B를 편집하고 C를 취소하며 D를 접수해도 남은 질문의 순서·설정·첨부가 유지된다. 저장 실패·인증 만료·절전이 겹쳐도 수동 계속이 장애를 우회하지 않는다.
3. 답변을 수신했지만 저장하지 못한 경우 성공 완료 알림을 내지 않고 다음 질문을 시작하지 않는다. 승인 해제·10분 만료·삭제한 대화의 오래된 알림을 처리한다.
4. 유효한 서명/OS 표시를 확인하지 못한 환경에서는 native 알림을 완료로 기록하지 않는다. `isSupported`와 생성 성공만으로 표시 성공을 판정하지 않고 `failed`와 실제 알림을 확인한다.

배포 전 사용 가능한 로컬 서명 방식의 유효성과 알림 표시를 확인한다. 외부 배포용 Developer ID/공증은 C10에서 별도로 다루며, 로컬 알림에 필요한 조건과 혼동하지 않는다. 기존 묶음/개인 데이터는 검증 후보와 분리하고 패키지 검사를 통과한 후보만 전달한다.

복구는 이번 변경의 소유 범위로 제한한다. 설정·제목 metadata 변경 전에는 복구 가능한 사본을 남기고, 구버전이 새 필드를 버리는지 실제 왕복으로 확인한다. 새 기능을 끄거나 이전 앱으로 돌아갈 때 새 대화/이미지/첨부를 일괄 덮어쓰거나 삭제하지 않는다. 임시 첨부·알림 인스턴스·편집 예약·timer는 종료/renderer 복구에서 해제하고 불확실한 질문은 자동 재전송하지 않는다.

## 조건부 확장과 CLI 호환

프로젝트 즐겨찾기는 같은 버디의 외형·이름을 유지하고, 작업 폴더별 대화와 모델/목적 설정을 구분하는 방향으로 검토한다. 선택 파일·Git 변경·선택 텍스트·스크린샷 문맥은 전송 전 확인하는 기존 M10과 연결한다. 자동 수집과 명시적 기억은 구분하고 기억은 조회·수정·삭제를 제공한다.

현재 작업 지시 보완은 기본 FIFO 옆에 명시적인 별도 동작으로 둔다. 완료 직전의 턴 ID 불일치나 통신 실패 시 자동으로 큐 전송하지 않고 초안을 보존해 사용자가 결정하게 한다. 대화 분기는 새 소유 ID·첨부/이미지 참조·삭제 범위를 먼저 설계한다.

파일 수정 모드는 작업 폴더·허용 범위·도구 승인·변경 내역·부분 수정/중단을 보여주는 흐름이 준비된 후 진행한다. 현재 읽기 전용의 읽기 범위도 작업 폴더로만 제한되는 것은 아니다. 기억·음성은 기존 M10/M11, Live2D/VRM·배회·다중 캐릭터는 M12의 조건을 따른다. Slack S01–S17과 다중 클라이언트 중앙 FIFO의 대기는 유지한다.

설치 CLI `0.162.0-alpha.2`의 생성 스키마에서 `turn/steer`, `review/start`, `skills/list`, `account/rateLimits/read`, 계획/차이/토큰 알림과 `thread/fork`를 확인했다. `collaborationMode/list`와 계획 설정은 실험 스키마에 포함된다. 스키마의 존재는 실제 계정 실행의 완료 근거가 아니므로 기능별 응답 형식·권한·실패 fallback을 확인한다. 공식 문서도 스킬 조회와 명시적 호출, 리뷰, 활성 턴 지시 보완을 설명한다. [Codex App Server](https://learn.chatgpt.com/docs/app-server)

고급 기능은 기존 연결과 좁은 IPC를 확장한다. 사용자 전체 CLI 설정을 자동 변경하거나 별도 에이전트 런타임·플러그인 마켓을 이 단계에서 도입하지 않는다. 공식 문서에서 아직 프로덕션 호출을 권하지 않는 플러그인 관리 API도 우선 범위에 넣지 않는다. [플러그인 API 상태](https://learn.chatgpt.com/docs/app-server)

### 우선 검토할 구체적인 캐릭터

1. **자체 Pixelorama 버디:** 기존 옹기봇의 분위기를 유지하면서 표정과 크기를 직접 정할 수 있다. 그림 제작 시간이 들지만 변환한 에셋의 불필요한 런타임을 추가하지 않는다. 가져온 자료 없이 자체 제작한 그림을 기본 시범으로 권한다.
2. **Quaternius Animated Robot Pack:** 한 캐릭터를 대상으로 시작할 수 있는 CC0 후보다. 생각·답변·쉬기 모습을 포즈로 만들고, 작은 화면의 얼굴 표현이 충분한지 시범 렌더링한다. 페이지는 애니메이션과 FBX/OBJ/Blend 형식을 안내한다. [원본 팩](https://quaternius.com/packs/animatedrobot.html)
3. **Quaternius Cute Animated Monsters Pack:** 21종 가운데 친근한 실루엣 하나를 선택할 수 있는 CC0 후보다. 현재 버디의 분위기와 맞는지 먼저 비교하고 전체 팩을 배포하지 않는다. [원본 팩](https://quaternius.com/packs/cutemonsters.html)
4. **Quaternius Ultimate Animated Animal Pack:** 12종의 애니메이션 동물 후보다. 일상 버디에 맞는 자세를 선별하고 귀·꼬리가 작은 창에서 잘리거나 표정을 가리지 않는지 확인한다. [원본 팩](https://quaternius.com/packs/ultimateanimatedanimals.html)

원본의 리그·텍스처·애니메이션을 다운로드해 확인하기 전에는 특정 표정이나 눈 깜빡임을 제공한다고 확정하지 않는다. 먼저 한 캐릭터의 정적 대기 모습을 실제 크기로 확인한 후 나머지 상태를 제작한다.

### 팩 제작과 배포 경계

현재 팩에는 SVG/PNG/WebP와 manifest·선택적인 MD만 설치한다. 스프라이트시트 atlas/crop은 지원하지 않으므로 Pixelorama의 개별 프레임이나 전체 공통 캔버스로 변환한다. GIF는 팩 형식이 아니며 APNG/animated WebP는 정적 대표 프레임으로 표시하므로 실제 재생은 v2 blink 프레임 규격을 따른다. 3D 원본·Godot 코드·HTML·셸 스크립트·음원은 이 계약에 넣지 않는다.

시범은 정적 상태 7개와 소수의 blink 프레임으로 제한한다. 프레임 시간·2~32개 한도·동일 decode 치수·전체 픽셀 예산은 기존 규격을 따른다. v2가 모든 상태의 프레임 애니메이션을 지원하는 것처럼 안내하지 않는다. 캐릭터·말풍선·mini의 실제 표시 크기, 밝고 어두운 바탕에서의 윤곽, reduced-motion에서의 상태 구분을 시각적으로 확인한다.

원본 자산을 채택할 때 자산명·제작자·원본 URL·라이선스/버전·다운로드 날짜·변환 내용·배포할 파일의 해시를 기록한다. CC0 후보도 출처를 남겨 수정과 재생성이 가능하게 한다. 편집 도구의 라이선스가 가져온 원본 그림·텍스처·음원의 권리를 대신하지 않는다.

**현재 팩 내보내기는 `author` 120자, `source`/`license` 각각 300자의 metadata와 참조 이미지·MD만 보존하며 별도 LICENSE/NOTICE 파일을 자동으로 포함하지 않는다.** 첫 시범은 자체 제작/CC0를 우선한다. 별첨이나 다수 자산의 출처를 요구하는 항목은 보존 형식을 설계·검증한 후 채택한다. 기존 팩에 임의의 라이선스 문서를 넣으면 함께 내보내진다고 안내하지 않는다.

Fab/Unity 상품과 Sonniss 소리는 완성 앱에서의 이용과 사용자가 다시 내보내는 독립 팩의 배포를 구분한다. 특히 Sonniss의 현행 조건은 수정한 소리도 라이선스 대상이며 소리/에셋 팩 재배포를 제한한다. 처음에는 자체 생성 소리와 앱 내 고정 소리를 검토하고, 이 공급처의 자료가 팩 내보내기에 섞이지 않게 한다. [Sonniss 배포 조건](https://sonniss.com/gdc-bundle-license/)

## 검증과 전달 계획

작업별로 기존 검사를 확장하고 실패 경계를 검증한다. 단순 문구·동일 구현을 반복 확인하는 테스트는 늘리지 않는다.

| 변경 범위 | 우선 검증 | 실제 환경에서 확인할 내용 |
|---|---|---|
| BUD01/03 | `test/attachments.test.cjs`, `scripts/attachments-ui-smoke.cjs`, 관련 접수/저장 회귀 | 클립보드·드롭·IME·여러 파일·대화 전환·보류 상태 동시 접수 |
| BUD02/04 | `scripts/buddy-lifecycle-smoke.cjs`, `scripts/buddy-features-smoke.cjs`, 설정 복원 검사 | 실제 OS 알림·단축키 충돌·초점 유지·글자 확대·잠금·정숙 |
| O01/O04/O08 | `test/connection-images.test.cjs`, `scripts/connection-image-smoke.cjs` | 새 설치·미로그인 콜백·외부 제공자·진단 파일 가림 |
| BUD05/06 | 이미지/팩 단위 검사, `smoke:assets`, `smoke:buddy`, 팩 왕복 검사 | 원본 저장·이미지 복사·프레임 decode·작은 크기의 표정·오디오를 켰을 때의 재생 |
| BUD07/08/09 | 소유 대화/저장 복구 검사와 지원/미지원 CLI fixture | 긴 기록·실제 리뷰/계획·스킬 선택·사용 한도 응답과 실패 |

각 변경에서 관련 단위·UI 검사가 통과하면 `npm run lint`, `npm run check`, 해당 통합 회귀를 수행한다. 배포 후보에는 `verify:package`로 ASAR/워커/팩 포함 범위를 확인하고 별도 staging에서 결과를 검토한다. 단순 계획 문서 작성에는 코드 회귀 검사를 실행한 것처럼 기록하지 않는다.

자원 평가는 같은 팩·같은 설정·같은 환경에서 전후로 비교한다. 유휴/숨김/잠금의 CPU·메모리·timer·IPC, 이미지 가져오기와 저장 지연을 확인한다. 배터리·Windows·DPI·설치/서명은 기존 C08/C10의 실기 범위를 유지한다. 개발 실행의 성공만으로 패키지 OS 알림이나 다른 플랫폼이 검증됐다고 표시하지 않는다.

실제 모델 실행은 fixture 회귀 이후 필요한 사례를 선택해 확인하며 호출 여부·모델·환경·결과를 기록한다. 계획/리뷰/스킬의 스키마 존재, 모의 CLI 결과, 실제 응답을 구분한다. 완료 기록에는 변경 내용·통과한 검사·실패/미검증 범위·복구 방법을 남기고 그때 [TASKS](../TASKS.md)의 상태를 갱신한다.
