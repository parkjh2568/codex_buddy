# 저장과 복구

설정·소유 대화 목록·본문은 JSON으로 저장하고 두 파일 교체는 저널로 복구한다. 저장 성공 후 등록부를 반영하며 실패하면 원본을 보존한다. 이는 프로세스 중단 복구이고 모든 파일/디렉터리를 fsync하는 DB 트랜잭션이나 전원 상실 내구성 보장은 아니다.

## 파일과 저장 시점

실제 위치는 설정의 기록 폴더 열기로 확인한다. macOS 기본 위치는 `~/Library/Application Support/OnggiBot/`다. 기록은 평문이며 CLI 인증 토큰은 저장하지 않는다.

| 파일 | 내용·한도 |
|---|---|
| state.json | v2 설정·활성 대화·소유 목록/제목/미리보기/연결 문맥, 최대 8MiB |
| conversations/UUID.json | 질문·답변·실행 상태·모델/추론/속도·첨부 참조·선택형 timing, 최대 32MiB |
| save-journal.json | 저장 중 대상 대화 ID와 state/history SHA-256 |
| delete-journal.json | [삭제](DELETE_CONVERSATIONS.md)의 확인 단계와 소유 범위 |

접수·thread 연결·완료/중단·측정 확정·대화 전환 때 저장한다. 설정/위치만 바뀌면 본문 직렬화를 생략한다. 스트리밍 글자마다 쓰지 않으므로 비정상 종료 직전의 부분 응답은 로컬 파일에 없을 수 있다. CLI 자체 기록은 별도다. 접수는 미완료 답변의 예상 공간을 예약해 초과 질문을 큐 등록 전에 거절한다.

## 저장과 복구 순서

1. 변경된 본문과 목록을 배타 .tmp 파일로 준비한다.
2. 본문이 바뀌었으면 소유 ID와 두 payload hash를 가진 저널을 .tmp→rename으로 확정한다.
3. 본문→목록 순서로 교체하고 저널을 제거한다.
4. 다음 시작에 저널이 남았으면 staged/final 파일의 hash·크기·소유 관계를 확인해 남은 교체를 마친다.

저널 확정 전 실패는 새 대화 등록·목록 변경을 메모리에서 되돌린다. 대화 전환 실패는 이전 활성 메시지·설정으로 돌아간다. 저널 확정 뒤 불확실한 실패는 파일을 보존하고 쓰기를 막는다. 오류로 접수되지 않은 미전송 질문이 복구 뒤 중단 상태로 나타나도 자동으로 CLI에 보내지 않는다.

완료 저장 실패는 화면 답변을 유지하고 다음 질문 실행을 멈춘다. 대기 취소의 저장 실패도 큐/쓰기를 막는다. 디스크 오류를 해결한 뒤 재시작해 복구한다. 저널의 hash·소유·크기가 맞지 않으면 자동 삭제/덮어쓰기 대신 복구 안내를 표시한다. 저널 없는 .tmp는 고유 orphan 이름으로 보존하며 자동 등록·만료하지 않는다.

## 읽기와 백업

canonical 폴더·일반 파일·링크를 확인하고 가능한 OS에서 no-follow/nonblocking FD로 연다. 최초 FD 크기+1 이내만 읽으며 UTF-8·읽기 전후 identity/크기/시각·경로 변경을 검사하고 항상 FD를 닫는다. 저널 hash는 원시 바이트 기준이다. 검사 직후 FIFO로 교체돼도 open에서 무한히 기다리지 않도록 한다.

생성자는 검증해 읽은 원본 바이트를 설정 복구·v1 이관·오류 백업에 사용한다. 백업 때문에 원본 경로를 다시 열지 않는다. 안전한 원본을 확보하지 못하거나 백업이 실패하면 쓰기를 차단하고 원본/저널을 남기며 삭제 복구를 이어 실행하지 않는다. 원본을 안전하게 읽고 백업한 상태의 손상 JSON은 경고 후 기본 상태로 시작할 수 있다. 모든 읽기 오류를 새 기록 생성으로 취급하지 않는다.

활성 대화 본문 읽기 또는 이어지는 직렬화·fingerprint 생성이 실패하면 state 백업 성공 여부와 관계없이 쓰기와 자동 삭제 복구를 차단한다. state 백업에는 본문이 없으므로 저장 worker도 후속 쓰기를 진행하지 않는다. 유효한 JSON이어도 깊은 중첩으로 직렬화가 실패할 수 있다. v1 이관의 백업·저장 실패도 쓰기를 차단해 빈 기본 상태가 원본을 덮지 않게 한다. 대화 읽기는 최초 경로 identity와 열린 FD, 읽은 뒤 FD와 현재 이름의 파일을 모두 대조하며 교체를 감지하면 두 파일을 보존한다. [2026-10-27 RCA와 회귀](plans/PRODUCTION_ENGINEERING_PLAN_2026-10-27.md#5-rca와-실제-수정)를 따른다.

v1 이관은 원본 state를 고유 이름으로 백업하고 남은 대화를 v2 목록에 등록한다. 이미 구버전에서 지운 기록이나 미등록 외부 세션을 자동 복원하지 않는다. 팩/말투 생성 저널의 별도 호환 조건은 [팩 복구](CHARACTER_PACKS.md#사용자-말투와-팩-복구-파일)를 따른다. 같은 권한의 외부 프로세스가 모든 상위 경로를 동시에 바꾸는 공격까지 완전히 격리하는 것은 아니다.

## 저장 worker와 실패 수명

saveAsync는 한 번에 하나만 실행한다. worker가 직렬화·SHA·저널·파일 교체를 수행하고 성공 뒤 main 등록부를 갱신한다. 큰 대화의 접수/연결/완료/취소/측정/정상 종료 저장에 사용한다. 상태를 바꾸는 IPC는 저장 완료를 기다리지만 포인터·창 열기·복사·제어 동작은 계속 처리한다.

snapshot 비교값은 원시 JSON 대신 fingerprint로 유지한다. worker에 보내는 등록부 동기화도 revision이 바뀔 때로 줄인다. 초기 읽기·일부 대화 전환/작은 설정·삭제 복구는 동기 경로다. 메시지 구조화 복사와 전체 JSON·SHA 비용은 남는다. 정상 종료는 진행 중 저장과 중단 상태 확정을 마친 뒤 worker를 정리한다. crash/timeout은 쓰기를 막고 재시작 복구를 안내한다.

대화 전환의 최종 저장은 정상 v2의 key 순서/집합·threadId 일치·정규화 후 32MiB 한도를 확인하면 방금 계산한 fingerprint를 사용해 state만 저장한다. 그 외 형식은 기존 본문 정규화·전체 저장 검사를 유지한다. 초기 읽기와 전환의 현재 대화 저장은 여전히 동기이며, 이 개선을 전체 비동기화로 표시하지 않는다. [10월 28일 비교와 수용 범위](history/ENGINEERING_REASSESSMENT_2026-10-28.md)를 따른다.

다른 대화의 본문 읽기·직렬화·해시 준비는 활성 상태를 바꾸기 전에 마친다. 준비가 실패하면 현재 메시지·설정·snapshot·디스크를 그대로 유지한다. 같은 대화를 다시 열 때는 현재 미저장 본문을 먼저 저장한 뒤 읽어, 옛 본문으로 되돌아가지 않게 한다. 최종 state 저장 실패 시 이전 상태로 되돌리는 계약과 불명 commit의 쓰기 차단은 유지한다. 10월 30일 보존 회귀는 `test/store-transition-failure.test.cjs`에 있다. 이 추가 수정의 성능은 이전 후보의 비교 결과로 대신 승인하지 않는다.

## 기록 조회와 내보내기

단계 표시·검색 예산·원격 페이지 병합은 [대화 조회](CONVERSATIONS.md)가 기준이다. 검증한 페이지를 저장한 뒤 메모리 cursor를 전진시킨다. 재시작은 처음 페이지를 다시 조회해 ID로 중복을 제거한다. 페이지마다 전체 snapshot을 쓰므로 누적 쓰기 증폭은 남는다.

Markdown 내보내기는 접수 시점의 제목·출력 필드·첨부/이미지 metadata를 고정하고 긴 불변 문자열은 공유한다. 예전 객체/배열형 error는 선택적으로 깊게 복사한다. 이미지는 하나씩 검증/쓰기한다. 선택기 이후 원본 변경이 출력 사본을 바꾸지 않으며 실패로 남은 쓰기 시작 파일·외부 추가/변조 파일은 지우지 않는다.
