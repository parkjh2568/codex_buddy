## 기록 읽기 크기 상한 보완

[src/store.cjs의 readHistory](../../src/store.cjs:98)는 경로·파일 종류·stat/fstat의 32MiB 한도를 확인하지만, 이후 `fs.readFileSync(descriptor)`는 파일 끝까지 읽고 반환된 Buffer의 크기를 검사한다. 검사 직후 같은 파일이 커지면 허용 상한을 넘는 I/O와 allocation이 먼저 발생한다.

임시 80바이트 파일을 FD의 fstat 직후 33MiB로 늘리는 제어된 주입에서 **34,603,008바이트 Buffer를 반환한 뒤 오류로 거부**하는 것을 확인했다. [재현 코드](../../artifacts/remaining-work-2026-10-14/history-growth-probe.cjs)와 [결과](../../artifacts/remaining-work-2026-10-14/history-growth-probe.json)가 있다. 임시 폴더는 정리했다. 큰 내용은 JSON decode/수용 전에 거부됐으므로 데이터 손상·원격 공격·실제 OS peak memory를 증명한 결과는 아니다.

수정은 기존 `readHistory` 안에서 제한된 FD 읽기와 초과 감지, 후속 fstat에 의한 변경 확인을 검토한다. 무제한 읽기를 다른 helper로 옮기는 것만으로 해결되지 않는다. worker 도입이나 DB 변경보다 먼저 크기 상한을 보장한다.

완료 조건은 작은 정상 파일·정확한 32MiB·초과·stat 후 성장·잘림·손상 UTF-8·링크/폴더 교체·읽기 실패에서 실제 최대 읽기량이 제한되고, 기존 정제·오류 안내·원본 보존이 유지되는 것이다. FD 정리와 성장/교체 경합 검사를 추가하며 실제 수정 전에는 해결 완료로 표시하지 않는다.

### 30초 전체 숨김의 확정 정책과 설계 제안

사용자 확정 사항은 **전달 완료 뒤 30초에 입력창을 포함한 전체 말풍선을 숨기고, 버디 클릭으로 다시 여는 것**이다. X는 즉시 숨긴다. 기존 X와 버디 재열기 동작은 이미 있고, 자동 30초 수명은 없다. 숨김은 대화·첨부·초안 삭제나 진행 작업 취소가 아니다.

남은 설계/구현은 다음과 같다.

1. 전달 완료를 저장 성공·이미지 원본 처리 완료·실제 표시로 연결한다. 보이는 복수 preview의 준비/실패도 확인한다. CLI 완료 이벤트 하나만으로 시작하지 않는다.
2. `measureResponseTime`은 기본 false이고 timing은 [조건부 생성](../../src/main.cjs:1362)이다. 현재 배치 ACK만 재사용하면 기본 설정에서 숨김이 작동하지 않을 수 있다. 측정 옵션과 독립적인 심플 답변/표시 세대를 설계한다.
3. main이 deadline을 소유하고 대화·답변·표시 세대·frame·가시성을 확인한다. 이전 RAF·답변·대화·renderer 재로드가 새 화면을 숨기지 않도록 무효화한다.
4. 매 상태 갱신·버디 움직임·모델 조회마다 30초를 초기화하지 않는다. 저장 실패·승인·절전/잠금·상세/설정 전환·새 답변 수명을 명시한다.
5. 비어 있지 않은 초안·IME·열린 메뉴·파일 선택·큐 편집·실행/대기·승인·중요 오류 동안 자동 숨김을 유예하고, 보호 해제 후 30초를 다시 주는 규칙은 **기존 계획의 제안**이다. 확정된 사용자 요구로 취급하지 않고 구현 전 해당 정책을 확정해야 한다.

완료 판정에는 29초 X·30초 자동 숨김·재열기·늦은 이미지·숨김 중 완료·시간 측정 off·새 답변과 이전 timer 경합·대화 변경·저장 실패를 포함한다. 30초를 실제 기다리는 화면 수용과 제어된 timer 검사도 구분한다.

### 상세 크기 조절과 설정 정렬

[panel 생성](../../src/main.cjs:484)은 투명 창·`resizable:false`이고 [showPanel](../../src/main.cjs:209)은 상세를 460×740 기준으로 다시 설정한다. 모서리 조절과 마지막 상세 bounds 보존이 모두 필요하다. 한 옵션을 바꾸는 것만으로 완료하지 않는다.

우선안은 기존 창의 상세 모드에 4개 모서리 조작 영역을 두고 main에서 제한된 bounds 변경을 수행하는 것이다. 먼저 격리 시제품으로 투명 창·pointer capture·프로그램 크기 변경을 확인한다. 시작 세션·반대 모서리·유한 좌표·최소/디스플레이 작업 영역 최대·늦은 IPC·pointercancel/lost capture·잠금/숨김/모드 전환을 검사한다. 드래그마다 JSON 저장·모델 조회를 하지 않는다. 다른 창이나 과거 세션의 요청은 적용하지 않는다. 현재 최소 크기와 영구 저장 여부는 [UI 계획](CHAT_UI_REDESIGN_PLAN_2026-10-13.md)의 범위를 따른다.

설정창은 input/time/select의 높이·오른쪽 기준선, switch·보조 설명, 접기 헤더, 캐릭터 이미지 비율과 글자, 긴 경로/오류·관리 버튼 줄바꿈을 함께 정리한다. 3스킨·작은/확대 창·섹션 모두 펼침을 실제 화면에서 확인한다. 코드상 차이를 모든 화면의 시각적 결함으로 단정하지 않는다.

상세 수치와 재현 명령은 [성능 결과](PERFORMANCE_OPTIMIZATION_RESULT_2026-10-13.md)를 따른다. 작은 기록의 지연이나 모든 percentile 개선은 확인되지 않았다. 실제 서비스 부하·원격 모델·SQL N+1을 측정한 결과도 아니다. 모델 dedup의 O(M²)은 상한 200·기존 TTL/single-flight 때문에 현재 우선 병목보다 낮으며 실제 요청/cache miss 근거 후 판단한다.

큰 main/renderer를 줄 수만 보고 나누는 작업은 보류한다. 접수·저장·표시의 소유권과 실패 경계가 독립된 경우에만 모듈화하며, 인라인 가능한 단순 로직을 helper로 추가 추출하지 않는다. SQL DB·범용 상태 관리·이벤트 버스·virtualization도 측정 없이 도입하지 않는다.

## 앱 전달과 외부 배포

최신 소스를 사용하려면 새 후보가 필요하다. `scripts/package.cjs`는 buildVersion 36과 overwrite를 사용하므로 기존 staging을 먼저 보존하고 다음 후보를 구분하는 build 식별을 정한다. 새 번들·ASAR·unpacked Store/worker·아이콘/고지를 대조하고 패키지 검사·strict 서명·격리 네이티브 실행을 확인한다. 최신 소스의 전체 integration도 후보 소스와 일치해야 한다. 일반/rollback 앱과 실사용 데이터를 자동 교체하지 않는다.

외부 배포가 필요해지면 Developer ID/공증·Windows 코드 서명·DMG/PKG 또는 설치 프로그램·업데이트/rollback 체계를 별도로 설계한다. 현재 로컬 ad-hoc 서명은 외부 배포 준비를 대신하지 않는다. 새 PC의 실제 설치/실행 실패·권한·CLI 설치 의존성까지 확인해야 완료다.
