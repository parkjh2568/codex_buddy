## FIRST_RUN_REVIEW

원래 경로: `docs/FIRST_RUN_REVIEW.md`.

### 최초 설치·Codex 연결

앱은 CLI/작업 폴더·인증·모델 목록의 준비 상태를 나누고, 실패 원인에 맞는 해결 버튼을 표시한다. 기존 CLI 로그인 캐시를 재사용한다. alpha.13/build28에서 연결 복구와 브라우저 로그인 안내를 구현했다. 구현 전 공백 분석은 [최초 연결 검토 이력](FIRST_RUN_REVIEW.md)에 보존했다.

#### 현재 사용 흐름

| 상태 | 동작 |
|---|---|
| 프로세스 연결 중단 | 한 번 자동 복구. 실패하면 `다시 연결` |
| CLI 경로가 바뀌거나 없음 | `자동으로 다시 찾기`, 필요하면 `설치 안내` 또는 실행 파일 선택 |
| 작업 폴더 없음 | `작업 폴더 선택` |
| 로그인 필요 | `ChatGPT로 로그인`으로 검증된 공식 HTTPS 주소를 기본 브라우저에서 열기 |
| 로그인 대기 | 앱에서 완료 확인, 취소 또는 5분 만료 |
| 모델 조회 실패 | 원인 표시 후 다시 확인. 다른 모델로 자동 변경하지 않음 |

다른 실행 파일/작업 폴더는 파일 종류·접근성·initialize 확인 후 확정하고 기존 기록을 보존한다. 새 연결은 새 대화를 준비하며 이전 대화를 열면 해당 연결 문맥을 복원한다. 공용 인증 토큰/이메일/인증 URL을 기록에 복제하거나 공용 CLI 계정에서 로그아웃하지 않는다. 중단된 질문·대기 질문은 자동 재전송하지 않는다.

alpha.18은 인증 조회에도 연결·계정 수명을 적용한다. 로그아웃/연결 교체/dispose 뒤의 성공·오류는 현재 상태를 덮지 않는다. 이전 조회가 끝나도 새 조회의 소유권을 해제하지 않는다. 로그인 완료 직후 계정 갱신이 교차하면 현재 상태를 한 번 다시 확인하며 반복 갱신에서는 재연결 안내를 유지한다. 실제 새 계정 브라우저 인증은 여전히 별도 수용이다.

#### 검증·남은 범위

설치된 CLI 캐시 인증 읽기는 확인했다. 로그인 정상/취소/중복/콜백 순서/URL 거절/만료는 단위·테스트 CLI 검증이다. 실제 미로그인 계정의 브라우저 콜백, 외부 제공자·Windows 신규 PC 설치/실행은 미검증이다.

alpha.15에는 CLI 버전·기능별 지원 상태, CLI→인증→폴더→모델의 단계 안내, 대화·인증 정보·개인 경로를 제외한 진단 JSON 내보내기를 추가했다. 실제 설치 CLI 0.162.0-alpha.2의 버전과 기존 인증·계획/스킬/한도 조회를 모델 호출 없이 확인했다. [확장 결과](BUDDY_EXPANSION_RESULT_2026-10-10.md)를 참고한다.

선택형 유료 테스트 질문, 새 PC 전체 설치 수용과 설치 프로그램은 후속 범위다. [남은 연결·환경 수용](../../TASKS.md#실제-환경에서-남은-수용)과 [연결/이미지 적용 기록](CONNECTION_AND_IMAGES_2026-10-08.md)을 따른다.

## BUDDY_MODES_REVIEW

원래 경로: `docs/BUDDY_MODES_REVIEW.md`.

### 버디·스킨·미니 대화·페르소나

현재 앱은 세 데이터형 스킨(paper/night/mono), 일반/미니 대화, 캐릭터별 Markdown 기본 성격/말투, v1 정적 팩과 v2 눈 깜빡임 팩을 지원한다. 구현 전 비교·계획과 build26 수용 기록은 [설계 이력](BUDDY_MODES_REVIEW.md)에 보존했다.

#### 현재 계약

스킨은 UI 색상, 캐릭터 팩은 외형/상태/프레임, MD는 질문의 기본 성격과 말투를 담당한다. 설정의 이름과 배율은 외형에 독립적이다. 미니 대화는 선택한 답변 하나와 하단 입력창을 보여주고 확장하면 같은 대화·초안을 유지한다. 일반/미니에서 작업 중 보낸 질문은 같은 FIFO를 사용한다.

MD는 캐릭터별로 분리하고 선택을 저장한다. 편집/복제/이름 변경/보관/복원은 사용자 MD와 registry의 소유권을 검사한다. 기본 내용 복원은 원본을 백업한 뒤 진행한다. 질문 접수 시 instructions/hash·모드·모델을 고정하므로 뒤의 편집이나 외형 변경은 이미 접수된 질문을 바꾸지 않는다.

팩은 미리보기에서 decode·규격을 검사한 뒤 확정한다. 교체/제거는 진행 작업과 대기열을 비운 뒤 진행한다. 내보내기는 작업 중에도 허용하며, 이미 접수된 질문의 말투 사본을 바꾸지 않는다. 편집 MD는 유지하며 제거 팩은 보관한다. 내보내기는 manifest/참조 이미지/MD만 포함하고 편집 MD 포함은 기본 꺼짐이다. 규격·보안·한도는 [캐릭터 팩](../CHARACTER_PACKS.md), 소유권/복구는 [구조](../ARCHITECTURE.md)를 따른다.

#### 표시·수명

정숙/일상/생동감은 안내와 장식 정책이며 실제 진행 상태/저장 오류/승인 필요를 숨기지 않는다. 화면 잠금은 표시·프레임·렌더 ACK를 억제한다. 절전은 현재 작업을 중단하고, 복귀 후 큐는 사용자가 계속한다. 기본 50%와 35/65% 배율을 유지한다.

캐릭터 목록에는 metadata/썸네일만 보내고 활성 팩의 자산/프레임만 전송한다. 프레임 timer는 창 좌표나 저장과 분리하고 숨김/교체/실패 때 정리한다. 실제 decode 실패는 fallback을 사용하며 metadata 검사만으로 성공을 주장하지 않는다.

Windows/DPI·물리 잠금/절전·장시간 번들/배터리 평가는 [후속 작업](../../TASKS.md)이다. 실제 모델의 말투/미니 검증은 [알파 결과](../ALPHA_REPORT.md)의 날짜별 근거를 따른다. Live2D/VRM·배회·다중 캐릭터·음성·기억과 Slack/중앙 FIFO는 미착수 범위다.

## FLOATING_PET_UPDATE

원래 경로: `docs/FLOATING_PET_UPDATE.md`.

### 플로팅 버디 동작

캐릭터 창은 안내 표시와 관계없이 기본 120×143 논리 픽셀을 유지하고, 안내는 별도 196×52 투명 창으로 표시한다. 상세 대화창의 초기 크기는 460×740이며 네 모서리로 조절하고 같은 앱 실행 동안 위치·크기를 유지한다. 심플은 기본 폭 360px/최대 높이 410px, 넉넉한 설정은 폭 400px/최대 높이 480px이며 내용에 따라 높이가 줄어든다. 화면 작업 영역이 작으면 크기를 제한한다. [대화 UI](../UI_UX_REFINEMENT.md)의 입력/숨김·크기 조절 계약을 따른다. 캐릭터 배율/팩에 따른 크기 변경은 [팩 규격](../CHARACTER_PACKS.md)을 따른다.

#### 이동·클릭·복구

드래그는 시작 지점의 절대 좌표·포인터 캡처를 사용한다. 캐릭터는 Dock/작업 표시줄·화면 밖으로 이동할 수 있고 안내 표시/숨김은 캐릭터 앵커를 바꾸지 않는다. 안내는 화면 경계 안에 배치하고 위 여유가 없으면 아래에 표시한다. 여백과 숨긴 하단 메뉴는 클릭을 통과시킨다.

대기 안내는 3초 뒤 숨고 캐릭터 hover 동안 유지한다. 하단 메뉴는 hover 진입 후 3초 뒤 숨는다. 드래그 중 안내/메뉴/장식 동작을 숨긴다. 재시작·화면 구성 변경에서는 보이지 않는 위치만 복구하며 트레이의 `버디 위치 초기화`와 `화면 복구`를 제공한다. renderer 복구에서는 notice 클릭 영역을 다시 등록하고 모델 질문을 재전송하지 않는다.

macOS는 비활성 panel·플랫폼 전용 창 옵션을 사용한다. Windows는 공통 이동/포커스·컬러 트레이·ICO/폰트 경로를 유지하지만 실제 동등 동작은 아직 확인하지 않았다.

#### 검증 명령과 한계

`npm run smoke:floating`은 합성 이동·앵커·클릭 영역, `npm run smoke:pointer`는 포인터 경로를 검사한다. `--verify-floating-restore`, `--verify-floating-recovery`는 첫 실행과 같은 격리 프로필을 순서대로 사용한다. `--native-floating-review`는 실제 마우스 드래그·클릭을 필요로 한다.

build13–24의 좌표/프레임/네이티브 검증 수치와 실패/재시도 조건은 [플로팅 이력](FLOATING_PET_UPDATE.md)과 [UI 이력](UI_UX_REFINEMENT.md)에 있다. 자동 검사는 Windows Snap/100–150%·혼합 DPI·IME·실제 절전/파일 잠금, macOS OS 타일링 미리보기 소멸·모니터 분리·전체 화면 Spaces 실기를 대신하지 않는다. [후속 작업](../../TASKS.md)을 유지한다.

## MARKDOWN_MODELS

원래 경로: `docs/MARKDOWN_MODELS.md`.

### Markdown과 모델 설정 확인·반영

2026-10-06, Codex CLI 0.160.0에서 확인하고 alpha.2부터 반영했으며 alpha.5에서 Fast와 자동 갱신, 입력창 밖 배치를 추가했습니다.

사용자 지정 앱 기본값: `gpt-5.6-luna / high`. Codex 전역 설정의 기본값과 별도로 앱 자체 설정에 저장합니다. 기존 alpha.1 기록의 대화·캐릭터 설정을 유지하고 새 모델 설정 필드에 이 기본값을 적용합니다. 이후 사용자가 직접 고른 모델·추론 값은 재실행에도 보존합니다.

#### Markdown

기존 alpha.1은 응답을 일반 텍스트로 표시했습니다. alpha.2는 답변에 Markdown을 적용합니다. 원문은 그대로 저장하며 전체 복사도 원문을 사용합니다. 사용자 질문·오류·승인 내용은 일반 텍스트입니다.

지원: 제목, 굵게/기울임/취소선, 순서/비순서 목록, 인용, 구분선, 인라인 코드, 코드 블록, 표, HTTP/HTTPS 링크. 코드 블록에는 코드만 복사하는 버튼이 있습니다. 표와 긴 코드는 가로 스크롤합니다.

markdown-it 15.0.2를 HTML 비활성으로 사용하고 DOMPurify 3.4.16로 허용 태그·속성만 남깁니다. 한국어 괄호·조사 경계의 강조(`**…(…)**는`)를 지원하기 위해 markdown-it-cjk-friendly 3.0.0을 적용합니다. npm 의존성과 렌더러를 esbuild로 묶어 로컬에서 로드합니다. CDN에 의존하지 않습니다. 이미지 자동 로딩, 임의 HTML, JavaScript/file/data URL은 허용하지 않습니다. 웹 링크는 클릭 시에만 시스템 브라우저로 엽니다.

50ms 화면 갱신에서 내용이 바뀐 답변만 다시 렌더링합니다. 미완성 코드 블록도 표시하고 완료 시 다시 해석합니다. 100,000자 응답 상한은 기존 알파와 같습니다. 코드 구문 강조, 수식, 실제 체크박스는 후속 확장입니다.

#### 모델·추론 변경법

1. 일반 실행으로 옹기봇의 대화창을 엽니다. 체험 모드에서는 모델 호출과 선택이 비활성입니다.
2. 질문 입력 박스 안쪽 하단 오른쪽의 모델 버튼을 눌러 팝업에서 모델을 선택합니다. 같은 줄 왼쪽은 말투 선택입니다.
3. 추론 선택에는 해당 모델이 지원하는 단계만 표시됩니다. 모델을 바꾸면 추론 선택은 기본으로 돌아갑니다.
4. 속도에서 Standard 또는 CLI가 제공한 Fast를 선택합니다. 앱 기본 속도는 Standard이며 Fast는 사용량이 증가합니다.
5. 질문을 보냅니다. 응답 위에 전송한 모델·추론 단계·Fast 설정이 기록됩니다.
6. CLI 기본 설정으로 돌아가려면 모델을 `CLI 기본값`, 추론을 `기본 추론`으로 선택합니다.
7. CLI 설정을 외부에서 바꿨거나 목록을 다시 읽으려면 `↻`를 누릅니다.

모델 변경은 현재 대화를 유지하고 다음 질문부터 적용합니다. 진행 중이거나 이미 대기 중인 질문은 전송 때의 설정을 유지합니다. 모델 제공자·로그인·API 키는 CLI가 관리하며 앱에서 변경하지 않습니다. 사용자의 전역 Codex 설정 파일도 수정하지 않습니다.

#### 기본값 의미

| 선택 | 적용 |
|---|---|
| CLI 기본값 + 기본 추론 | config/read의 모델·추론 설정 |
| 지정 모델 + 기본 추론 | 그 모델의 defaultReasoningEffort |
| 지정 모델 + 지정 추론 | 두 값을 검증해 turn/start에 전달 |
| CLI 기본값 + 지정 추론 | CLI 모델과 지정 추론 |

CLI에 모델 설정이 없으면 목록의 기본 모델, 추론 설정이 없으면 선택 모델의 기본 추론을 사용합니다. 기본값 복귀 때도 실제 값을 명시해 이전 질문의 모델 override가 남지 않게 합니다.

이번 PC에서 CLI 설정은 `gpt-6.1-sol / high`이고 같은 모델의 카탈로그 기본 추론은 `low`였습니다. 따라서 CLI 설정의 기본값과 모델 자체 기본값을 구분합니다. 모델 목록과 지원 단계는 하드코딩하지 않습니다.

모델 목록은 계정·제공자·CLI 버전에 따라 달라질 수 있으며, 목록에 있다는 사실만으로 실제 실행 권한을 보장하지 않습니다. 선택 모델이 사라지거나 추론 단계가 지원되지 않으면 오류를 표시하고 자동으로 다른 모델을 선택하지 않습니다.

#### 모델 목록 자동 갱신과 Fast

모델 ID·표시 이름·설명·추론 단계·속도 ID/이름/설명은 `model/list`의 응답에서 가져옵니다. CLI 설정의 모델·추론 기본값은 `config/read`를 읽습니다. 앱에서 사용자가 선택한 `gpt-5.6-luna / high`는 별도 기본값입니다. Standard는 앱의 일반 속도 선택입니다. 모델 목록은 CLI의 카탈로그이므로 사용 권한·서버 제공 상태를 보장하지 않습니다.

기존 버전은 최초 연결과 수동 `↻`만 갱신했습니다. alpha.5는 대화창 열기·포커스·모델 선택 영역 접근·질문 전송 때 캐시가 5분 이상 지나면 다시 조회합니다. `↻`는 즉시 재조회합니다. 백그라운드에서 5분마다 계속 모델을 호출하는 동작은 없습니다. 조회에는 추론 호출이 필요하지 않습니다.

CLI 실행 파일의 경로·파일 ID·크기·수정 시각이 바뀌면 캐시가 신선해도 유휴 상태에서 기존 app-server를 종료하고 새 파일로 연결합니다. 저장된 대화 ID는 유지하고 다음 질문에서 재개합니다. 실행·대기 중인 질문이 있으면 재시작을 미뤄 현재 요청을 보호합니다. 앱이 CLI 소프트웨어 자체를 자동 설치하거나 업데이트하지는 않습니다. 새 목록은 선택한 CLI가 실제로 반환하는 범위 안에서만 표시됩니다.

설치 CLI 0.160.0은 7개 모델에 `serviceTiers: [{id: "priority", name: "Fast", ...}]`를 반환했습니다. UI는 이 ID를 읽어 `turn/start.serviceTierForTurn`에 질문마다 전달합니다. Standard는 스키마가 지정한 `default`를 명시하여 이전 Fast가 남지 않게 합니다. 추론 단계를 낮추거나 모델을 바꾸는 방식이 아닙니다. 미래 CLI가 다른 속도 ID/이름을 반환해도 목록에서 읽습니다. 필드가 없는 이전 CLI에는 Fast를 임의로 표시하지 않습니다.

모델·추론·속도는 질문 접수 시 큐에 고정합니다. 이미 대기 중인 질문에 나중 설정을 소급하지 않습니다. 새 모델에서 기존 속도가 미지원이면 모델 변경 시 Standard로 돌아갑니다. 저장한 속도가 갱신된 목록에서 사라지면 미지원 표시와 오류를 내며 사용자가 속도를 다시 선택합니다.

[공식 Speed 문서](https://learn.chatgpt.com/docs/agent-configuration/speed)는 Fast 사용량 증가와 모델·계정·워크스페이스에 따른 지원 차이를 설명합니다. 실제 응답 속도 향상이나 서버가 사용한 최종 등급을 이 알파에서 측정·보장하지 않습니다.

#### 검증 범위

`smoke:models`는 카탈로그/기본값·Fast·질문별 스냅샷·자동 갱신/포커스·대화 유지를, `smoke`는 Markdown 보안/미완성 코드/복사를 확인한다. 실제 Luna/high 응답·Fast 요청과 당시 CLI 모델 7개 조회는 [검증 이력](MEASUREMENTS_BEFORE_CLEANUP_2026-10-10.md)에 보존한다. 모든 모델의 실행 권한·최종 서버 등급·속도 향상을 보장하지 않는다.

근거: [OpenAI App Server](https://learn.chatgpt.com/docs/app-server), [markdown-it](https://markdown-it.github.io/markdown-it/), [DOMPurify](https://github.com/cure53/DOMPurify).

캐시를 가진 자동 갱신 중 선택 메뉴를 비활성화하지 않고, 모델 메뉴에 포커스가 있으면 옵션 교체를 나중으로 미룹니다. 포커스를 벗어나면 받은 목록을 반영합니다. 수동 새로고침은 명시적인 재조회로 기존 로딩 표시를 사용합니다.

##### 1. 저장 읽기·복구 방어

- 대상: [store.cjs](../../src/store.cjs)의 생성자 state 읽기, `readHistory`, `recoverPendingDeletion`의 저널/본문, `recoverPendingSave`의 저널/최종·임시 payload open 6곳과 [저장 worker](../../src/store-worker.cjs)의 호출 경계.
- 작업: 플랫폼 지원 시 nonblocking open을 적용하고 일반 파일·링크·FD identity·읽기 전후 변경 확인을 유지한다. 기존 크기 한도, BOM/UTF-8 처리, v1/v2 이관, 저널의 hash·소유 대화 검증을 바꾸지 않는다. 단순 flag/검사를 불필요한 새 헬퍼로 추출하지 않는다.
- 예외: 일반 파일→FIFO/링크/다른 inode 교체, 삭제·권한 오류, 부분 JSON, 저장/삭제 저널 공존, 읽기 실패 뒤 쓰기 차단, worker 오류·종료. 플랫폼 미지원 검사는 skip 이유와 별도 수용 범위를 기록한다.
- 완료: 현재 두 실패 재현이 bounded error로 끝나고, 나머지 네 open 지점도 격리 회귀로 확인한다. 원본·임시/저널 보존과 기존 복구 결과를 대조한 뒤 `npm run verify` 및 다른 담당자의 독립 리뷰를 통과한다. 재현의 1초는 watchdog이며 성능 목표 시간이 아니다.

##### 2–3. 기준선과 패키지 전달

- 기준선: 미커밋 변경을 보존한 채 source/script/fixture/asset hash와 검사 시각·OS/Node/Electron·profile 경로를 기록한다. 278개는 현재 과거 증거의 수이며 후속 회귀가 추가되면 실제 검사 수로 갱신한다. 커밋은 별도 요청 범위다.
- 대상: [패키징](../../scripts/package.cjs), [ASAR 검증](../../scripts/verify-package.cjs), [패키지 자원 검사](../../scripts/packaged-resource-smoke.cjs), 버전·현재 안내 문서. 현재 buildVersion은 39로 고정되어 있으므로 다음 후보 식별자를 정하고 소스·앱 metadata·결과의 일치를 확인한다.
- 보존: staging은 `overwrite:true`이므로 기존 build39 후보를 보존할 별도 경로/복구본을 확인한 후 생성한다. 일반 실행 앱과 rollback build38을 자동 교체하지 않는다. 미완료 persona 생성 저널 v2는 현재 버전에서 복구를 마친 뒤 구버전으로 돌아가는 조건을 안내한다.
- 완료: 원본과 ASAR·unpacked worker/reader 바이트 일치, 제외 파일 누출 없음, 실제 ASAR의 팩/스킨/이미지/첨부·저장/검색·복구, 로컬 서명과 격리 startup/종료를 확인한다. 최신 후보의 5상태 자원 결과는 과거 후보와 구분한다. 실제 창을 여는 단계는 사용자 시간 허용 뒤 `--interactive`로 실행한다.
- 전달: 후보 검증 후 설치/실행 앱 교체를 별도 단계로 판단한다. 사용자 프로필을 자동 이관·삭제하거나 미완료 v2 저널을 구버전으로 복구하지 않는다. Developer ID/공증·외부 배포 완료로 표시하지 않는다.

##### 4. P01·P07: 동기 처리와 메시지 복사

- 대상: [Store](../../src/store.cjs)의 생성자·`readHistory`·`newConversation`·`openConversation`·`saveAsync`, [worker](../../src/store-worker.cjs), [main](../../src/main.cjs)의 대화 전환·본문 검색 activeMessages 전송·MD 내보내기 `structuredClone`. worker `postMessage`의 구조화 복사와 명시적 export clone은 다른 비용으로 측정한다.
- 먼저: 읽기/parse/정규화/SHA, worker 생성·postMessage·저장, export snapshot의 CPU·heap·최대 이벤트 루프 지연·총시간을 분리한다. 기존 [store 벤치](../../scripts/store-cost-benchmark.cjs)를 먼저 재사용하고 새 모듈 의존성이 생기면 격리 벤치의 module 복사 범위도 맞춘다.
- 구현 후보: 중복 직렬화/왕복 payload를 줄이는 작은 변경부터 검토한다. I/O만 Promise로 바꿔 parse/SHA가 main에 남는 문제를 해결했다고 표시하지 않는다. 추가 worker 작업은 기존 책임 경계 안에서 요청 ID·대화 ID·revision·취소·종료·저장과의 상호 배제를 설계한 뒤 적용한다.
- 예외: 저장 중 전환/종료, worker crash/timeout, 원본의 외부 변경, 취소 후 늦은 응답, export 도중 원본 변경·부분 파일 실패. 파일 형식과 접수→저장→FIFO 실행 순서를 유지한다.
- 완료: 동일 합성 데이터·동일 환경에서 전후 20표본과 실행 순서 교차로 중앙값/p95·main 지연·CPU·heap·논리 쓰기를 비교한다. 초기/대화 전환/저장/export 중 어느 경로가 좋아지고 나빠지는지 각각 기록한다. 사용자 반응성과 총시간·메모리의 허용 퇴행 기준을 변경 전에 정하고 충족하지 못한 후보는 채택하지 않는다.

##### 5. P04: 신규 캐시 쓰기

- 대상: [AttachmentStore](../../src/attachments.cjs)의 파일별 전체 조사와 [ResponseImages](../../src/response-images.cjs)의 신규 쓰기 조사·최종 stat snapshot 대조. 이미지 warm hit의 기존 개선은 다시 구현할 항목이 아니다.
- 기준: 마지막 합성 측정에서 10,000개 파일의 신규 이미지 1장은 총 177.30ms, 1ms timer의 최대 간격 54.02ms였다. 단일 관찰이므로 반복 측정으로 분포를 먼저 확인한다.
- 구현 후보: 한 접수의 최대 8개 파일에 대해 실제 신규 바이트를 먼저 계산하고, 작업 소유권 아래 quota 조사·확정을 묶어 반복 O(파일수×첨부수)를 줄일 수 있는지 설계한다. 이미지/일반 파일 보관 root별 lock·예약/확정·부분 성공을 분명히 한다. 단순 폴더 mtime 캐시나 검증 삭제는 사용하지 않는다.
- 예외·완료: 같은 크기 변조·조사한 inode의 성장·root 교체/링크·동시 import/capture·취소·부분 쓰기에서 quota와 원본 보존을 유지한다. 0/1,000/10,000개×1/8개 첨부의 stat/읽기/쓰기 횟수·메모리·이벤트 루프 지연을 비교하고 warm hit가 퇴행하지 않아야 한다. 원자적 외부 프로세스 잠금을 보장한다고 주장하지 않는다.

##### 6. P05: 페이지 저장 증폭

- 대상: [main](../../src/main.cjs)의 `open-conversation`/`load-older` 원격 페이지 병합→`saveAsync`→cursor 확정과 Store 저널/worker.
- 먼저: 현행 25턴 페이지 계약과 40페이지 논리 쓰기 약 20.52배를 같은 fixture에서 재확인한다. 증분 저장·명시적 batch commit은 대안 비교이며 채택이 확정된 설계가 아니다.
- 설계 필수: 새/구형 읽기, 변경 전 원본·백업, 실패 시 rollback, 중복/순서/ID 안정성, 페이지별 확정 시점, 취소 가능 구간, 종료·디스크 부족·중간 전원 상실의 보존 범위를 명시한다. 형식 변경과 UI 변경을 한 번에 묶지 않는다.
- 완료: 저장 성공 전 cursor 전진 0건, crash 지점별 재시작 결과·등록부/본문 일치·기존 메시지/첨부/목적 보존 확인. 논리/실제 쓰기 범위를 구분해 증폭 감소와 초기 읽기·검색·내보내기·삭제 퇴행 여부를 검증한다. 안전한 대안이 없으면 현행 포맷을 유지하고 설계 결과를 남긴다.

##### 7–8. P06·P03의 조건부 개선

- P06 대상은 [main 삭제 분기](../../src/main.cjs)다. 동시 4개는 이미 적용됐으며 RPC N회가 남는다. 지원 CLI에서 bulk/관계 조회의 실제 계약·기능 감지를 확인하는 조사까지만 우선 확정한다. source/폴더/실행 파일 소유권과 파생 관계·30초 전체 deadline·늦은 삭제 알림·부분 실패 재시도 저널을 보장하는 경우에만 호출 수를 줄인다. 지원하지 않으면 안전한 N회 경로를 유지하고 변경 불가 이유를 기록한다. 실제 모델 질문·삭제는 자동으로 실행하지 않는다.
- P03 대상은 [renderer의 renderHistory](../../src/ui/renderer.mjs)다. 최초 100개는 유지하고 100/1,000/전체 확장에서 DOM 수·렌더 시간·스크롤·메모리를 측정한다. 실제 지연이 확인될 때 행 재사용/가상화를 비교한다. 검색·정렬·즐겨찾기·삭제 재시도·열린 메뉴 대상·키보드 포커스·스크린리더·복귀 스크롤을 보존하는 회귀가 완료 조건이다. 레이아웃 계측과 실제 입력 검사는 화면 허용 뒤 수행한다.

##### 검증·진행 규칙

1. 안전성 수정 → 단위/정적 검사 → 독립 리뷰 → 지적 반영 → 최종 검증을 작업 단위별로 수행한다. 서로 다른 저장 변경을 한 번에 합치지 않는다.
2. 문서/계획 변경만으로 전체 GUI·자원 검사를 반복하지 않는다. 구현 변경에는 관련 headless 회귀와 `npm run verify`, 성능 변경에는 동일 조건 전후 벤치를 적용한다. 실제 창은 허용된 시간에만 연다. `smoke:changed`의 증거 재사용과 신규 실행을 구분한다.
3. 장기/배터리·충전기·실제 IME·잠금/절전·Finder 드롭·다른 앱 클립보드·OS 알림/Spaces는 아래 실기 목록을 사용한다. Windows/Intel·공증은 해당 장비/자격이 준비될 때 진행한다.
4. Slack·음성·기억·새 렌더 엔진·DB 도입·범용 플러그인·근거 없는 파일/테스트 삭제는 이번 범위에 포함하지 않는다. 단순 로직은 인라인에 두고 검증/소유권 경계가 바뀔 때만 모듈을 나눈다.

#### 유지할 UI·저장 계약

말투 옆 `+`에 첨부·작업 목적·스킬을 모으고, 심플은 선택한 답변과 하단 입력을 표시한다. 전달 완료 후 30초에 입력창을 포함한 전체를 숨기며 초안·IME·첨부 선택·메뉴·승인·실행/대기·저장/복구·중요 오류 동안 미룬 뒤 다시 30초를 준다. X는 즉시 숨기고 버디 클릭으로 다시 연다. 상세 네 모서리 크기와 위치는 같은 앱 실행 동안 유지한다. 규격은 [UI·접근성](../UI_UX_REFINEMENT.md)을 따른다.

원본·저널·첨부 사본·편집한 MD와 팩 복구본은 보존한다. 보관량 조회와 명시적으로 선택한 미참조 캐시의 복구 보관/복원은 구현했으며, 자동 영구 삭제를 추가하지 않는다. 단순 동기 로직을 불필요한 헬퍼로 옮기지 않는다.
