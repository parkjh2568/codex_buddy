# my_budy 품질 개선과 재검토 결과

이 문서는 alpha17/build33의 당시 결과다. 최신 alpha18/build34의 인증 수명·이미지 내보내기·기록 페이지·계측과 검증은 [후속 작업 결과](BUDDY_FOLLOWUP_RESULT_2026-10-10.md)를 따른다.

2026년 10월 10일, [alpha16 검토](CHANGE_REVIEW_ALPHA16_2026-10-10.md)의 R09–R12와 O11을 수정하고, 수정 후 재검토에서 재현한 첨부 제거 경합 R13도 보완했다. 현재 소스는 `0.1.0-alpha.17`, macOS arm64 staging 후보는 build33이다. 단순 처리는 기존 함수 안에 두었고 새 helper 모듈·런타임 의존성을 추가하지 않았다.

최종 단위 117개, 첨부 제거·trusted 드롭 경합을 포함한 격리 Electron 통합 14종, 패키지 84개 런타임 파일과 strict ad-hoc 서명 검사가 통과했다. 이번 작업의 실제 모델 요청은 0회다. 기존 일반 실행 build30은 교체하지 않았고 이전 staging build32를 복구 경로에 보존했다.

## 수정과 검증

| 이슈 | 변경 | 확인한 조건 |
|---|---|---|
| R09 편집 진입 초안 | 편집 진입 중 입력·전송·첨부·충돌하는 큐 조작 잠금. 화면 전환 시점의 일반 초안과 첨부 보존. 늦은 응답의 대화/예약 확인과 finally 해제 | 지연 응답·실패·대상 취소·예약 해결·대화 변경. 실제 Electron의 동기 잠금과 기존 reload/FIFO 회귀 |
| R10 fallback 설정 | hotkey를 명시한 요청에만 단축키 전환 등록. 동일 키 재등록과 선호 키 재시도·저장 rollback 유지 | fallback에서 글자/알림 저장, 명시적 충돌, 충돌 해소, 저장 실패 후 이전 등록 유지 |
| R11 사용량 병합 | 계정/연결/dispose revision은 전체 폐기. 같은 계정의 이후 이벤트 ID를 최대 16개 추적해 최신 항목을 보존하고 다른 항목을 전체 조회에서 보완 | 31% 이벤트와 23% RPC의 순서 교차, image 버킷 보존, 계정 변경, 오래된 오류, 불확실·과다 이벤트 |
| R12 연결 안내 | 한도 정보의 stale 상태를 연결 종료로 단정하지 않고 이전 값과 재조회 필요를 안내 | 정상 연결의 빈 한도 이벤트, 기존 값/시점 유지 |
| R13 첨부 제거 경합 | 첨부 제거가 끝날 때까지 기존 picking 상태를 사용해 편집·전송 잠금. 제거 대상의 초안 키를 await 전에 고정. preload도 첨부 제어 잠금을 확인 | 제거 응답과 편집 순서 교차, 제거한 파일이 편집 종료 후 복원되지 않음. 실제 Electron에서 저장 대기 중 제거 RPC와 trusted 드롭을 함께 검증 |
| O11 원본 읽기 | 이미지 저장은 대화상자 이후에만 검증한 원본을 읽음. 복사·재첨부는 해당 분기에서 읽음 | 취소 0회·저장 1회, 대화상자 사이 캐시 변조 거절, 원본 보존·외부 교체 파일 보존 회귀 |

편집 수명과 첨부 제어는 [renderer.mjs](../../src/ui/renderer.mjs:87), trusted 파일 입력의 UI 잠금은 [preload.cjs](../../src/preload.cjs:22), 설정·이미지 저장은 [main.cjs](../../src/main.cjs:1192), 한도 순서는 [connection-setup.cjs](../../src/connection-setup.cjs:23)에 있다. UI 잠금은 main의 소유권·자료 제한·저장·예약 검사를 대체하지 않는다.

표시하는 사용량의 전체 확인 시점은 병합된 항목 중 가장 이른 로컬 확인 시점으로 잡는다. RPC 뒤에 온 이벤트의 값을 오래된 전체 스냅샷으로 덮지 않으며, 미갱신 항목을 현재 이벤트와 동시에 확인했다고 표현하지 않는다. 어떤 항목이 바뀌었는지 판별할 수 없거나 추적 한도를 넘으면 RPC를 보수적으로 건너뛰고 재조회한다. 실제 서버 스냅샷의 정확한 시각을 보장하는 기능은 아니다.

## 수정 후 다시 확인한 사항

수정 후 검토에서 편집 진입 객체의 중복 필드를 제거했다. 저장량 계산은 같은 try 블록 안에서 들여쓰기만 정돈했다. 새 함수를 만들거나 동기 문자열 처리를 helper로 옮기지 않았다. 스킬 목록의 비동기 I/O와 파일/프로세스 검증 경계도 유지한다.

첨부 제거는 초기 편집 진입 검사에서 빠져 있던 조합이었다. 실제 UI 콜백에서 제거 요청을 지연하고 편집을 먼저 완료하면, 편집 종료 후 삭제한 `removed` 파일이 일반 초안에 다시 나타났다. [수정 전 실패 로그](../../artifacts/goal-alpha17-attachment-removal-before.log)는 이 파일이 남은 assertion 실패다. 실패 기록을 성공으로 바꾸지 않고 보존했다. 기존 picking 상태로 작업을 직렬화한 뒤 같은 회귀가 통과한다.

추가 검토에서는 prompt만 잠금을 확인하면 첨부 제거 중 trusted 드롭이 다른 입력을 시작할 수 있는 것도 확인했다. [입력 잠금 수정 전 실패](../../artifacts/goal-alpha17-input-lock-before.log)는 이 경로의 IPC 호출을 재현한다. preload가 파일/이미지 입력을 인식한 뒤 첨부 제어의 잠금까지 확인하도록 보완해, 바쁜 입력의 오류 callback이 다른 작업의 picking 상태를 해제하지 않게 했다. 일반 텍스트 붙여넣기·드롭은 첨부 입력으로 가로채지 않는다.

최종 Electron 검사는 실제 main action이 `store.saving`을 기다리는 동안 UI의 제거·편집 순서와 trusted 드롭을 교차시킨다. 편집/전송이 잠기고 숨은 편집 예약이나 새 첨부가 생기지 않는 것을 확인한 뒤 저장 대기를 해제한다. `ATTACHMENT_REMOVAL_EDIT_RACE_CHECKED`와 최종 exit 0이 근거다. 물리 파일 드롭이나 OS 클립보드의 실기 결과로 표현하지 않는다.

R01–R08의 기존 회귀도 함께 통과했다. 정상/저장 중 reload, 스크롤 읽음, 검색 revision, 도구 거절, 승인 해결, 파괴된 창, 저장 실패·FIFO·원문 복원·외부 파일 보존 경계를 유지한다. 새로운 문제를 단위 검사 숫자만으로 없다고 판정하지 않고 실제 변경 경로와 테스트가 다루는 조합을 확인했다.

## 주석과 제거 및 통합 판단

이번 제품 변경에는 새 TODO/FIXME·주석 처리 실행 코드·lint 억제를 추가하지 않았다. 기존 주석은 reload 보류, 접수 순서, 삭제 응답 순서, OS 미검증의 이유를 설명하며 현재 코드와 맞는다. 완료된 작업 지시를 남겨 둔 주석은 확인하지 못했다.

현재 쓰지 않는 새 metadata의 생성은 앞선 alpha16 정리에 포함돼 있다. Store의 과거 reviewState 허용은 호환 읽기이며 일괄 삭제 대상이 아니다. 필요한 프로세스·저장·첨부/이미지·팩 모듈을 통합할 근거도 없다. 현재 사용처가 있는 의존성을 줄이는 대신, 중복 원본 읽기와 불필요한 필드·들여쓰기를 정리했다.

README·TASKS·구조·빌드/검증 안내는 alpha17/build33의 현재 결과를 가리키게 갱신했다. alpha15·alpha16의 검토 및 수정 문서는 당시 기록으로 유지하고 최신 결과 링크를 붙였다. 오래된 실패 로그와 이전 사용자/복구 자료를 코드의 미사용 부분처럼 삭제하지 않았다.

## 실행 묶음과 한계

최신 후보는 [alpha17 staging build33](../../dist/staging/OnggiBot-darwin-arm64/OnggiBot.app)다. 이전 [alpha16 build32](../../artifacts/legacy-cleanup-2026-10-12/cleanup-targets.tar.gz)의 Info.plist·ASAR 해시를 복사본과 대조해 보존했다. [보존 근거](../../artifacts/goal-alpha17-rollback-backup.json). 일반 실행 alpha14/build30과 이전 alpha15/build31 복구 경로도 유지했다.

기존 버전이 실행 중이면 트레이 메뉴에서 그 작업 상태를 확인하고 종료한 뒤 후보 앱을 실행한다. 기존 사용 중인 앱이나 모델 작업을 이번 검사가 자동으로 종료한 것은 아니다. 후보를 일반 실행 경로로 교체하거나 공개 배포한 작업도 아니다.

실제 OS 클립보드 왕복·물리 드롭·IME·알림 배너/클릭/권한·새 계정 브라우저 인증·Windows/Intel·혼합 DPI·물리 절전/다중 모니터, Developer ID/공증·설치 프로그램은 기존 수용 범위로 남는다. 이번 모의/격리 검사를 이 영역의 완료로 표시하지 않는다. 로컬 ad-hoc 서명은 공개 배포 서명이 아니다.

## 기획과 개발 관점의 결론

시작한 문제와 전제, 처음 확인할 사용 사례, 2026년 10월의 공식 제품 변화, 현재 라이브러리의 이유와 다음 측정 우선순위는 [제품 방향 검토](../BUDDY_PRODUCT_REVIEW_2026-10-10.md)에 정리했다. 기본 질문·캐릭터 접점은 공식 앱과도 겹치므로, 개인 SVG/MD·고정 폴더의 같은 대화·명시적 FIFO·조용한 상태 확인이 실제 불편을 줄이는지 확인하는 것이 다음 투자 기준이다.

이 반복에서는 확인·분석 → 안전한 수정 → 수정 후 재검토 → 제품/구조 재평가를 수행했다. 확인한 R09–R13과 O11에는 남은 필수 수정이 없으며 검사·문서·후보의 현재 상태를 대조했다. 새 기능은 기존 계획의 착수 조건을 유지한다. 향후 사용 사례·플랫폼·성능 수용 과제를 이미 완료했다고 확장하지 않는다.
