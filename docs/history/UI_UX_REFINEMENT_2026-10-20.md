# 대화 UI·접근성

현재 alpha23 소스의 대화·설정 계약을 정리한다. build39는 이번 UI 후속 변경 이전의 패키지이며 새 소스를 포함한 재패키징은 하지 않았다. 말투 옆 `+`, 답변 중심 심플 모드, 보호 유예를 포함한 30초 전체 숨김, 상세 모서리 드래그와 설정 정렬을 지원한다. 설계와 도입 당시 검증은 [UI 작업계획](CHAT_UI_REDESIGN_PLAN_2026-10-13.md)·[alpha21 구현 결과](REMAINING_IMPLEMENTATION_RESULT_2026-10-14.md)에, 현재 검증·패키지·실제 화면 확인 범위는 [alpha23 구현 결과](IMPLEMENTATION_RESULT_2026-10-19.md)에 기록한다.

2026-10-19에 추가로 확인한 복합 상태의 잘림·정렬·정보 구조 문제와 수정 우선순위는 아래 [화면별 상세 감사](UI_UX_REFINEMENT_2026-10-20.md#화면별-상세-감사-2026-10-19)를 따른다. 기능 지원과 특정 기본 상태의 정렬 통과를 모든 상태의 UI 완성으로 해석하지 않는다.

후속 구현의 설계·완료 기준은 [최종 실행 계획](UI_UX_REFINEMENT_2026-10-20.md#uiux-최종-실행-계획-2026-10-20), 현재 소스 변경과 실제 검증 범위는 [구현 결과](UI_UX_REFINEMENT_2026-10-20.md#uiux-구현-결과-2026-10-20)를 따른다.

일반 대화는 공통 좌우 여백/기준선, 심플은 16px 여백을 사용한다. 입력창 하단의 말투 옆 `+`에 이미지·파일·클립보드 이미지·작업 목적·스킬을 모았다. 첨부 미리보기와 기본값이 아닌 목적/선택 스킬 요약은 입력창에 남긴다. 말투·`+`·모델/추론·중단·전송의 폭을 나누고 긴 이름은 생략해 버튼 공간을 보존한다. 넓은 상세 창에서는 최대 읽기 폭을 제한한다.

`+`와 모델 팝업은 동시에 열지 않고 밖 클릭/Esc로 닫는다. Escape는 열린 모달, 팝업, 창 숨김 순서를 지킨다. 파일 선택 전에 첨부 팝업을 닫고 기존 trusted 붙여넣기·드롭 경계를 유지한다. 모델 변경은 다음 질문부터 적용한다.

입력창은 여러 줄에 맞춰 높이가 늘고 줄이면 복귀한다. Enter 전송·Shift+Enter 줄바꿈·한글 조합 중 전송 억제를 유지한다. 작업 중 보내기는 일반/심플에서 FIFO에 접수한다. 새 대화의 첫 접수 때 텍스트/첨부 초안은 같은 대화 ID로 이전한다. 접수 실패는 초안을 유지한다.

## 심플 말풍선과 상세 창

최초 심플 모드는 작은 입력 말풍선이며, 답변이 있으면 main이 선택한 assistant 답변 하나와 아래 입력창을 표시한다. 현재 실행 답변을 우선하고, 대기 질문이나 내용 없는 대기 취소 카드가 이전 전달 답변을 밀어내지 않게 한다. 사용자 질문 카드·전체 도구 로그·복사/측정 도구는 상세에서 확인하며, 체험/실제 연결과 실패 안내는 유지한다. 이미지뿐인 답변은 빈 텍스트 상자 없이 표시한다.

심플 높이는 헤더·입력·선택 답변의 자연 높이에 맞추고 설정의 기본 410px/넉넉하게 480px 및 화면 작업 영역으로 제한한다. 긴 답변과 첨부 목록은 내부에서 스크롤하며 입력창이 밀려나지 않게 한다.

저장 성공·응답 이미지 처리 완료·실제로 보이는 미리보기의 준비 또는 실패 안내를 확인한 뒤 30초를 계산한다. 수신 대답속도 측정을 꺼도 표시 수명은 별도로 작동한다. 30초가 지나면 **입력창을 포함한 말풍선 전체를 숨기고 버디 클릭으로 다시 연다**. 일반 상태 갱신으로 시간을 다시 시작하지 않는다.

**확정한 보호 정책:** 초안·첨부 선택·승인 처리 중 자동 숨김을 미루고, 처리가 끝나면 새로 30초를 제공한다. 한글 조합·열린 팝업·실행/대기·큐 편집·저장/복구 상태도 보호한다. `×`는 보호 상태와 관계없이 즉시 숨기며 대화·초안·첨부·작업을 취소하지 않는다. 대화/답변 전환·다시 열기·상세/탭 전환·화면 복구·잠금/절전에서는 이전 표시 세대와 예약을 무효화한다.

상세 창은 네 모서리 드래그로 조절한다. 포커스한 모서리에서 방향키는 8px, Shift+방향키는 32px을 적용한다. 유효한 panel/main frame·세션·화면 영역을 검증하며 창 밖으로 이동한 포인터와 빠른 release도 정리한다. 크기 조절 중 파일을 반복 저장하지 않는다. 상세 크기·위치는 런타임에서 보존하므로 확장·설정/기록·재열기에서 유지되며 앱 재시작까지 저장하지는 않는다. 심플 배치가 상세 bounds를 덮어쓰지 않는다.

## 기록·이미지·설정

상세 기록은 최근 100개/약 256KiB 텍스트부터 표시하고 이전 묶음을 추가한다. 심플은 선택한 답변 하나만 만든다. 숨겨진 패널은 메시지/상태 캐시만 갱신하고 보일 때 DOM을 반영한다. 상세에서 지난 내용을 읽으면 스크롤을 보존하고 `맨 아래로`를 제공한다.

이전 대화 목록도 전체 정렬·검색 결과에서 100개씩 표시하고 `이야기 더 보기`로 추가한다. 대화 열기·즐겨찾기는 바로 표시하고 제목 변경·Markdown 내보내기·삭제는 이름 있는 `···` 팝업으로 모은다. 추가 질문은 request/question ID별 입력 노드를 유지해 재정렬 중 입력·선택·포커스를 보존한다. 질문 의미가 달라지면 이전 답변 초안을 별도로 남긴다.

답변은 정제된 Markdown으로 표시하며 원문/코드 복사 범위를 유지한다. 응답/첨부 이미지는 작은 보관 미리보기를 필요한 위치에서 로드하고 원본 열기 때 소유 참조를 검사한다. 실패 안내와 텍스트는 유지한다. 이미지 생성 원본을 새로 만들지 않고 기존 CLI 결과를 다시 읽을 수 있다.

친구 이름은 NFC 정규화 후 1–20 코드 포인트·제어 문자 거절 규칙을 사용한다. 저장 실패는 메모리 이름도 되돌린다. 이름은 질문 원문·기존 대화·앱 데이터 폴더를 바꾸지 않으며, 변경 후 접수한 질문의 말투 지시에 반영한다. 선택 탭의 aria-current, 설정 aria-pressed, 키보드 포커스·동작 줄이기를 유지한다.

설정은 버디 이름·섹션 바로가기와 화면/대화 옵션을 먼저 표시하고 캐릭터 선택은 `친구 모습`을 펼친다. select·시간 입력·스위치와 이름/저장 줄의 기준선을 맞추고, 팩·말투·연결·사용량의 접기 헤더를 통일했다. 캐릭터 이미지는 같은 박스 안에서 비율을 유지하고, 긴 이름·경로·도움말·복구 목록은 동작 버튼을 덮지 않게 줄바꿈/스크롤한다.

MD 저장은 읽은 파일의 hash를 확인한다. 외부 변경 시 앱 초안과 최신 파일을 비교하고, `초안 유지`·`최신 파일로 초안 교체`·`비교한 파일에 초안 저장` 중 선택한다. 비교 후 파일이 다시 바뀌면 다시 충돌을 알린다. 저장·기본 복원 처리 중 새로 작성한 입력은 보존하며 초안은 앱을 종료하면 사라진다.

## 검증 범위

alpha21 도입 당시 390×580·460×740·720×900 각각 3스킨의 정렬/overflow와 색상 전환 후 캡처를 확인했다. 이후 alpha22의 단위·Electron·패키지 검사와 실제 선택기·네 모서리·OS 클립보드 API 검증은 [Mac 후속 결과](MAC_FOLLOWUP_RESULT_2026-10-15.md)를 따른다. 당시 결과를 문서 정리에서 재실행한 검사로 표시하지 않는다.

alpha23의 390/460/720px×3스킨×3글자 배율 조작 영역·키보드 검사, 추가 질문 재정렬과 MD 충돌 비교의 실제 Chromium 검증은 [최신 구현 결과](IMPLEMENTATION_RESULT_2026-10-19.md)를 따른다. 합성 composition 이벤트와 노드/포커스 검사는 물리 한국어 입력기 수용을 대신하지 않는다.

`npm run smoke`에는 일반 460×740/작은 390×580 레이아웃·입력 확장·긴 이름·Markdown·큐·notice 검사가 포함된다. `smoke:buddy`는 세 스킨의 심플 레이아웃, `smoke:attachments`는 첨부/심플 FIFO, `smoke:stability`는 숨김/재표시·renderer 복구를 확인한다. `smoke:chat-ui`는 격리 체험 환경에서 `+`·답변 선택·실제 30초 대기·보호·미리보기와 크기 조절 소유권을 검사한다. 프로그래밍 기하/Chromium 입력 검사는 macOS의 실제 모서리 드래그 검증과 구분한다.

build16–25의 변경 경위·네이티브 화면·좌표/프레임 수치·당시 실패와 검증 제한은 [UI 이력](UI_UX_REFINEMENT.md)에 보존했다. alpha20/build36의 단위 147개·Electron 14종·패키지 85개 검증은 [당시 결과](FINAL_IMPLEMENTATION_RESULT_2026-10-13.md)이며 새 UI의 완료 근거로 바꾸지 않는다. Windows/혼합 DPI·스크린리더·OS 합성 영상·장시간 사용 평가는 별도 미검증이다.

## 화면별 상세 감사 (2026-10-19)

사용자 요청에 따라 화면 코드와 현재 소스의 실제 Electron 표시를 다시 확인했다. 이번 작업은 감사와 기록이며 제품 코드·스타일 수정은 하지 않았다. 기존 미커밋 작업을 유지했고 감사 실행을 모두 종료했다.

### 범위와 근거

- `src/ui/index.html`, `style.css`, `renderer.mjs`, `notice.html` 및 패널 배치/크기 조절 코드를 확인했다.
- 격리 체험 앱과 로컬 CLI fixture 앱을 사용했다. 실제 모델·계정 조회·로그인·사용자 대화 기록을 사용하지 않았다. 계정 사용량의 2033년 초기화 날짜는 fixture 값이다.
- 새 `npm run smoke`는 통과했다. 460×740·390×580·720×900 및 paper/night/mono의 기존 정렬 행렬을 실제로 실행했다. 의도적인 권한/이름 경계 거절 로그와 테스트 실패를 구분한다.

### 확인 사항과 우선순위

### 가장 먼저 고칠 복합 상태: U01

재현 순서는 상세 창을 390×580으로 줄임 → 실행 중인 턴 유지 → 옵션과 자유 입력이 있는 추가 질문 1건 → FIFO 질문 3건 → 6줄 초안 입력이다. 로컬 fixture와 네이티브 입력으로 만들었으며 실제 작업 승인은 하지 않았다.

- `#chat-tab` 가시 바닥은 y=571, 창 바닥은 580이다.
- 입력창은 y=471~571, composer 전체는 y=454~628이다.
- **중단 y=583~611, 전송 y=579~615**로 창 밖에 놓인다. 버튼의 중앙을 누를 수 없다.
- 읽기 영역의 높이가 소진되고 내부 padding 때문에 messages에 28px 상자가 남는다. `맨 아래로`는 y=119~152로 올라와 탭/연결 구역과 겹친다.
- 같은 조합의 720×900 창에서는 전송 버튼이 안에 들어온다. 최소 크기의 조합별 공간 배분 문제다.

[작은 창 재현 캡처](../../artifacts/ui-ux-audit-2026-10-19/fixture/request-queue-multiline-390.png), [넓은 창 비교](../../artifacts/ui-ux-audit-2026-10-19/fixture/request-queue-720.png), [기하와 probe](../../artifacts/ui-ux-audit-2026-10-19/audit-summary.json)를 따른다. 숨김이나 클리핑만 늘려 문제를 감추지 말고 전송/중단과 요청 응답 버튼에 항상 도달할 수 있게 해야 한다.

### 주요 정렬·피드백 근거

**이전 대화:** 460px에서 검색 입력의 왼쪽은 x=33, 옵션 행은 x=57이다. 본문 검색 버튼의 top≈309.9와 체크박스 top≈292.9가 갈린다. 카드 오른쪽 padding 50px은 이제 카드 바깥에 작업 열이 있는 구조에서도 남아 있다. [현재 화면](../../artifacts/ui-ux-audit-2026-10-19/interactive/history.png)을 참고한다.

**캐릭터 카드:** 같은 첫 행의 이미지 top은 373.39/364.59, 이름 top은 476.39/467.59다. 단순 카드 외곽 크기와 `object-fit:contain` 검사로는 이 차이를 발견하지 못한다. [설정 첫 화면](../../artifacts/ui-ux-audit-2026-10-19/interactive/settings-top.png)과 [편집 작업 배치](../../artifacts/ui-ux-audit-2026-10-19/interactive/persona-editor.png)를 참고한다.

**제목 오류:** 공백 3자로 저장하면 서버는 올바르게 거절하고 제목을 보존한다. 그러나 오류는 모달 밖 `#toast`에만 표시되며, 모달이 열린 접근성 트리는 제목/입력/취소/저장만 포함했다. toast 중앙 hit도 false였다. 넓은 창에서는 배경 아래쪽에 문구가 보이므로 ‘항상 시각적으로 완전히 숨겨진다’고 단정하지 않는다. [실패 화면](../../artifacts/ui-ux-audit-2026-10-19/fixture/rename-validation-hidden.png)을 참고한다. 삭제 창은 `#delete-error`를 따로 채우므로 같은 결함으로 묶지 않는다.

**색상:** 현재 중단 조합의 계산값은 paper 약 4.29:1, night 약 1.58:1, mono 약 4.71:1이다. 스킨의 본문/기본 muted 색이 모두 나쁘다는 뜻은 아니다. 특정 위험 버튼의 고정 배경이 원인이다. [night 팝업](../../artifacts/ui-ux-audit-2026-10-19/interactive/simple-popover.png)에서는 흰 스크롤바도 확인했다. 이번 계산만으로 전체 접근성 적합성을 판정하지 않는다.

### 수정·검증 순서

1. **조작 영역 보장:** U01을 먼저 수정한다. 기존 읽기/큐/요청/입력 책임은 유지하고 CSS 높이 배분을 우선 검토한다. 불필요한 JS 레이아웃 헬퍼나 새 전역 상태를 추가하지 않는다.
2. **식별·오류:** U02·U03을 수정한다. 위험 버튼의 스킨별 색상 조합, 모달 안 오류와 aria 연결을 검증한다.
3. **공통 정렬:** U04·U06·U08·U09·U11을 같은 간격/선택/폼 기준으로 맞춘다. 카드 외곽뿐 아니라 내부 이미지·제목의 top/기준선도 검사한다.
4. **정보 구조:** U05·U07·U12·U13·U14·U15를 다듬는다. 자주 쓰는 동작을 쉽게 찾게 하고, 고급 설정과 읽기 전용 상태 설명을 접되 실패/체험 안내·선택값 요약은 남긴다. U10의 배율 범위도 이 단계에서 결정한다.
5. **수용:** 기본/긴 제목/빈 목록/검색 없음/다수 기록, 긴 모델·말투 이름, 이미지 전용 답변/실패, 큐 수정/추가 질문/여러 줄 초안, 모달 실패를 확인한다. 심플의 전체 숨김·초안/팝업 보호와 상세 크기 보존은 기존 계약대로 유지한다.

기존 `ui-layout-smoke`는 공통 경계·컨트롤 높이·기본 입력 확장·overflow를 잘 확인하지만 다음 항목은 빠져 있었다. 테스트 개수를 무작정 늘리기보다 기존 검증에 적은 수의 대표 조합을 추가한다.

- 390×580 + 실행/추가 질문/큐/여러 줄 초안에서 send/stop의 **부모 가시 영역 포함과 중앙 hit**, 요청 답변 버튼까지 스크롤 도달 확인.
- reading-area가 작아질 때 `jump-latest`가 읽기 영역 밖의 탭/연결 줄을 덮지 않는지 확인.
- history 옵션 행의 공통 left/세로 중앙, 캐릭터 같은 행의 이미지/이름 top, 설정 현재 위치의 스타일/상태를 확인.
- 3스킨의 위험 버튼 기본/hover/focus 색 조합, night 중첩 스크롤바를 확인. 전체 스크린샷 비교에만 의존하지 않는다.
- 공백 제목 등 모달 내 오류가 모달 접근성 트리와 필드 설명에 남는지 확인. 소스에 오류 문자열이 있는 것만으로 통과시키지 않는다.
- 글자 배율 검사는 컨트롤이 겹치지 않는지와 실제 적용 대상의 computed font가 바뀌는지를 구분한다. 캡처 파일명만으로 현재 활성 페이지를 판단하지 않는다.

이번 감사에서는 기존 기본 smoke의 통과와 위 결함 재현을 함께 기록했다. 발견한 결함을 수정했다고 표시하지 않으며, 전체 단위/패키지/30초 수명·실제 브라우저 인증·물리 한국어 IME·VoiceOver 수용을 이번에 다시 실행한 것으로 쓰지 않는다.

## UI/UX 최종 실행 계획 (2026-10-20)

아래 미착수 상태는 계획 작성 시점의 기록이다. 현재 구현·검증 결과는 [구현 결과](UI_UX_REFINEMENT_2026-10-20.md#uiux-구현-결과-2026-10-20)를 따른다.

### 현재 상태와 작업 범위

10월 19일 보고의 U01–U15를 현재 HTML/CSS/renderer와 다시 대조했다. 핵심 원인인 고정 높이 누적, 밝은 고정 배경, 전역 토스트, 이중 gutter, 카드 내부 가운데 정렬, 설정의 긴 단일 흐름이 남아 있다. 이 절은 구현 계획이며 UI 수정 완료 보고가 아니다.

테스트의 작업 방해 방지는 먼저 처리했다. 현재 npm GUI 런처와 개발 smoke 진입에는 `--interactive` 가드가 있고, `smoke:changed`는 기본 증거 조회만 한다. 10월 19일 [검증 기록](../../artifacts/non-interrupting-tests-2026-10-19/verification.json)의 lint/check/단위 253개 통과·GUI 실행 0건은 당시 근거다. 이 계획 작성에서 해당 검사를 새로 실행했다고 표시하지 않는다. 캐시가 없거나 만료되면 GUI를 실행하지 않고 미검증을 남긴다.

my_budy의 목표인 작은 버디·말투·이미지·가벼운 대화를 유지한다. 새로운 라우터·설정 프레임워크·UI 라이브러리·DB를 도입하지 않는다. 기존 Electron/main/preload/renderer 경계를 유지하고 표시 문제는 CSS/HTML과 기존 이벤트 처리에서 먼저 해결한다. 단순 계산·상태 갱신은 해당 함수 안에 작성하고 범용 헬퍼나 컴포넌트 파일로 불필요하게 분리하지 않는다.

### UI01: 남은 공간을 나눠 입력 동작을 보장

원인은 개별 영역의 고정 높이 합계다. 창 최소 크기를 크게 올리거나 버튼을 작게 줄이는 것으로 대체하지 않는다. `requests`와 `queue-bar`를 하나의 보조 스크롤 영역으로 묶는 안을 우선 적용한다. 각 ID와 이벤트 소유권은 유지하고 상세에서 보조 영역의 중복 스크롤을 줄인다. composer는 그 밖에 두어 전송·중단이 항상 남게 한다. 읽기 영역은 남은 공간을 사용하되 높이가 부족할 때 jump를 연결/탭 영역에 그리지 않는다.

높이 정책은 CSS의 flex/grid·min-height·max-height로 먼저 해결한다. 매 프레임 모든 DOM 높이를 재는 JS 루프나 임의의 timeout은 추가하지 않는다. 연결 도움말·기록 경고가 길어도 자체 경계 안에서 읽고 버튼에 도달할 수 있어야 한다. 요청/큐를 접어 숨기기만 해 승인·취소를 놓치게 만들지 않는다.

`renderDraftAttachments()`는 심플 contentHeight에 `#queue-bar`와 `#requests` 높이를 각각 더한다. 새 wrapper 도입 시 이 합산을 같이 조정해 이중 계산·빈 여백·크기 진동을 방지한다. compact 전용 overflow도 함께 대조한다. 새 답변 준비/보호 상태와 높이 계산을 섞어 일반 publish마다 30초를 연장하지 않는다.

예외 수용은 6줄 초안·첨부 8개·긴 요청/오류·큐 수정 배너·100/110/120%·심플 전환·짧은 화면 작업 영역을 포함한다. 전송·중단은 부모 clip 영역까지 포함해 경계를 검사하고 실제 중앙 hit를 확인한다. 요청 답변 버튼은 보조 영역 스크롤로 도달할 수 있어야 한다. 초안·첨부·현재 실행·FIFO 순서는 바꾸지 않는다.

### UI02: 위험 색상과 모달 내부 실패 처리

**U02:** 현재 스킨은 `skins.cjs`에서 색상 키 10개를 정확히 검증한다. UI 정리를 위해 JSON에 임의의 `dangerBackground` 키를 넣어 스킨 포맷을 깨지 않는다. 기존 팔레트의 danger/surface/wash를 사용해 CSS에서 위험 동작 조합을 정한다. 고정 밝은 배경을 제거하고 normal/hover/focus/pressed/disabled를 함께 정리한다. 일반 크기 글자 대비 4.5:1 이상을 구현 목표로 삼되, 단순 팔레트 계산과 실제 Chromium computed 색상 검증을 구분한다. 주 버튼/일반 보조 버튼까지 모두 위험색으로 바꾸지 않는다.

**U03:** 제목 폼 안에 지속 오류 영역을 두고 입력과 `aria-describedby`/`aria-invalid`를 연결한다. `act()`의 catch가 정리한 오류 문구를 결과에도 돌려주도록 최소 확장하고 기존 호출부의 `ok` 계약을 유지한다. 제목 이벤트 안에서 검증/오류/버튼 복구를 처리한다. 전역 오류 라우터나 별도 폼 라이브러리는 만들지 않는다.

공백/빈 값·60자 초과·저장 실패·동일 대화가 사라짐·중복 제출을 확인한다. 실패 시 모달·입력·기존 제목을 유지하고 저장 버튼을 복구한다. 다시 열 때 이전 오류를 초기화하며 취소 후 원래 동작 버튼으로 포커스를 돌린다. 모달 밖 토스트만으로 완료 처리하지 않는다. 이미 내부 오류가 있는 삭제/팩 미리보기와, 별도 확인이 필요한 팩 보관/MD 충돌을 구분하고 전역 catch 변경의 영향을 검토한다.

### UI03: 공통 간격과 선택 상태

- **U04:** `.history-options`의 추가 gutter를 없애고 `.text-button` 전역 margin-top이 옵션 행에 적용되지 않게 한다. 검색 버튼/체크박스 label을 하나의 행 기준으로 배치하고 좁아지면 논리적인 줄 단위로 감싼다. label의 클릭 영역은 체크박스를 포함한다.
- **U06:** 캐릭터 카드 내부를 이미지·이름·설명 행으로 명시적으로 정렬한다. 같은 행의 이미지와 이름 시작점을 맞추며 긴 이름은 읽을 수 있게 줄바꿈한다. 설명을 임의로 잘라 정렬을 맞추지 않는다. 비율과 선택 체크 공간도 유지한다.
- **U08:** 설정 아이콘의 `aria-pressed=true`에 대응하는 지속 스타일을 추가한다. 캐릭터는 기존 button 구조에 선택 상태를 명시하고 main의 확정 상태를 따른다. 저장/선택 실패 시 화면만 선택됐다고 남기지 않는다. 검증되지 않은 키보드 규칙을 요구하는 role을 새로 붙이지 않는다.
- **U09:** 기본 light/night dark의 native `color-scheme`과 popup/textarea/요청/큐/편집 영역의 스크롤바 정책을 일관되게 적용한다. native select/time/checkbox까지 포함한다. Chromium 표시와 macOS 파일 선택기 전체 테마 수용은 별도다.
- **U11:** select를 모두 46%로 고정하지 않고 긴 값이 있는 행은 작은 창에서 위아래 배치한다. 단축키·작업 폴더·CLI 경로는 현재 값 전체를 확인할 수 있는 설명을 제공한다. hover title만으로 키보드 사용자의 확인을 대신하지 않는다.

여백은 기존 gutter와 4/8/12/16/24/32px 계열을 사용하고 특수 상태마다 다른 보정값을 늘리지 않는다. 기본 input/select/button 높이는 기존 40px, 미니/아이콘 버튼은 현재 용도에 맞는 범위를 유지한다. focus outline이 clip에 잘리는지도 확인한다. 동일 행의 정렬과 긴 내용에서 필요한 줄바꿈을 구분한다.

### UI04: 버디에 맞는 목록·설정 흐름

**U05 — 대화 목록:** 대화 열기와 즐겨찾기는 바로 사용할 수 있게 하고 제목 변경·Markdown 내보내기·삭제는 이름 있는 추가 작업 팝업으로 모으는 안을 기본으로 한다. 기존 popover 패턴을 활용하고 카드 안에 button을 중첩하지 않는다. 오른쪽 50px 예약은 실제 동작 배치와 맞춰 제거/축소한다. 모든 행을 특정 고정 높이로 강제하기보다 제목·미리보기·metadata에 맞춘 자연 높이를 사용한다.

메뉴 대상은 conversation ID로 고정하고 목록 재정렬·본문 검색·100개 더 보기·삭제 대기 상태에서 다른 대화에 작업하지 않게 한다. 탭 전환·대상 제거·Esc·밖 클릭으로 닫고 trigger 포커스를 복원한다. 삭제 확인과 실행 중 잠금 정책은 그대로 둔다. 내보내기 이미지 포함 옵션도 보존한다. 기존 smoke의 ‘행 안 버튼 5개’/포커스 복원 검사는 각 동작에 도달해 올바른 대상에 적용되는지 확인하도록 변경한다. 검사 삭제로 새 구조를 통과시키지 않는다.

**U07 — 설정:** 상단에 현재 버디의 간단한 표시와 설정 섹션 바로가기를 두고, 자주 쓰는 대화/화면 옵션을 처음 접근하기 쉬운 위치로 옮긴다. 캐릭터 카드와 가져오기는 펼쳐 선택하는 영역으로 유지한다. 알림·연결·보관·팩/말투 편집의 묶음을 명확하게 하되 새 페이지/라우터를 추가하지 않는다. 같은 input을 여러 섹션에 복제하지 않고 기존 노드를 이동/그룹화해 이벤트 중복·중복 ID·초안 소실을 피한다. 연결/복구 실패 안내를 접힌 곳에만 숨기지 않는다.

**U12 — MD/팩 작업:** MD 저장을 주 동작, 다시 읽기·폴더 열기를 보조 동작, 복원/보관을 관리 동작으로 표현한다. 기본/사용자/보관 모드에서 가능한 동작과 불가 사유를 가까이 표시한다. 비활성 기능을 무조건 감춰 기능 자체를 찾지 못하게 만들지 않는다. 외부 수정 hash 비교·저장 중 입력 보존·기본 복원 백업은 변경하지 않는다. 긴 MD 충돌 문구는 작은 창에서 세로 배치를 허용한다.

**U13 — 보관/사용량:** 확인·중단·선택 보관·복원을 명시적인 action row로 분리한다. 진행/중단 요청/부분 성공·실패/복구본 보존을 상태 영역에서 구분한다. 결과는 캐시 합계/참조/보관 가능 수와 계정 한도별 이름 있는 행으로 정리한다. secondary 미제공과 조회 실패를 같은 이름 없는 `확인 불가`로 쓰지 않는다. 관측된 null/0·시각 없음·만료된 값·일부 결과를 구분하고 토큰으로 비용/남은 질문 수를 추정하지 않는다. 자동 삭제나 원격 조회를 추가하지 않는다.

### UI05: 글자와 심플 대화의 읽기 흐름

**U10 — 배율 범위 결정:** 기존 100/110/120% 값을 유지하면서 메시지 본문·Markdown 제목/목록/인용/코드/표·질문 입력을 대화 글자 배율의 대상으로 삼는 안을 기본으로 한다. 계정/도구 metadata와 앱 전체 설정 글자까지 확대하는 전역 zoom은 사용하지 않는다. 설정 설명에 범위를 명시한다. 코드/표는 상대 크기를 유지하면서 내부 가로 스크롤을 허용한다.

현재 textarea 높이는 입력/compact 전환 때 계산하므로 배율 변경 시에도 기존 자리에서 높이를 한 번 다시 계산해야 한다. 커서·선택·IME·초안은 유지하고 일반 상태 갱신 때마다 재측정하지 않는다. 커진 입력 영역이 UI01의 남은 공간 규칙을 다시 깨지 않게 한다.

**U14 — 심플 팝업:** `+`의 이미지/파일/붙여넣기는 첫 화면에 남기고 작업 목적·스킬은 기본 접힌 상세 선택으로 둔다. 기본값이 아닌 선택 요약은 composer에 유지한다. 목적/스킬 상태를 초기화해 팝업 높이를 줄이지 않는다. 팝업 열림 자체의 숨김 보호와 Esc→팝업 닫기→창 닫기 순서를 유지하고 접기 전환 후 위치/크기를 다시 맞춘다. 파일 선택 시작 전에 팝업을 닫는 기존 경계도 보존한다.

**U15 — 질문 설명:** 기존 select를 유지하고 선택지 설명을 텍스트로 표시한다. 선택된 옵션과 직접 입력의 관계를 안내하고 선택하지 않은 상태에서도 다른 옵션의 의미를 확인할 수 있게 한다. 설명은 `textContent`와 질문별 고유 ID/aria 연결을 사용하며 HTML로 실행하지 않는다. 설명 없음/긴 설명/중복 label/선택 변경/직접 입력·질문 순서/의미 변경을 확인한다. 기존 request ID/question ID별 입력 노드와 이전 초안 보존 계약을 유지한다. 설명 추가로 높이가 늘어난 상태는 UI01 조합에서 다시 수용한다.

### 리뷰에서 수정한 예외

- 요청/큐만 묶은 첫 수정에서도 첨부 8개+긴 요약+수정 배너, 연결/기록 경고가 함께 표시되면 입력 자식이 composer 경계를 넘었다. 두 공통 스크롤 영역으로 수정하고 부모 clip 경계와 중앙 hit를 다시 검사했다. 긴 안내는 스크롤해서 읽는 절충이 있다.
- 새 메뉴가 pending deletion의 재시도를 막거나 비활성 rename에 포커스를 주던 문제를 수정했다. 해당 대상의 삭제만 다시 열 수 있고 메뉴 진입 시 첫 활성 버튼에 포커스한다.
- 팝업 접기 전환 뒤 크기 증가, 창 크기 변경/이력 스크롤로 메뉴가 어긋나는 경로를 보완했다. 반복 렌더 안에 들어간 이벤트 등록도 최종 검토에서 찾아 top-level 1회 등록으로 옮겼다.
- 닫힌 MD 모달의 0×0 버튼까지 정렬 검사에 섞이던 선택자를 실제 설정 행으로 바로잡고, 동작을 찾는 메뉴 검사·부모 clip·대상 ID·재시도 포커스·초안/선택 보존을 확인하도록 기존 검사를 강화했다. 행당 버튼 5개라는 옛 구조 조건을 삭제만 해 통과시키지 않았다.
- danger의 `color(srgb ...)` 직렬화 값을 0–255 RGB로 오해하지 않도록 실제 canvas 픽셀 색으로 대비를 계산했다. 이 결과를 모든 UI 색상의 접근성 통과로 확대하지 않는다.
