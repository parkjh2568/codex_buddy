# 대화·설정 UI와 심플 말풍선 작업계획

2026-10-13. 대상은 `my_budy`의 옹기봇(OnggiBot), 현재 소스 alpha20 / staging build36이다. 이 문서는 실제 코드 검토에 따른 **설계·작업계획**이다. 아래 UI 변경, 30초 숨김, 모서리 드래그를 구현하거나 실기 검증한 결과가 아니다.

기존 [최종 후속 결과](FINAL_IMPLEMENTATION_RESULT_2026-10-13.md), [구조](../ARCHITECTURE.md), [현재 대화 UI](../UI_UX_REFINEMENT.md), [첨부·FIFO 계약](../ATTACHMENTS_AND_QUEUE_2026-10-10.md)을 기준으로 한다. 단순 이벤트·표시 계산은 기존 함수 안에서 처리하고, 새 UI 프레임워크·일반 상태 관리 계층·별도 초안 저장소를 추가하지 않는다.

## 대화창의 배치와 여백

입력창의 기본 형태는 다음과 같다. 이 그림은 배치 제안이며 완성 화면이 아니다.

```text
답변과 이미지가 있는 읽기 영역

┌─────────────────────────────────────┐
│ [선택한 이미지/파일] [목적: 검토]    │  선택한 경우만 표시
│ 메시지를 입력하세요…                │
│                                     │
│ [말투 ▾] [+]       [모델 ▾] [중단] ↑ │
└─────────────────────────────────────┘
```

- 말투와 `+`는 왼쪽 한 묶음, 모델은 남는 폭 안에서 축약, 중단·전송은 고정 폭이다. `+` 버튼은 말투 바로 옆에 둔다. 작은 창에서는 모델 세부 추론 텍스트부터 축약하고 전송 버튼을 밀어내지 않는다.
- `+` 안에는 첨부 동작을 먼저 두고, 구분선 아래에 목적·스킬 선택과 새로고침·한도 안내를 둔다. 모델 설정은 기존 모델 팝오버를 유지한다. 두 팝오버를 동시에 열지 않는다.
- 첨부 미리보기·삭제, 기본값이 아닌 목적/선택 스킬 요약은 입력창 안에 남긴다. 기본 대화 목적은 별도 줄을 차지하지 않는다. 준비 실패는 메뉴를 닫아도 확인할 수 있다.
- 간격은 4/8/12/16/24/32px 계열로 정리한다. 상세 창 좌우 여백은 기본 24px, 심플은 16px에서 시작해 실제 작은 화면 검증으로 조정한다. 서로 관계있는 요소는 가깝게, 답변과 입력·설정 섹션 사이에는 분명한 간격을 둔다.
- 버튼은 상세 36–40px, 심플 최소 32px의 클릭 영역을 목표로 한다. 작은 그림 크기와 클릭 영역 크기를 구분한다. 같은 동작 줄은 수직 중앙과 기준 높이를 맞춘다.
- 읽기 영역에 중첩 테두리·상태 설명을 반복하지 않는다. 넓힌 창에서는 텍스트가 창 전체 폭으로 지나치게 늘어나지 않도록 최대 읽기 폭과 가운데 배치를 검토한다. 이미지·코드의 가로 스크롤은 각 콘텐츠 영역 안에서 처리한다.
- 헤더·탭·정상 연결 상태는 가볍게 유지한다. 복구 필요·저장 실패·승인 요청은 접힌 메뉴에만 가두지 않는다. 설정 변경은 다음 질문부터 반영한다는 기존 계약을 유지한다.
- 기존 팔레트·캐릭터 개성을 유지한다. 새 이미지 에셋이나 폰트·아이콘 라이브러리는 필요하지 않다. 스타일 삭제는 DOM/선택자 사용처와 3개 스킨 확인 뒤 진행한다.

### `+` 팝오버의 입력·접근성

기존 컨트롤과 ID를 옮겨 사용하며 숨은 중복 select·중복 이벤트를 만들지 않는다. 폼 요소가 들어가므로 메뉴 항목 전용 ARIA를 무리하게 적용하지 않고, 이름을 가진 팝오버와 올바른 label을 사용한다.

열기/닫기 상태, 키보드 이동, 밖 클릭, Escape, 트리거로의 포커스 복귀를 검사한다. Escape는 모달 → 열린 팝오버 → 창 숨김 순서로 처리한다. 메뉴의 일반 동작 버튼은 `type=button`이며 Enter로 대화가 우발 전송되지 않아야 한다. 파일 선택 직전 팝오버를 닫고, 취소·완료 후 적절한 입력 위치로 돌아간다.

`src/preload.cjs`의 trusted paste/drop/click 검증과 `#paste-image` 선택자를 보존한다. 메뉴를 옮겨도 실제 클릭·붙여넣기·드롭만 허용하며, 파일 경로를 임의 IPC로 받는 새 우회 경로를 만들지 않는다. 첨부 8개·합계 32MiB, 사본 보관, 작업 폴더·대화 소유 검사, FIFO 접수 snapshot을 유지한다.

## 심플 모드 상태와 30초 수명

| 상태 | 화면 | 숨김 정책 |
|---|---|---|
| 최초/새 대화 | 작은 이름·확장·X, 텍스트 입력과 `+`; 빈 답변 카드나 큰 환영 영역은 없음 | 자동 숨김 타이머 없음 |
| 입력·첨부 준비 | 입력창, 선택 첨부, 필요한 준비 상태 | 입력 보호; X는 즉시 숨기되 초안 유지 |
| 실행/대기 | 현재 실행 중인 답변이 있으면 그 답변, 작은 상태·대기 개수, 아래 입력창 | 자동 숨김 보류; 새 질문은 기존 FIFO로 접수 |
| 완료 | 해당 답변 텍스트·이미지, 아래 입력창 | 저장·이미지 처리·화면 전달 확인 뒤 30초 |
| 실패/중단/저장 실패 | 실패·부분 답변·복구/확장 동작과 입력창 | 성공 완료의 자동 숨김을 적용하지 않음 |
| 승인/추가 질문 | 기존 상세 승인 UI로 전환하거나 기존 알림 정책대로 안내 | 승인 화면을 타이머로 숨기지 않음 |
| 숨김 | 버디만 남음 | 다시 열면 기존 답변·초안 복구; 실행·큐·대화 삭제 없음 |

답변 선택은 현재 실행 턴의 assistant ID를 우선한다. 필요하면 main이 선택한 표시 대상 ID 하나를 panel 상태에 추가하고 renderer가 큐 순서를 다시 추측하지 않도록 한다. 대기만 존재하면 마지막 전달 답변과 대기 상태를 유지하고, 다음 queued assistant를 완료 답변처럼 선택하지 않는다. 새 대화·과거 대화 열기에서는 해당 대화의 마지막 유효 답변을 선택한다. 사용자 질문 카드·다른 과거 답변·전체 도구 로그·반복 메타데이터는 심플 화면에서 표시하지 않는다. 실제 응답/체험 응답과 오류 구분은 간결하게라도 유지한다.

최초 말풍선은 입력에 필요한 높이부터 시작한다. 답변 길이·이미지·입력 줄 수에 맞춰 높이를 늘리되 현재 미니 크기 설정과 화면 작업 영역을 최대 범위로 사용한다. 큰 답변은 답변 영역만 스크롤하고 입력창은 항상 아래에 보인다. 스트리밍 토큰마다 창 좌표를 바꾸지 않고 높이 변경을 묶어 화면 흔들림을 막는다. 위/아래 배치와 꼬리는 실제 크기로 다시 계산한다.

### 타이머 기준

1. **저장 성공 + 응답 이미지의 원본 처리 완료 + 실제 보이는 심플 답변의 표시 확인**을 모두 만족한 때를 전달 완료로 정의한다. 현재 화면 안의 미리보기들이 표시 또는 실패 안내에 도달했는지 확인하며 첫 이미지 하나만 보고 판단하지 않는다. 화면 밖의 lazy 이미지까지 모두 decode할 때까지 무한히 기다리지는 않는다. 이미지 미리보기 실패는 실패 안내가 표시된 것으로 완료 판정할 수 있으나, 전체 저장 실패는 성공 전달로 판정하지 않는다.
2. 기존 시간 측정용 `response-rendered`와 읽음용 `notice-read`는 목적이 다르다. 이미 상세 모드에서 ACK된 답변을 심플로 다시 열어도 표시 수명은 필요하다. 기존 ACK 재전송이나 `renderedAt` 초기화로 해결하지 않고 심플 표시 세대를 따로 확인한다.
3. main이 타이머와 deadline을 소유한다. renderer는 현재 답변·표시 세대·표시/이미지 준비와 입력 보호 상태만 제한된 IPC로 전달한다. main은 panel/main frame, 활성 대화·답변·세대·가시성·저장 결과를 검사한다. 숨겨진 창이나 이전 RAF는 새 타이머를 시작할 수 없다.
4. 매 `onState`, 모델 조회, 버디 움직임으로 30초를 다시 시작하지 않는다. 새 답변의 전달 완료나 명시적 다시 열기만 새 표시 수명을 만든다. 임시 표시 상태는 대화 JSON에 저장하지 않는다.
5. **제안하는 보호 예외:** 비어 있지 않은 초안·IME 조합·열린 팝오버/파일 선택·큐 편집·실행/대기·승인/중요 오류가 있으면 자동 숨김을 미룬다. 일반 포커스나 마우스 이동만으로 영원히 연장하지 않는다. 보호 상태 해제 후에는 30초의 읽기 시간을 다시 제공한다. 이 예외는 사용자 확인 대상이며 확정한 동작으로 표시하지 않는다.
6. X는 보호 상태와 관계없이 즉시 숨기고 팝오버·자동 숨김 예약을 정리한다. 저장/이미지 작업·현재 작업·큐는 중단하지 않는다. 완료 후 몰래 다시 열지 않고 기존 버디/알림 정책을 따른다.
7. 전체 모드·설정/기록 전환, 대화 변경, 창 종료/renderer 복구, 잠금·절전에서 이전 예약을 무효화한다. 복귀 시 과거 타이머가 다른 대화를 숨기지 않도록 한다. 읽음은 실제 표시로만 판정한다.

이미지뿐인 답변은 빈 텍스트 상자 없이 이미지를 표시한다. 여러 이미지의 일부 실패·지연, 파일뿐인 질문, 긴 코드·표·10만 자 문자열에서도 입력창이 밀려나지 않아야 한다. 이미지 lazy preview·참조 소유 검사·Markdown 정제·긴 기술 문자열 표시 최적화를 유지한다.

## 상세 창 모서리 드래그

현재 단일 panel 창은 상세와 투명 말풍선을 함께 담당한다. **우선안은 이 창을 유지하고 상세 모드에만 작은 모서리 드래그 영역을 두어 main에서 제한된 `setBounds`를 수행하는 방식**이다. 투명 창의 기본 resize를 전제로 하지 않는다. UX01에서 격리 프로필의 작은 시제품으로 투명·포인터 캡처·프로그램 크기 변경의 실현 가능성을 먼저 확인하고, UX06에서 제품 코드와 4모서리 물리 조작을 검증한다. 시제품은 사용자 프로필이나 배포 앱을 교체하지 않는다.

- 4개 모서리에 약 8–12px의 겹치지 않는 영역과 방향 커서를 둔다. 상단 창 이동 영역·X·스크롤바·팝오버와 충돌하지 않게 `no-drag`와 hit 영역을 조정한다. 버튼이 있는 모서리를 과도하게 덮지 않는다.
- 시작 시 원래 bounds·모서리·화면 좌표·표시 세대를 고정하고 반대 모서리를 기준으로 계산한다. 유한 좌표·panel의 main frame·상세 모드·활성 드래그를 검증한다. pet/안내 창에서 크기 조절할 수 없다.
- pointer capture, pointercancel, lost capture, 숨김/모드 변경, 잠금/절전, renderer 종료에서 드래그를 정리한다. 모서리 밖으로 이동해도 계속 조절되고 놓으면 반드시 끝나야 한다. 오래된 이동 IPC는 다음 드래그에 적용하지 않는다.
- 이동 요청은 프레임 단위로 묶고 이전 요청이 밀리면 최신 좌표를 사용한다. 움직일 때마다 JSON 저장·대화 재렌더·모델 조회를 하지 않는다. 기하 변경 IPC는 저장 대기/보관 작업 중에도 안전하게 처리하되 데이터 변경 권한을 확장하지 않는다.
- 상세 최소 크기는 기존 작은 화면 검사의 390×580을 시작 기준으로 삼되 작업 영역이 더 작으면 그 안에 맞춘다. 최대 크기는 현재 디스플레이 작업 영역이며 좌표·크기를 논리 픽셀로 취급한다. 혼합 DPI와 디스플레이 제거는 별도 실기 수용이다.
- 마지막 상세 크기/위치는 런타임에서 별도 보존한다. 심플 확장, 설정/기록 전환과 재열기에서 460×740으로 되돌리지 않는다. 미니의 버디 앵커 배치가 상세 bounds를 덮어쓰지 않는다. 앱 재시작까지의 영구 저장은 별도 요구가 없으므로 첫 구현에 추가하지 않는다.
- 창의 네 모서리와 미니→상세→설정→기록→재열기, 화면 끝까지 늘리기·줄이기·취소를 검사한다. 확대해도 입력창은 하단에, 설정 콘텐츠는 스크롤 영역 안에 유지한다.

대안은 불투명 상세 창을 따로 두고 OS의 기본 크기 조절을 사용하는 것이다. 현재는 별도 창의 초안·팝오버·ACK·첨부·종료 동기화가 추가되므로 먼저 도입하지 않는다. 우선안의 물리 조작·성능·안정성이 수용되지 않으면 실패 근거를 기록하고 대안의 범위를 다시 판단한다.

섹션 순서는 **버디 이름·캐릭터 → 대화/화면 → 움직임 → 연결/알림 → 고급 관리**를 기준으로 검토한다. 캐릭터 팩 관리·말투 MD·보관/복구·상세 진단은 접어서 밀도를 줄인다. 연결 장애의 해결 동작과 진행 중인 저장/복구 상태는 접힌 섹션 밖에서도 확인 가능해야 한다.

기존 `ui-layout`, `model-ui`, `buddy-features`, `attachments`, `stability`, `timing`, `buddy-expansion`, `floating` 검사에 새 계약을 반영한다. 2개 카드·고정 높이 가정만 바꾸고 초안/첨부/FIFO/ACK 보호 검사를 제거하지 않는다. 저장 실패·오래된 표시 세대·이전 resize 세션·권한 없는 창 요청은 의미 있는 실패 주입으로 검사한다. 단순 CSS 선언과 같은 값을 확인하는 단위 검사는 늘리지 않는다.

구현 후 `npm run lint`, `npm test`, `npm run check`와 영향 경로 Electron 검사를 실행한다. 최종 공유 후보를 만들 때 전체 integration·패키지 소스 대조를 수행한다. 자동 좌표/DOM·캡처 검사와 실제 macOS 모서리 드래그·IME·파일 대화상자·30초 기다리기 검증은 구분해 기록한다. Windows/혼합 DPI가 확인되지 않으면 미검증으로 남긴다.

최종 결과 보고에는 변경 전후 대화/설정/심플/`+` 화면, 전달 완료 기준과 실제 숨김 경과, 4모서리 조작, 초안/첨부/FIFO 유지, 검증한 소스·패키지 버전, 실패·미확인 사항을 담는다. 확인하지 않은 외관이나 동작을 완료로 쓰지 않는다.

## 이번 계획의 확인 범위

현재 UI/main/preload, 구조·UI·첨부 문서와 영향 검사 코드를 읽고, 기존 완료 소스 장부의 190개 파일이 계획 작성 전 소스와 일치함을 확인했다. 이번에는 계획·작업 목록·현재 UI 문서의 후속 링크만 작성한다. 실행 코드·배포 앱·사용자 프로필은 변경하지 않는다. 기존 단위 147개·Electron 14종은 alpha20 당시 결과이며, 새 UI 요구사항이 통과한 검사 수가 아니다.
