# my_budy 정리·최적화 결과

2026-10-13. [코드 분석](FULL_CODE_REVIEW_2026-10-13.md)의 FULL01–FULL09를 기준으로 입력 검증과 비동기 수명, 실패 시 파일 보존, 모달과 추가 질문 접근성을 보완했다. 중복 fixture 한 개를 통합하고 이미지 decode의 불필요한 후속 처리를 줄였다. 기존 작업 트리의 변경을 보존했으며 새 범용 헬퍼나 상태 프레임워크를 추가하지 않았다.

## 적용 내용

| 순서 | 항목 | 변경과 유지한 계약 |
|---|---|---|
| 1 | FULL01 입력 ID | 팩·말투·스킨 ID는 정규식 전에 문자열인지 확인한다. 팩 및 사용자 말투 복구 데이터에도 같은 자료형 경계를 적용했다. 스킨 색상도 문자열만 허용한다. 유효한 ID와 팩 schema 1/2는 유지한다 |
| 2 | FULL02 이미지 캐시 | decode 후 사용량 확인부터 원본·미리보기 저장까지 같은 인스턴스의 순서를 보장한다. 동일 해시는 한 번만 계산하고 새 파일의 합계 공간을 확인한 뒤 쓴다. 쓰기 실패에서도 다음 저장을 진행하고 임시 파일을 정리한다. 기존 이미지 재사용은 한도를 넘긴 캐시에서도 허용한다 |
| 3 | FULL03 사용량 조회 | 진행 조회에 process/accountRevision을 보관한다. 같은 소유 범위만 합치고 계정 변경·재연결에서 새 RPC를 시작한다. 오래된 응답과 finally가 새 조회를 덮거나 지우지 않는다. notification으로 더 최근에 갱신한 사용량은 보존한다 |
| 4 | FULL04 팩 export | 실패 시 전체 폴더를 재귀 제거하지 않는다. 직접 생성한 파일의 dev/ino·내용과 경로를 확인해 정리하고, 직접 만든 빈 폴더만 제거한다. 추가·수정·교체·부분 쓰기 파일은 보존하고 경로를 안내한다. 정상 출력은 loadPack으로 재검증한다 |
| 5 | FULL05 모달 Escape | 이미 처리된 키 이벤트를 존중하고 열린 dialog에서 패널 숨김을 호출하지 않는다. 삭제·팩 적용 중에는 keydown 단계에서 기본 닫힘도 막는다. 일반 모달 취소와 모델 popover 닫기는 유지한다 |
| 6 | FULL06 추가 질문 label | 내부 순번으로 DOM ID를 만들고 label.control과 select의 aria-labelledby를 질문에 연결한다. 외부 질문 ID를 HTML에 삽입하지 않는다 |
| 7 | FULL07 실제 CLI 검사 | turn/start 실패·완료·시간 초과에서 타이머와 listener를 정리한다. 대기 결과는 실패 객체로 전달해 await 전 rejection을 피한다. 검사용 thread의 소유 확인 후에만 실패 정리를 시도하고, 정리 실패와 ID를 기록한다. 실행 시작/실패를 기록해 이전 passed 결과와 구분한다 |
| 8 | FULL08 검사 결과 | native floating의 async callback 안에서 예외를 처리한다. 필수 캡처 후 성공 결과를 기록하고 실패 시 오류 종료한다. 모델 검사의 캡처와 확장 검사의 디버거·워커·창 정리도 passed 기록보다 먼저 수행한다 |
| 9 | FULL09 현재 문서 | 현재 단위 검사 수와 기본 팩 4개, 작업 중 export 허용, 이름의 말투 지시 반영, 첫 응답 항목 정의와 제한 있는 본문 검색을 구현에 맞췄다. 날짜별 과거 측정 수치는 보존한다 |

추가로 `persona-codex.cjs`의 말투 기록 한 필드를 `delete-codex.cjs`에 포함해 삭제·말투 검사에서 공통 fixture를 사용한다. 두 원본은 그 필드 외에 바이트가 같다는 것을 확인했으며 별도 프로토콜 추상화는 추가하지 않았다. 제거한 파일은 변경 전 사본에 보관했다.

`asset-validator.cjs`는 이미지마다 decode 크기와 frameCount를 합산하고 픽셀 한도를 넘은 시점에 중단한다. 이후 이미지 decode와 캔버스 생성을 피하며 이미 연 bitmap과 검증 창은 finally에서 해제한다. 시간·메모리 개선률을 측정한 변경은 아니다.

## 검증

단위 검사는 134개 통과했고 실패·건너뜀은 0개다. ESLint·CSS 검사, JavaScript 구문·기본 팩 4개 검사와 렌더러 빌드도 통과했다. 회귀 검사는 다음 실패 경계를 포함한다.

- 누락/null/boolean/배열 ID, 잘못된 복구 ID와 색상 자료형, 정상 팩·말투 초기화.
- 계정·process·disconnect 변경, 이전 성공/오류와 새 조회의 완료 순서, 동일 소유 조회 병합과 notification 보존.
- 거의 찬 sparse 캐시의 이미지 동시 저장, 같은 해시 재사용, 원본/미리보기 쓰기 실패와 다음 저장 재개. 캐시 계약 검사에는 모의 decode를 사용한다.
- 팩 export의 외부 추가·수정·교체·부분 쓰기 보존, 새 폴더의 정상 실패 정리, 정상 출력의 revision 일치.
- 실제 CLI 검사 코드의 모의 RPC 및 cleanup 실패, 타이머/listener 해제와 failed 기록.
- native floating 검사 코드의 모의 screenshot 실패, passed 미기록과 exit 1.
- 합계 픽셀 예산 초과 시 후속 decode 중단과 bitmap/창 해제. 이 단위 검사는 실제 이미지 decoder 검사를 대신하지 않는다.

격리 Electron 통합 검사 14종은 모두 통과했다. 마지막 캐시 조건 수정 뒤 이미지·첨부·확장 3종을 재확인했고, 모달 keydown 보강 뒤 확장·삭제·모델·말투·팩 수명 5종도 모두 통과했다. 실제 삭제 RPC를 보류한 상태의 Escape로 삭제 확인창과 패널 보존을 확인했다. 실제 모델 호출과 사용자 대화·원본 첨부 변경은 없다. 실제 Electron 이미지 decode는 assets 검사에서 확인한다. 화면 읽기 프로그램의 실제 사용이나 물리 키보드·IME 수용 완료를 의미하지 않는다.

처음 제한된 실행 환경에서는 Electron이 로그 없이 SIGABRT로 종료했다. 데스크톱 실행 경로에서 격리 프로필로 검사했다. 확장 검사의 첫 데스크톱 실행에서는 첨부 제거 대기가 시간 초과됐고, 잠금 상태에서 보낸 CDP drop 이벤트의 수신을 확인한 뒤 잠금을 해제하도록 검사 순서를 보강했다. 모달 검사도 실제 cancel 이벤트를 확인하며, 사용자 입력으로 열린 모달과 프로그램으로만 열린 모달의 조건을 구분한다. 실패 실행의 로그와 프로필은 근거로 보존한다.

검증 로그와 변경 전 사본은 [optimization-2026-10-13](../../artifacts/optimization-2026-10-13)에 있다. 최종 검사별 경로와 파일 해시는 [validation.json](../../artifacts/optimization-2026-10-13/validation.json)에 기록한다.

## 범위와 후속

이번 결과는 확인된 수정과 개발 번들에 대한 결과다. 기존 `dist`의 설치·롤백 앱은 이전 소스의 배포본으로 보존했으며 이번 코드의 새 패키지를 생성한 것은 아니다. OS 알림 배너·실제 클릭, Windows/혼합 DPI, 물리 IME·드롭·절전, 새 계정 로그인 및 배터리 검증은 기존 [TASKS](../../TASKS.md)의 수용 조건을 유지한다.

큰 main/renderer의 책임 이동, 로컬 기록 읽기의 워커 이전, 모델 탐색 구조 변경은 실제 경합 계약과 계측을 근거로 진행할 후속 판단이다. 함수 길이 또는 작은 중복만으로 모듈을 늘리지 않는다. 기존 저장 migration·복구·팩 독립 MD·배포 자산과 라이선스 고지는 유지한다.

이 결과 작성 당시 전체 감사의 문서 검토 28개가 남아 있었다. 이후 원문 대조를 마치고 저장 참조 자료형과 검사 화면 준비 경계도 보완했다. 최종 135개 단위·전체 범위와 추가 회귀는 [전체 감사](FULL_CODE_REVIEW_2026-10-13.md)를 따른다. 위 134개와 9개 항목의 결과는 해당 단계 기록이다. 이전 정리 과정의 합성 PNG 두 원본 미복구 제한은 [정리 결과](LEGACY_FILE_CLEANUP_RESULT_2026-10-12.md)에 보존한다.
