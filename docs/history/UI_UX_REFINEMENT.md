# UI·UX 정돈 — alpha.9 build16

기준: 2026-10-06. 사용자가 요청한 현대미술의 여백, 반듯한 정렬, 편안한 대화 경험을 현재 Electron UI에 적용했다.

## 확인한 문제와 방향

기존 화면은 답변 12px·보조 정보 8–10px로 글씨가 작았고, 영역별 여백과 테두리·둥근 카드가 누적돼 내용보다 조작부가 먼저 보였다. CSS에도 같은 선택자의 이전 값을 나중에 덮어쓰는 규칙이 반복됐다. 입력 높이가 고정돼 여러 줄을 읽기 어려웠으며 긴 기록을 읽다가 최신 답변으로 돌아오는 조작이 없었다.

여백은 같은 종류의 정보를 묶고 서로 다른 행동을 구분하는 용도로 사용한다. 옹기봇을 중심으로 한 첫 화면, 읽는 공간, 입력하는 공간에 각각 역할을 준다. 종이색 바탕·짙은 본문·절제한 올리브색으로 시각적 우선순위를 표현하고, 실제 대화가 시작되면 답변에 공간을 내준다.

## 반영 내용

| 영역 | 적용 |
|---|---|
| 공통 기준선 | 좌우 24px 공유, 400px 이하에서는 20px. 메뉴·연결 문구·입력·모델 설정 기준선 일치 |
| 상단 | 평평한 브랜드 마크, 얇은 밑줄 메뉴, SVG 설정/닫기 아이콘. 상단 드래그와 설정 진입 유지 |
| 첫 화면 | 캐릭터와 부드러운 빛, 짧은 문구, 같은 기준선의 질문 제안. 기본 화면에서 스크롤 없이 표시 |
| 대화 | 본문 14px·넉넉한 줄간격, 제목·단락·목록 간 간격 확대. 코드 12px·표 가로 스크롤 유지 |
| 입력 | 52px에서 최대 132px까지 자동 높이 조절, 짧게 지우면 원래 높이 복귀. 작은 창에서는 최대 100px |
| 최신 답변으로 이동 | 이전 내용을 읽을 때만 ‘맨 아래로’ 표시. 기존 자동 스크롤 조건과 읽는 위치 보존 유지 |
| 복사 | 성공 시 버튼에 잠깐 ‘복사됨’ 표시. 원문·코드 복사 범위 유지 |
| 모델 설정 | 입력 밖 하단에 유지, 배경과 테두리를 줄임. CLI 모델·추론·Standard/Fast 기능 유지 |
| 이전 대화 | 제목·미리보기·날짜 순서, 삭제 버튼은 카드 안의 예약한 오른쪽 공간에 배치. 영구 삭제 확인과 기본 취소 유지 |
| 설정 | 공통 여백과 넓은 행 간격, 기능별 구분선. Slack 홍보 카드는 짧은 대기 안내로 정리 |
| 작은 화면 | 높이 600px 이하에서는 첫 화면의 장식을 접어 제안·입력을 먼저 표시. 바탕화면 캐릭터는 유지 |
| 접근성 | 선택 메뉴의 `aria-current`, 입력 도움말 연결, 키보드 포커스·움직임 줄이기 유지 |

대화창 기본 크기는 430×690에서 460×740으로 변경했다. 작업 영역이 더 작으면 생성 크기를 줄인다. 캐릭터 창의 크기·드래그·투명 클릭 영역과 build15의 macOS 제목 창 속성 제거는 유지했다.

새 UI 라이브러리·폰트 다운로드·네이티브 모듈을 추가하지 않았다. CSS의 중복 덮어쓰기와 제거된 홍보 카드 스타일을 정리했다. 단순 입력/스크롤 로직은 기존 렌더러에 인라인으로 작성했다. 설정의 오래된 숫자 버전 대신 알파 안내를 표시하며 CLI clientInfo 버전 정리 O09는 남아 있다.

## 확인 범위

- `npm run check`: JS 구문·기본 캐릭터 팩 확인 통과.
- `npm run smoke`: 체험 대화, Markdown 보안·불완전 코드 표시, 큐, 캐릭터 교체, 안내 자동 숨김, 클릭 통과 통과.
- UI 레이아웃 검증: 460×740와 390×580 모두 기준선 일치, 전체 화면/첫 화면 넘침 없음, 입력창 가시성 확인. 입력 높이 52→132→52와 52→100→52 확인. `artifacts/ui-layout-smoke.json`.
- `npm run smoke:performance`: 1,000개 기록의 페이지 로드·읽는 위치 유지·변경분 IPC·저장 상한·맨 아래 이동 통과. `artifacts/performance-ui-smoke.json`.
- `npm run smoke:history`: 테스트 CLI로 검색·대화 격리·재개 통과.
- `npm run smoke:delete`: 테스트 CLI로 확인/취소, 실패 시 로컬 보존, 재시도·재시작 확인 통과. 실제 사용자 대화나 실제 CLI 세션 삭제 없음.
- 첫 화면·작은 창·설정 렌더링을 이미지로 검토했다. `artifacts/ui-refined-welcome.png`, `ui-refined-compact.png`, `ui-refined-settings.png`. 이전 대화 목록은 `artifacts/alpha-history.png` 참고.
- macOS build16에 UI·버전·캐릭터 창 옵션이 포함됨을 확인하고 실제 앱을 실행했다. 캐릭터 클릭으로 새 대화창을 열고 화면·모델/추론/속도 표시를 확인했다. 기존 설정과 소유 대화 목록/파일을 교체 전후 대조했다. `artifacts/ui-packaged-verification.json`.

macOS Apple Silicon에서 검증했다. 작은 창 검증은 같은 macOS에서 프로그램으로 크기를 조절한 결과이며 Windows 실기·혼합 DPI 검증 결과는 아니다. 편안함에 대한 실제 사용자의 장시간 평가, VoiceOver/Windows 스크린리더 검증, 구석 타일링 미리보기 소멸은 별도 미검증이다. 복사 피드백은 기존 복사 경로에 추가했으며 이번 자동 시나리오에서 시스템 클립보드 복사는 실행하지 않았다.

## build17 — 친구 이름 설정

설정의 `친구 이름`에 1~20자를 입력하고 저장한다. 기본값은 `옹기봇`이며 상단·답변 표시 이름·입력 안내·캐릭터 접근성 이름·지난 대화 안내·창 제목·트레이 설명을 갱신한다. 긴 이름은 상단에서 생략해 설정/닫기 버튼 공간을 보존하고 마우스를 올리면 전체 이름을 보여준다. 이름은 모든 캐릭터 외형에 공통으로 유지한다.

`state.json`의 `settings.buddyName`에 저장한다. 앞뒤 공백을 제거하고 Unicode NFC로 정규화하며 빈 이름·20자 초과·제어 문자를 거절한다. 여기서 글자 수는 정규화 후 Unicode 코드 포인트 기준이다. 저장 실패 시 메모리의 이름도 이전 값으로 되돌린다. 입력 중인 이름은 반복 상태 갱신에 덮어쓰지 않으며 오류/성공은 입력란 아래 표시한다.

이름 변경은 기존 대화 원문·모델·CLI 입력·CLI 세션 이름을 바꾸지 않고 새 대화를 만들지 않는다. 이전 답변의 작성자 표시에는 현재 이름을 사용한다. 체험 응답의 자기소개는 질문을 보낼 때의 이름을 사용한다. 앱 식별자와 데이터 폴더는 기존 값을 유지한다.

macOS 체험 검증에서 공백 정리·저장/재로드·기존 답변/캐릭터 창 동기화·입력 초안 유지·외형 변경 시 유지·잘못된 입력/다른 창 요청 거절·HTML 모양 이름의 문자 그대로 표시·기존 기록 파일 보존을 확인했다. `artifacts/buddy-name-smoke.json`, `buddy-name-settings.png`를 참고한다. 기존 체험/UI 회귀도 통과했다.

build17 앱을 실행해 실제 설정 입력란과 저장 성공을 확인하고, 기존 이름을 유지한 채 모델 등 설정과 소유 기록을 대조했다. `artifacts/name-packaged-verification.json`에 기록했다. 실제 모델 요청은 보내지 않았으며 Windows 실기 검증은 미수행이다.

## build19 — 각 화면의 행과 열 정렬

2026-10-07 대화·이전 대화·설정·미니 말풍선의 공통 좌우 기준선을 맞췄다. 스크롤 영역은 항상 6px 공간을 확보하고 그만큼 오른쪽 패딩을 보정해 스크롤 유무에 따라 내용이 탭·입력창보다 안쪽으로 밀리지 않게 했다. 미니 말풍선의 제목·메시지·입력창·모델 줄은 같은 16px 여백을 사용한다.

설정의 네 선택 상자는 같은 두 열과 40px 높이를 사용한다. 이름 저장과 이전 대화 검색은 40px 높이의 입력/버튼과 같은 84px 작업 버튼 열을 사용한다. MD 편집 작업 버튼은 같은 폭의 세 열로 배치한다. 접힌 편집기 제목은 다른 설정 제목과 시작선을 맞추고 펼치기 표시를 오른쪽에 둔다. 토글과 경로 이동 표시는 같은 오른쪽 열에 맞췄다. 대화 목록의 제목/날짜는 글자 기준선을 공유하며, 미니 헤더와 모델 컨트롤은 높이를 통일했다.

`npm run smoke`에서 460×740 및 390×580의 양쪽 기준선·선택 열·버튼 높이/폭·입력 확장·가로 넘침을 확인했다. `npm run smoke:buddy`에서 세 스킨의 360×410 미니 말풍선 정렬을 확인했다. 렌더링 이미지와 macOS build19 실행 설정 화면을 검토했고 기존 설정·대화 목록/파일을 교체 전 스냅샷과 대조했다. 실제 프로필의 대화는 0개였다. 근거는 `artifacts/ui-layout-smoke.json`, `buddy-features-smoke.json`, `alignment-packaged-verification.json`이다. Windows 실기 검증은 수행하지 않았다.

## build21 — 말투와 모델을 작은 한 줄로

2026-10-07 사용자가 첨부한 Codex 모델 표시를 참고해 하단을 28px 높이의 한 줄로 구성했다. 말투 선택은 왼쪽, 모델 이름과 작은 추론 단계 표시는 오른쪽에 놓고 두 조작의 테두리와 배경을 제거했다. Fast를 선택하면 모델 옆에 번개를 표시한다. 이전 두 줄보다 약 32px를 줄여 대화 영역에 돌려준다.

모델 버튼은 팝업을 연다. 팝업에서 기존 CLI 목록 기반 모델·추론·Standard/Fast와 새로고침을 그대로 제공한다. 작은 창에서도 팝업을 화면 안에 배치하며 Esc는 팝업만 닫고 모델 버튼으로 포커스를 돌려준다. 탭이나 창 크기를 바꾸면 열린 팝업은 닫힌다. 선택은 기존 IPC와 질문별 모델 스냅샷 경로를 사용한다. 모델 목록 포커스 보존에 쓰던 설정 서명의 누락된 변수 선언도 보완했다.

`npm run smoke`에서 460×740/390×580의 한 줄·좌우 순서·투명한 모델 버튼과 입력/정렬 회귀를 확인했다. `npm run smoke:buddy`에서 세 스킨의 360×410 한 줄 및 팝업 범위·세 선택 상자 표시를 확인했다. `npm run smoke:models`는 테스트 CLI로 여섯 질문의 모델/추론/속도 스냅샷, Fast 표시, 목록 자동 갱신·포커스 유지·팝업 닫기를 검증했다. 실제 macOS build21에서 미니 말풍선과 팝업 화면, Esc 동작을 확인하고 현재 사용자 이름·모드 등 설정과 기록 목록/파일을 보존했다. 실제 모델 질문은 새로 보내지 않았으며 Windows 실기는 미검증이다. 근거는 `artifacts/model-bar-packaged-verification.json` 및 위 세 smoke 결과 파일이다.

## build22 — 입력창 안으로 설정 통합

2026-10-07 반복 단축키 도움말을 제거하고 그 자리에 말투·모델 선택을 넣었다. 입력창 하단은 말투, 모델/추론, 보내기 순서이며 모델 팝업·Fast와 기존 Enter/Shift+Enter 동작을 유지한다. 단축키 안내는 보내기 버튼의 툴팁으로 제공한다. 조회 상태와 오류는 필요할 때 입력창 안에 표시한다.

긴 모델 이름은 생략하고 보내기 버튼의 크기는 유지한다. 응답 중 중단 버튼이 나타나는 경우도 조작이 겹치지 않게 배치했다. 외부 모델 줄을 제거해 일반/작은 창의 대화 영역은 이전 검증 대비 각각 36px/32px 늘었다.

일반 460×740·작은 390×580과 세 스킨의 미니 360×410에서 입력창 내부 배치, 긴 이름과 중단 버튼, 겹침·넘침, 팝업 범위를 검증했다. 테스트 CLI의 모델/추론/속도 스냅샷과 선택 조작으로 추가 질문이 전송되지 않는 것도 확인했다. 목록 포커스 검증의 고정 150ms 지연은 실제 갱신 상태를 최대 5초 기다리는 방식으로 바꿨다. macOS build22의 실제 입력창 화면, 모델 팝업 열기/닫기, 접근성에 노출된 툴팁을 확인하고 현재 이름·표시 모드 등 설정과 기록 목록/파일을 보존했다. 실제 모델 질문은 새로 보내지 않았고 Windows 실기는 미검증이다. 근거는 `artifacts/composer-controls-packaged-verification.json`, `ui-layout-smoke.json`, `buddy-features-smoke.json`, `model-ui-smoke.json`이다.

## build23 — 캐릭터 하단 메뉴 3초 숨김

캐릭터 하단 대화·쉬기/깨우기·설정 메뉴에 별도 3초 타이머를 적용했다. 포인터의 반복 상태 알림이나 남아 있는 포커스가 메뉴를 계속 표시하지 않도록 `focus-within` 표시 조건을 제거하고, 실제 캐릭터 재진입 시 다시 표시한다. 드래그 중에는 메뉴를 숨긴다. 표시 상태는 클릭 영역 판정에도 함께 전달한다.

격리 렌더러에서 메뉴 표시·포커스·반복 진입 이벤트 후 3초 숨김과 기존 클릭 영역/드래그/UI 회귀를 확인했다. build23 macOS 앱을 교체한 뒤 하단 메뉴 없이 캐릭터만 보이는 실제 화면 및 기존 설정/기록 목록·파일 보존을 확인했다. 네이티브 마우스 hover의 정확한 경과시간과 Windows 실행은 별도로 측정하지 않았다. 근거는 `artifacts/pet-ui-smoke.json`, `pet-menu-packaged-verification.json`이다.

## build24 — 안내 말풍선 숨김 때 캐릭터 위치 고정

기존 구현은 안내 말풍선을 표시할 때 캐릭터 창을 120×143에서 196×195로 확장하고, 숨길 때 다시 줄였다. 네이티브 창 좌표·크기 변경과 렌더러 내부 좌표 갱신 사이에 시차가 있어 캐릭터가 잠깐 다른 위치에 그려질 수 있었다. 최종 앵커만 비교하는 기존 검사는 이 중간 프레임을 확인하지 못했다.

안내 말풍선을 별도 196×52 투명 창으로 분리했다. 캐릭터 창은 말풍선 표시 여부에 따라 이동하거나 크기를 바꾸지 않는다. 안내 창은 화면 경계 안에 배치하고 위쪽 여유가 없으면 캐릭터 아래에 표시한다. 안내 문구에는 가벼운 전용 렌더러를 사용하며 투명 여백은 클릭을 통과시킨다. 안내 창 IPC는 동기화·클릭 영역·포인터·대화 열기로 제한했다. 기존 3초 자동 숨김과 하단 메뉴 동작은 유지한다.

최종 소스의 새 격리 프로필 `npm run smoke`에서 중앙·상단 오른쪽 모서리마다 4회 표시/숨김을 반복했다. 각각 137·186개 렌더링 프레임의 캐릭터 좌표와 창 크기가 고정됐고 캐릭터 창 move/resize 이벤트는 모두 0회였다. 안내 창의 표시·숨김, 화면 안 배치, 클릭 통과, 대화 열기, 다른 설정 접근 거절도 확인했다. 기존 UI·Markdown·큐·캐릭터 교체 회귀가 통과했다. 앞선 제한 실행은 Electron SIGABRT로 종료됐고 기존 테스트 프로필 재실행에서는 자동 숨김 검사가 실패했다. 그 테스트 프로필은 별도 이름으로 보존했으며 새 격리 프로필에서 위 결과를 얻었다. 기존 프로필 실패 원인은 확정하지 않았다.

macOS build24의 패키지 버전과 소스 일치를 확인하고 실제 앱에서 캐릭터 클릭으로 미니 대화를 열고 닫았다. 기존 사용자 이름·모델·위치 등 설정과 소유 대화 목록/파일을 교체 전후 대조했다. 근거는 `artifacts/pet-notice-smoke.json`, `pet-flicker-packaged-verification.json`이다. 프레임 검사는 Electron 렌더러 좌표와 창 이벤트 검사이며 OS 합성 화면의 동영상 측정은 아니다. Windows 실행·다중 모니터 실기는 미검증이다.

## build25 상태·유휴·복구

캐릭터의 대기 안내는 hover 동안 유지하고 이탈 후 3초 뒤 숨긴다. 하단 세 메뉴는 hover 진입으로 표시한 뒤 3초 후 숨긴다. 안내와 캐릭터가 공유하는 응답 도착 상태는 메인에서 관리한다. 숨겨진 패널은 DOM 갱신을 미루고 미니는 최신 두 카드만 생성한다. 길이 제한 안내는 원문 보존/스트림 수집 초과를 구분한다.

입력창 포커스 그림자의 잘못된 색상 문법과 반복 CSS를 정리했다. 경고는 클릭하여 닫을 수 있는 버튼으로 표시한다. renderer 종료에서는 질문을 다시 보내지 않고 화면만 복구한다. `smoke:stability`는 숨김/재표시·미니 두 카드·긴 원문·강제 화면 종료 및 세 스킨 포커스 그림자를 검사한다. 자동 창 검증은 OS의 타일링 미리보기나 사용자의 실제 입력 체감을 대신하지 않는다. 최종 네이티브 확인 상태는 [프로젝트 검토](PROJECT_REVIEW.md#build25-재검토-적용-기록)에 기록한다.
