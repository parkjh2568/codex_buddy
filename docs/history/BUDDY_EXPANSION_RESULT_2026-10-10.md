# 버디 확장 구현 결과 · 2026-10-10

아래는 alpha15/build31 적용 당시의 기록이다. 정상 reload·읽음·사용량 순서 등 당시 후속 보완은 [alpha16 수정 결과](CHANGE_REMEDIATION_RESULT_2026-10-10.md), alpha17/build33의 편집·첨부·설정·사용량 보완과 검증은 [품질 개선 결과](QUALITY_CYCLE_RESULT_2026-10-10.md)를 따른다. 실제 모델 호출·알림 show는 당시 기록이며 build31은 `dist/rollback-alpha15-build31/`에 보존한다. 최신 소스·후보와 검증 범위는 [현재 알파 보고서](../ALPHA_REPORT.md)를 따른다.

`my_budy`의 버디 경험을 유지하면서 [확정한 작업 계획](../BUDDY_ROADMAP_2026-10-10.md)의 BUD00–BUD09와 O01/O04/O08을 구현했다. 소스는 `0.1.0-alpha.15`, 별도 검증 앱은 macOS arm64 staging build31이다. 기존 일반 실행용 alpha.14 묶음과 이전 복구 자료는 교체하지 않았다. 이번 실제 확인에서 일반 실행 경로의 CFBundleVersion은 30이며 Info.plist는 작업 전 12:50:41에 작성돼 있었다. 이전 문서의 build29 표기와 구분한다.

단위 검사 101개와 격리 Electron 통합 검사 14종을 통과했다. 실제 CLI의 버전·인증·계획 모드 목록·스킬 목록·계정 한도 조회는 모델 호출 없이 확인했다. 이어 빈 임시 폴더에서 Luna/high/Standard의 짧은 계획·전용 리뷰 요청 두 개를 읽기 전용으로 실행했다. 추가 권한/도구 요청은 없었다. OS 클립보드 수동 왕복, 물리 파일 드롭·Windows 입력은 이 결과에 포함하지 않는다.

## 사용 방법

- 입력창의 이미지/파일 선택과 드롭은 같은 첨부 초안으로 들어간다. 이미지와 텍스트가 같이 있는 클립보드는 일반 paste에서 텍스트를 유지하며, `이미지 붙여넣기`로 이미지를 명시적으로 선택한다. 최대 8개, 파일당 16MiB, 합계 32MiB다.
- 작업 중 보낸 질문은 FIFO로 기다린다. `대기 보류`는 현재 답변을 계속하면서 다음 질문을 멈춘다. 대기 항목의 `수정`에서 텍스트·첨부를 변경하고 `저장`한다. `수정 취소`는 원래 대기 질문과 새로 쓰던 초안으로 돌아간다.
- `대기 질문 모두 취소`는 클릭 당시의 대기 질문을 대상으로 한다. 현재 답변과 그 이후 새로 접수된 질문까지 취소하는 기능은 아니다.
- 생성 이미지 아래에서 원본 열기·이미지 복사·다른 이름으로 저장·다시 첨부를 사용한다. 복사는 PNG로 전달하고 저장은 원본 PNG/JPEG/WebP 형식을 유지한다. 같은 이름의 기존 파일이 있으면 새 이름을 선택한다.
- `이전 대화`에서 ☆/★로 즐겨찾기, `제목`으로 이름 변경, `MD`로 내보내기를 한다. 이미지 포함 옵션을 켜면 새 `.assets` 폴더에 사본을 만들고 Markdown에서 상대 링크로 연결한다. 첨부 파일은 이름/크기만 기록하며 내용을 복사하지 않는다.
- 본문 검색은 검색어 입력 후 별도 버튼으로 실행한다. 최근 기록 최대 100개/32MiB, 결과 50개로 제한한다. 제목/최근 내용 검색은 기존처럼 즉시 동작한다.
- `작업 목적 · 스킬`에서 목적을 선택한다. 스킬은 CLI 연결 후 해당 작업 폴더의 목록을 새로고침하고 선택한다. 전용 리뷰는 텍스트 지시·일반 파일 첨부를 사용하며 이미지/명시적 스킬은 분석 목적의 질문에서 사용한다.
- 알림과 정숙 시간은 설정에서 선택한다. 정숙 시작과 끝이 같으면 하루 종일 알림을 억제한다. 승인 표시 초기값은 기존 대화창 자동 열기다.

## 오류·경합 처리

### 첨부와 이미지

클립보드 바이트는 첫 비동기 검증 전에 복제한다. 파일 선택·드롭·바이트 입력은 `AttachmentStore`의 동일한 크기·형식·decode·해시·캐시 한도를 적용한다. 여러 파일 중 하나가 실패해도 초안에 부분 등록하지 않는다. 가져오기 중 대화/폴더/편집 대상이 바뀌거나 화면이 잠기면 후보 등록을 거절한다. 편집 저장 중 새 첨부 접수도 막는다.

이미지 활용은 renderer가 넘긴 파일 경로/Markdown URL을 읽지 않는다. 활성 대화의 검증된 결과 ID로 원본을 확인하고, 저장 대화상자가 끝난 뒤 소유 대화·메시지·이미지를 재확인한다. 새 파일의 쓰기 실패는 처음 연 파일과 같은 객체임을 확인한 뒤 정리하며 캐시와 텍스트 답변을 유지한다. 내보내기 폴더는 비어 있을 때만 제거하고, 부분 사본이나 사용자가 추가한 파일이 있으면 남겨 실패 안내에서 알린다. 같은 이름의 기존 파일·폴더는 교체하지 않는다.

### FIFO와 저장

수동·인증·연결·절전·저장 보류를 Set으로 구분했다. 정상 수동 보류에서는 새 질문을 접수할 수 있다. 연결 복구만으로 수동 보류를 해제하지 않으며 저장 장애를 계속 버튼으로 우회하지 않는다.

편집 예약은 실행 전 질문을 고정하여 뒤 항목이 추월하지 못하게 한다. ID/token을 확인하고 기존 `admissionTail`/저장 워커에서 수정 저장을 직렬화한다. 실패하면 원래 질문/첨부를 복원하고 편집 초안을 유지한다. 화면 복구가 편집과 겹치면 수동 보류로 돌아간다. 전용 리뷰의 대기 질문에 이미지가 들어온 경우도 확정 전에 거절한다.

대기 취소 저장 중에는 다음 작업을 dispatch하지 않는다. 취소 확정 응답은 저장 후 반환한다. 저장 장애에서 취소하지 않은 대기 질문은 원문과 첨부를 보존하고 보류하며 새로 실행하지 않는다. 재시작 때의 미완료 질문은 기존처럼 중단 상태로 읽고 자동 재전송하지 않는다.

### 알림·선택 기능

완료 알림은 이미지 준비와 답변 저장 성공 후 한 번만 발생한다. 직접 중단은 실패 알림 대상이 아니다. 늦은 완료/기록 재조회로 같은 알림을 반복하지 않는다. OS 실패는 대화의 성공을 바꾸지 않으며 버디와 대화창에서 확인한다. 읽지 않은 답변은 버디 주의 상태로 유지하고 보이는 대화에서 읽음 처리한다.

알림 클릭은 대화 소유권을 다시 확인한다. 진행 중 작업이나 대기줄이 있으면 현재 대화를 열며 다른 기록으로 강제 전환하지 않는다. 삭제한 대화의 알림은 열지 않는다. 승인 대기에도 기존 10분 작업 제한은 유지한다.

계획·리뷰 시작은 같은 소유 턴 수명에 포함했다. 시작 RPC 전의 이벤트도 해당 턴 ID 확정 후 처리한다. 준비 중 중단 요청이 오면 선택 기능 조회 이후에도 실행 전 다시 확인한다. `plan`·`enteredReviewMode`·`exitedReviewMode` 결과를 표시하고 기록 재조회에서도 복원한다. CLI의 내부 리뷰 사용자 항목으로 앱에서 접수한 원문/첨부를 덮어쓰지 않는다. 실제 CLI가 같은 결과를 리뷰 종료 항목과 agentMessage로 함께 보내므로 종료 항목을 최종 원문으로 사용해 화면/기록에서 중복을 제거한다.

리뷰 API는 일반 질문과 모델/추론/속도 계약이 다르다. 대화 연결에서 확인한 모델과 실제 리뷰 모델을 동일하다고 표시하지 않는다. 최종 리뷰 적용 모델을 응답에서 확인할 수 없는 경우 CLI 전용 설정을 따른다고 안내한다.

스킬은 CLI가 반환한 활성 목록의 토큰으로만 선택하며 256KiB 이내 파일을 제한적으로 읽고 해시를 기록한다. 실행 직전 해시가 달라졌으면 실패 안내 후 재선택한다. 검사를 통과한 뒤 CLI가 읽을 때까지 원문이 영구 고정된다는 보장은 하지 않는다. 지원하지 않는 선택 API는 별도 안내하고 일반 질문 경로는 유지한다.

도구/계획 표시는 각 24개와 항목별 문자 제한을 둔다. 원본 도구 로그를 계속 누적하지 않는다. 계정 한도는 최대 16개 bucket, 각 primary/secondary의 사용 비율·초기화·조회 시각만 정제한다. 계정 변경 시 이전 값을 지우고 연결 중단은 오래된 값으로 표시한다. 숨긴 창의 지속 polling을 추가하지 않았다.

## 캐릭터와 무료 에셋 선택

시범은 기존 SVG 제작 경로를 사용한 자체 픽셀 스타일 캐릭터로 정했다. 원본은 `scripts/create-characters.cjs`, 팩은 `characters/onggi-pixel-bean/`이다. 외부 3D 엔진·Pixelorama 설치나 에셋 다운로드 없이 현재 런타임 형식으로 만들었다. manifest에는 자체 원본 출처와 기존 `Project character assets` 표기를 기록했다. 외부 CC0 에셋 또는 CC0 배포 권한이라고 주장하지 않는다.

8개의 정적 SVG(7개 상태와 blink), manifest, 기본 성격과 말투 MD만 포함한다. SVG 안에 실행 코드/참조/CSS 애니메이션을 넣지 않았다. 실제 decode, 공통 캔버스, 3개 blink 프레임, 새 폴더 내보내기/다시 읽기, 35/50/65% 화면 표시를 확인했다.

무료 에셋 11개 사이트의 판단·원문 출처는 [계획의 에셋 분석](../BUDDY_ROADMAP_2026-10-10.md#무료-에셋-사이트별-판단)에 유지했다. Quaternius 등 외부 에셋과 jfxr 고정 효과음은 별도 후속 후보다. 현재 추가한 소리는 OS 알림 소리 옵션이며 캐릭터 팩 오디오 지원이나 외부 효과음 도입은 아니다.

## 전달과 남은 수용 조건

최신 검증 앱은 `dist/staging/OnggiBot-darwin-arm64/OnggiBot.app`이다. 일반 실행 경로의 기존 alpha.14/CFBundleVersion 30 묶음과 이전 복구 자료는 보존했다. 패키지에 테스트·보고서·개인 기록·모의 CLI를 넣지 않았다. 네트워크 접근이 제한된 환경에서는 `--electron-zip-dir <공식 Electron ZIP 캐시 폴더>`로 같은 버전/OS/CPU의 로컬 ZIP을 사용할 수 있다.

남은 수용 조건은 실제 OS 클립보드 왕복·물리 파일 드롭·한국어 키보드 조합, 알림 배너/클릭/권한·정숙의 OS 실기, 다른 모델/제공자별 리뷰 적용값과 실제 앱의 추가 질문/승인 흐름, 미로그인 브라우저 콜백, Windows/Intel/DPI/파일 잠금, Developer ID·공증·설치 프로그램이다. CUA의 앱 화면 조회가 시간 초과하여 이번 알림 배너를 육안 확인했다고 기록하지 않는다. OS/인증 한계를 자동 허용이나 임의 권한 확대로 우회하지 않았다. 실제 모델 검증은 알린 두 개의 짧은 개발 검사로 제한했으며 최초 설정 화면에 자동 유료 테스트 질문을 추가하지 않았다.

작은 로직은 기존 함수 안에서 처리했다. 입력/저장/팩 검증의 기존 경계를 재사용하고 별도 큐·클립보드·옵션 프레임워크를 추가하지 않았다. 이후 최적화는 C07–C09의 실제 자원/긴 기록 측정에 따라 진행한다.

2026-10-12에 이 버전의 앱 원본은 [정리 복구 압축본](../../artifacts/legacy-cleanup-2026-10-12/cleanup-targets.tar.gz)에 보관하고 dist/rollback-alpha15-build31 실행 폴더를 정리했다. 당시 소스/검사 수와 실제 실행 여부는 위 기록을 유지한다.
