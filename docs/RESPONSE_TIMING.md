# 수신 대답속도 측정

alpha.6, 2026-10-06. 상단에는 `대화`, `이전 대화`만 두고 우측 톱니바퀴로 설정을 엽니다. `수신 대답속도 측정`은 기본 꺼짐이며 변경을 저장합니다. 켠 뒤 보낸 질문부터 측정합니다. 완료·오류·중단 답변 끝에 줄바꿈과 측정 정보를 별도로 표시합니다.

## 구간 정의

| 표시 | 시작 → 끝 | 포함 범위 |
|---|---|---|
| 입력 → 앱 수신 | 입력창 제출 → 메인 IPC 핸들러 진입 | 렌더러→메인 전달 |
| 앱 수신 → CLI 전송 | 메인 수신 → turn/start JSON을 stdin에 쓰기 | 모델 조회, FIFO 대기, 연결·thread 준비 |
| CLI 전송 → 응답 완료 | stdin 쓰기 → 최종 턴 완료 수신 | 모델 처리·도구·승인·통신 포함 |
| 응답 완료 → 화면 반영 | 완료 수신 → 보이는 대화 화면의 두 animation frame 이후 | 저장·IPC·DOM 갱신, 화면이 숨겨진 시간 포함 |
| 첫 응답 대기 | CLI 전송 → 첫 답변 텍스트·계획·리뷰 결과 또는 완료 이미지 항목 수신 | 최초 표시 가능한 답변 항목 수신까지(이미지 decode·저장 완료 시각은 아님) |
| 큐 대기 | 큐 등록 → 실행 시작 | 위의 앱 수신→CLI 전송에 포함됨 |
| 전체 | 입력 제출 → 화면 반영 | 첫 네 구간의 합 |

`mm:ss.ffff`는 분:초.소수점 네 자리입니다. 예: `00:03.2484`. 0.1ms 단위로 반올림하며 분은 99를 넘어도 잘리지 않습니다. 값이 없으면 `—`입니다. 큐 대기와 첫 응답은 상세 지표이므로 전체에 다시 더하지 않습니다. 다른 진입 경로에서 제출 시각을 제공하지 않으면 입력 구간과 전체를 추정하지 않습니다.

`performance.timeOrigin + performance.now()`로 동일 PC의 프로세스 시각을 맞춥니다. 단조 시계와 time origin의 용도는 [Node 24 perf_hooks](https://nodejs.org/docs/latest-v24.x/api/perf_hooks.html), 정밀도 제한은 [W3C High Resolution Time](https://www.w3.org/TR/hr-time-3/)을 따릅니다. 표시 자릿수가 실제 측정 정확도를 보장하지 않습니다. 앞으로 별도 서버를 연결하면 클라이언트와 서버 시계를 직접 빼는 방식은 사용할 수 없습니다.

CLI 전송은 OS stdin 쓰기 접수이며 CLI 내부 파싱 완료 ACK가 아닙니다. 응답 완료는 최종 턴 이벤트이며 순수 모델 추론 시간과 같지 않습니다. 화면 반영은 DOM 프레임 확인이며 모니터 픽셀 표시를 직접 측정하지 않습니다. 설정·이전 대화 화면을 보고 있으면 대화 화면으로 돌아온 뒤 확정하므로 해당 대기 시간이 포함됩니다. 측정 푸터 자체의 후속 갱신 시간은 포함하지 않습니다.

## 저장·표시

측정치는 assistant 메시지의 별도 `timing` 필드로 대화 파일에 저장합니다. 질문 원문·모델 답변 원문·전체 복사에는 섞지 않습니다. 옵션을 끄면 기존 푸터를 숨기고 새 질문의 측정을 시작하지 않습니다. 켜진 상태로 보낸 질문의 진행 중 측정은 마무리합니다. 과거 측정되지 않은 대화는 시간을 복원하지 않습니다.

체험 모드는 `체험(CLI 측정 없음)`으로 표시하며 실제 CLI 구간은 `—`입니다. CLI로 보내기 전에 대기 취소하면 CLI 관련 구간도 `—`입니다. 연결·실행 중 오류는 확인된 종료 시점까지 기록합니다. 완료 상태는 즉시 화면 갱신을 예약하고 스트리밍 중간 이벤트는 기존 50ms 묶음을 유지합니다.

## 검증

`npm run smoke:timing`은 실제 모델 대신 테스트 CLI를 사용합니다. 첫 응답/최종 응답 분리, FIFO 대기, 네 구간 합, 시간 형식, 설정 토글·저장·복원, 숨겨진 대화 화면의 ACK 지연, 원문 오염 방지를 검증합니다. `artifacts/timing-ui-smoke.json`, `artifacts/alpha-response-timing.png`에 근거를 저장합니다.

`npm run smoke:real`은 Luna/high로 실제 CLI 왕복과 화면 반영 확인을 수행하고 `artifacts/real-response-timing.json`에 기록합니다. 한 번의 짧은 질문은 평균/상위 지연이나 Fast 성능 비교를 대신하지 않습니다. 성능 목표는 같은 질문·같은 대화 길이·같은 서비스 등급으로 반복 측정한 뒤 정합니다.

## 저장·표시 수명

대화 저장은 직렬 워커에서 수행한다. CLI 전송 준비/화면 반영 구간에는 해당 시점까지 실제 기다린 저장 시간이 포함되며, 워커 적용만으로 전체 모델 응답이 빨라졌다고 해석하지 않는다. 미니 화면에서는 실제 생성된 두 카드만 표시 ACK 대상이다. 숨겨진 패널/메시지는 보이는 화면으로 돌아온 뒤 ACK한다. ACK 저장 실패는 timing을 복구하여 재시도 가능하게 했다.

화면 반영 확인은 두 animation frame 뒤 적격 응답을 최대 100개씩 묶는다. 대화·표시 세대·메시지와 timing 객체 소유권을 저장 대기 전후에 확인하고, 같은 배치에서 변경된 timing은 한 번 저장한다. 중복 확인은 재저장하지 않고 저장 실패 시 해당 배치의 timing을 복구한다. 단일 응답 확인 형식도 유지한다. [성능 최적화 결과](history/PERFORMANCE_OPTIMIZATION_RESULT_2026-10-13.md)에 실제 저장 횟수·반복 측정과 오류 검증 범위를 기록한다.

당시 실제 응답 표본은 [측정 이력](history/MEASUREMENTS_BEFORE_CLEANUP_2026-10-10.md)에 보존한다. 단일 응답을 평균 지연이나 성능 향상률로 비교하지 않는다.

## 접수 시각

receivedAt은 send의 접수 검증 시점이며 이전 저장이나 앞선 접수 확정을 기다리기 전입니다. 따라서 메인에서의 저장 대기·모델 조회·FIFO 대기는 이후 dispatch/전체 시간에 반영됩니다. 취소 신호는 진행 중 저장을 기다리지 않고 전달하지만 종료 상태의 영속화는 직렬 저장을 기다립니다. 화면 반영 ACK는 보이는 메시지에만 기록하며 숨김·미니에서 표시하지 않은 이전 메시지는 ACK하지 않습니다. [현재 검증 결과](history/ISSUE_REMEDIATION_RESULT_2026-10-08.md)
