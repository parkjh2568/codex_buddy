# 최초 설치·Codex 연결

앱은 CLI/작업 폴더·인증·모델 목록의 준비 상태를 나누고, 실패 원인에 맞는 해결 버튼을 표시한다. 기존 CLI 로그인 캐시를 재사용한다. alpha.13/build28에서 연결 복구와 브라우저 로그인 안내를 구현했다. 구현 전 공백 분석은 [최초 연결 검토 이력](history/FIRST_RUN_REVIEW.md)에 보존했다.

## 현재 사용 흐름

| 상태 | 동작 |
|---|---|
| 프로세스 연결 중단 | 한 번 자동 복구. 실패하면 `다시 연결` |
| CLI 경로가 바뀌거나 없음 | `자동으로 다시 찾기`, 필요하면 `설치 안내` 또는 실행 파일 선택 |
| 작업 폴더 없음 | `작업 폴더 선택` |
| 로그인 필요 | `ChatGPT로 로그인`으로 검증된 공식 HTTPS 주소를 기본 브라우저에서 열기 |
| 로그인 대기 | 앱에서 완료 확인, 취소 또는 5분 만료 |
| 모델 조회 실패 | 원인 표시 후 다시 확인. 다른 모델로 자동 변경하지 않음 |

다른 실행 파일/작업 폴더는 파일 종류·접근성·initialize 확인 후 확정하고 기존 기록을 보존한다. 새 연결은 새 대화를 준비하며 이전 대화를 열면 해당 연결 문맥을 복원한다. 공용 인증 토큰/이메일/인증 URL을 기록에 복제하거나 공용 CLI 계정에서 로그아웃하지 않는다. 중단된 질문·대기 질문은 자동 재전송하지 않는다.

alpha.18은 인증 조회에도 연결·계정 수명을 적용한다. 로그아웃/연결 교체/dispose 뒤의 성공·오류는 현재 상태를 덮지 않는다. 이전 조회가 끝나도 새 조회의 소유권을 해제하지 않는다. 로그인 완료 직후 계정 갱신이 교차하면 현재 상태를 한 번 다시 확인하며 반복 갱신에서는 재연결 안내를 유지한다. 실제 새 계정 브라우저 인증은 여전히 별도 수용이다.

## 검증·남은 범위

설치된 CLI 캐시 인증 읽기는 확인했다. 로그인 정상/취소/중복/콜백 순서/URL 거절/만료는 단위·테스트 CLI 검증이다. 실제 미로그인 계정의 브라우저 콜백, 외부 제공자·Windows 신규 PC 설치/실행은 미검증이다.

alpha.15에는 CLI 버전·기능별 지원 상태, CLI→인증→폴더→모델의 단계 안내, 대화·인증 정보·개인 경로를 제외한 진단 JSON 내보내기를 추가했다. 실제 설치 CLI 0.162.0-alpha.2의 버전과 기존 인증·계획/스킬/한도 조회를 모델 호출 없이 확인했다. [확장 결과](history/BUDDY_EXPANSION_RESULT_2026-10-10.md)를 참고한다.

선택형 유료 테스트 질문, 새 PC 전체 설치 수용과 설치 프로그램은 후속 범위다. [남은 연결·환경 수용](../TASKS.md#실제-환경에서-남은-수용)과 [연결/이미지 적용 기록](CONNECTION_AND_IMAGES_2026-10-08.md)을 따른다.
