# my_budy 후속 작업 분석과 실행 계획

2026-10-10. [품질 개선 결과](history/QUALITY_CYCLE_RESULT_2026-10-10.md), [제품 방향 검토](BUDDY_PRODUCT_REVIEW_2026-10-10.md), [현재 작업 목록](../TASKS.md)을 alpha17 코드와 대조해 작성한 후속 계획이다. 계획 작성 시점에는 아래 작업을 구현하거나 실기 검증을 새로 완료하지 않았다. 이후 사용자 실행 요청에 따른 alpha18의 수정·측정·검증과 남은 수용은 [후속 작업 결과](history/BUDDY_FOLLOWUP_RESULT_2026-10-10.md)를 따른다. 아래 출발점과 코드 위치는 계획 작성 당시 기준으로 유지한다.

우선순위는 **기존 기능의 실제 사용 수용 → 같은 환경에서 성능 측정 → 확인된 병목의 최소 수정 → 플랫폼·배포 수용**이다. my_budy의 목적은 캐릭터·이름·말투를 유지하며 로컬 Codex와 편하게 대화하는 버디다. 질문 전달, 첨부, 기다림, 결과 확인이 안정적인지부터 확인한다. 조용한 개인 버디와 CLI 사용 편의성을 우선한다는 판단은 현재의 작업 가정이며 사용자 선호가 확정됐다는 뜻은 아니다.

일반 실행 alpha.14/build30과 alpha.16/build32·alpha.15/build31 복구 묶음은 보존한다. 사용 중인 앱이나 모델 작업을 자동으로 종료하거나 일반 실행 경로를 덮어쓰지 않는다. 후보를 검사할 때는 실제 실행 버전을 확인해 이전 앱의 단일 인스턴스 창을 최신 후보로 오인하지 않는다.

## 2. 작업 원칙과 판단 기준

[AGENTS.md](../AGENTS.md)와 [개발 구조](ARCHITECTURE.md)를 적용한다.

- 단순 상태 검사·문자열 처리·지역 Map 구성은 기존 함수 안에서 처리한다. 한 호출의 몇 줄을 감싸는 helper, 범용 dispatcher, 새 상태관리 프레임워크를 만들지 않는다.
- 프로세스, 저장, 첨부·이미지 검증, 데이터형 캐릭터 팩의 책임 경계는 유지한다. 파일 I/O·프로세스 요청·큰 데이터 처리는 필요한 비동기 수명을 유지한다. 인라인 작성 원칙을 메인 프로세스의 동기 I/O 확대 근거로 삼지 않는다.
- 질문은 접수 당시 대화·자료·모델·말투·목적을 유지한다. 승인·중단은 FIFO 질문 큐와 별도로 처리하며, 연결 복구·절전 복귀·재시작이 질문을 자동 재전송하지 않는다.
- 데이터 손실, 다른 대화 응답 적용, 외부 파일 덮어쓰기, 불확실한 저장 뒤 실행 재개는 성능 개선보다 우선한다. UI 잠금은 main의 소유권·예약·크기·경로 검사를 대체하지 않는다.
- 실제 모델 응답, 테스트 CLI 응답, 체험 응답, OS 실기 결과를 각각 기록한다. 모델 선택과 read-only·승인 정책을 임의로 바꾸지 않는다.
- 새 버그는 재현 조건과 실패 근거가 있을 때 확정한다. 아래의 비용 후보·미검증 수용 조건을 현재 장애로 단정하지 않는다.

## 4. 후속 1 — 최초 연결과 복구

**분석.** 단계 안내와 해결 버튼은 이미 구현됐다. 실제 기존 인증 읽기와 로그인 순서·취소·5분 만료의 모의 검증도 있다. 남은 핵심은 처음 쓰는 사람이 문제를 구분하고 첫 대화까지 도달하는지, 실제 미로그인 계정의 브라우저 콜백이 정상인지다. 단순히 설치 버튼을 더 늘리는 것으로 해결됐다고 판단할 수 없다.

주요 위치는 [refreshModels](../src/main.cjs:99), [연결 복구 action](../src/main.cjs:930), [인증 처리](../src/connection-setup.cjs:93), [모델 목록](../src/models.cjs), [최초 연결 안내](FIRST_RUN_REVIEW.md)다.

| 시나리오 | 확인할 동작·예외 | 완료 조건 |
|---|---|---|
| 정상 기존 인증 | 캐시 재사용, CLI→인증→폴더→모델 표시, 선택 모델 유지 | 임의 로그인·모델 변경 없이 질문 접수까지 진행 |
| CLI 없음/경로 변경 | 자동 재탐색·수동 선택·설치 안내. 실행 파일 검증과 initialize 실패 | 실패 후보를 설정으로 확정하지 않고 원래 기록·초안 보존 |
| 폴더 없음/읽기 거절 | 폴더 선택 후 재확인, 취소, 대화별 기존 연결 문맥 | 원인이 폴더 문제로 표시되고 무관한 재로그인을 요구하지 않음 |
| 실제 브라우저 로그인 | 공식 URL, 완료/취소/5분 만료, 오래된 loginId, 도중 CLI 종료 | 해당 시도만 완료/취소하며 인증 완료 후 모델 목록 준비 |
| 연결 중단 | 유휴 상태의 한 번 자동 복구, 실패 뒤 수동 재연결 | 끊긴 질문·보류 큐 자동 재전송 0회, 재연결 뒤 사용자가 재개 가능 |
| 모델·한도 API 미지원 | 지원/미확인/미지원과 연결 실패 구분, stale 값의 시점 | API 미지원 때문에 계정/연결 상태를 거짓 성공·실패로 바꾸지 않음 |
| 새 Mac 최초 실행 | CLI가 없는 상태부터 폴더/로그인/첫 질문까지 따라가기 | 도움을 받은 지점·오류·해결 횟수와 실제 결과를 기록 |

실제 미로그인 수용은 별도 OS 사용자 또는 독립 인증 환경에서 한다. 앱 프로필만 분리해도 공용 CLI 인증 캐시는 공유될 수 있으므로 기존 계정의 로그아웃·토큰 이동을 검사 준비 수단으로 쓰지 않는다. 테스트 CLI로 인증 UI를 확인한 결과를 실제 로그인 완료로 쓰지 않는다.

산출물은 상태별 재현 기록, 정제한 진단 JSON, 확인한 CLI/OS 버전, 최초 사용 수용표다. 막힌 단계가 재현될 때만 해당 action·안내 문구를 수정한다. 항상 재연결·항상 재로그인·무제한 재시도 같은 우회는 추가하지 않는다. 선택형 테스트 질문 O06은 비용·전송 내용을 명시한 별도 범위이며 첫 실행이나 재연결에서 자동 호출하지 않는다.

## 5. 후속 2 — 첨부·이미지·FIFO와 실제 OS

**분석.** 현재 회귀는 저장 대기 중 제거 RPC, 큐 편집, trusted 드롭의 순서 교차까지 확인한다. 실제 물리 입력·클립보드·한글 IME·OS 알림의 끝까지 이어지는 경험은 별도 수용이다. 특히 요청했던 그림 대화는 텍스트만 복원한 것을 이미지 표시 성공으로 간주할 수 없다.

| 한글 IME·전송키 | 조합 중 Enter, 조합 확정 뒤 Enter, Shift+Enter, ⌘/Ctrl+Enter | 조합 중 접수 0회, 확정된 원문만 한 번 접수 |
| 알림·읽음 | 완료/승인/실패, 정숙/소리/내용 숨김, 권한 거절, 클릭, 숨김·잠금·다른 대화 | 내용/정숙 설정 준수, 중복 억제, 클릭 대상과 읽음 상태 일치 |
| 절전·모니터·표시 | 실제 suspend/resume·화면 잠금·Spaces·배율·메뉴 막대·타일링 | 자동 재전송 없음, 위치 복구·클릭 통과·숨김 정책 확인 |

원래 그림 대화가 없거나 원본을 복구할 수 없다면 조회 한계와 이미지 실패 안내를 남긴다. 새로운 생성은 기록 복원 검사와 구분한다. 예외 재현은 테스트 CLI와 합성 파일을 먼저 사용한다. 실제 이미지 생성·모델 응답은 필요한 별도 검증 범위에서만 수행하고 요청 횟수와 모델을 기록한다.

산출물은 OS 수용표와 실패 시 최소 재현이다. 이미지 클립보드는 미리보기 성공만으로 합격 처리하지 않고 앱 밖 붙여넣기까지 확인한다. 알림 `show` 이벤트만으로 배너·권한·클릭을 모두 확인했다고 기록하지 않는다.

## 6. 후속 3 — 성능을 먼저 측정

**현재 확인한 비용 후보.** 워커 저장은 직렬화돼 있지만 [saveAsync](../src/store.cjs:274)의 `worker.postMessage`는 전체 data를 구조화 복사한다. [readHistory](../src/store.cjs:98)는 최대 32MiB 기록을 동기 읽기·UTF-8 decode·JSON parse한다. [원격 병합](../src/main.cjs:903)은 턴마다 기존 배열을 검색한다. [내보내기](../src/main.cjs:854)는 대화 사본과 최대 128MiB·256개 이미지 버퍼를 보관한다. 이것들은 코드에서 확인한 작업량이며, 체감 지연·메모리 장애가 이미 재현됐다는 뜻은 아니다.

| 측정 대상 | 데이터/조건 | 수집할 값 | 판단에 필요한 구분 |
|---|---|---|---|
| 첫 실행·다시 열기 | 프로세스 시작과 이미 실행 중인 창 열기를 따로 측정 | 창 표시·입력 가능·첫 화면 반영 시간 | CLI/모델 대기와 UI 시간을 분리 |
| 상주 버디 | 동일 팩의 움직임/줄이기/정숙/숨김, 표시 대화창 닫힘 | 프로세스별 CPU·메모리, frame 변경 수, 표시 상태 | Electron 프로세스와 CLI 하위 프로세스를 별도로 수집 |
| 저장 | 작은 기록, 1,000개 메시지, 파일 크기가 다른 큰 기록 | postMessage 호출·전체 저장·main 이벤트 루프 지연, worker 비용 | 디스크 시간과 main 복사 비용 분리 |
| 기록 열기·검색 | 같은 기록의 캐시 상태를 명시, 다수 대화 검색 | 읽기/parse/병합/DOM 시간, p95 지연·메모리 최고값 | 검색의 100개/32MiB/50건 한도와 명시적 실행 유지 |
| 내보내기 | 텍스트만, 이미지 포함, 취소, 용량 상한 근처 | 사본·이미지 읽기·쓰기 시간, 프로세스별 RSS 최고값 | 성공·취소·부분 실패를 각각 측정 |
| 여러 이미지 | 합성 PNG/JPEG/WebP와 다른 크기, 미리보기/원본 | decode·읽기·IPC 크기, 이미지당/전체 메모리 최고값 | base64 확대와 원본 버퍼·decode 메모리 구분 |
| 대기 입력 | 저장/기록 처리와 입력·취소의 순서 교차 | 접수 지연·취소 처리 시간·큐 순서 | 총 응답 시간에 모델 시간을 섞어 앱 병목으로 해석하지 않음 |
| 실제 배터리 | 충전·전원 모드·백그라운드 활동·화면 밝기가 통제된 별도 실험 | 배터리 변화/OS 에너지 지표와 조건 | CPU 감소만으로 배터리 절감률을 계산하지 않음 |

데이터셋 제안은 소형 기록, 1,000개 메시지, 약 8/24MiB 기록, 32MiB 경계와 초과 거절, 1/8개 이미지 및 이미지 포함 내보내기다. 바이트 수는 실제 직렬화한 JSON 기준으로 기록하고 합성 자료를 사용한다. 정상 데이터와 한도 거절 데이터를 별도로 표시한다. 이 수치는 검사 설계 제안이며 이미 측정한 기준이나 성능 보증이 아니다.

### 측정 절차

1. OS/하드웨어/Electron/CLI/프로젝트 버전·소스/ASAR 해시, 팩·배율·전원·화면·프로필·기록 크기·다른 활동을 기록한다. 현재 후보와 수정 후보를 같은 환경에서 비교한다.
2. 창 다시 열기 같은 짧은 측정은 조건별 준비 실행 후 최소 20표본을 제안한다. 중앙값·p95·최댓값과 원자료를 함께 남긴다. 긴 작업·자원 측정은 반복 수와 경과 시간을 별도로 기록하며 적은 표본의 p95를 안정적인 성능 보증으로 쓰지 않는다.
3. 자원은 조건별 10분 측정을 출발점으로 삼되 실행 순서의 영향을 줄이도록 전후 후보 순서를 바꾸어 반복한다. 화면 잠금·다른 앱 활동 등 조건이 깨진 구간을 표시한다. 실행 수·시간을 줄인 경우 그 한계를 기록한다.
4. 프로세스별 메모리와 최고값을 남긴다. 공유 메모리가 있으므로 단순 합계를 유일한 물리 RAM 사용량으로 부르지 않는다. 작업 후 유휴 상태로 돌아왔을 때 메모리도 확인한다.
5. 사용 시나리오의 지연과 직접 연결된 비용을 확인한 뒤 수정 후보를 고른다. 반복 변동보다 작은 차이는 개선 확정으로 쓰지 않는다. 병목이 없으면 해당 구조 개선을 보류하고 측정 근거만 남긴다.

기존 [performance smoke](../scripts/performance-ui-smoke.cjs)는 1,000개 메시지·표시 페이지·delta IPC·용량 거절·동기 `store.save()` 시간 확인이다. 현재 `saveAsync()`의 복사/워커 지연을 모두 측정하거나 큰 이미지 내보내기를 비교하는 검사는 아니다. [resource smoke](../scripts/resource-smoke.cjs)는 Electron 자기 프로세스 CPU/메모리 표본이며 CLI·배터리 측정을 대신하지 않는다. [packaged resource wrapper](../scripts/packaged-resource-smoke.cjs)는 Electron으로 ASAR를 로드하므로 실제 서명된 `.app` 실행·알림·플랫폼 수용과 구분한다. [timing smoke](../scripts/timing-ui-smoke.cjs)는 테스트 CLI의 단계 계산·FIFO·화면 ACK 계약을 확인한다.

기존 검사 스크립트에 필요한 계측과 원자료만 추가하는 것을 우선한다. 테스트용 계측을 일반 사용자 UI에 노출하지 않는다. 체험/테스트 CLI 성능과 실제 CLI 연결의 자원을 구분하고, 실제 모델을 호출하지 않아도 가능한 측정부터 수행한다.

## 7. 후속 4 — 확인된 병목만 최소 수정

아래는 착수 후보 순서다. 모든 후보를 자동으로 수정하지 않는다. 측정한 병목이 다른 곳이면 실제 영향 순서로 조정한다.

| 후보 | 적용 조건과 작업안 | 보존할 계약·예외 | 필요한 검증 |
|---|---|---|---|
| 대화 내보내기 이미지 버퍼 | 최고 메모리에서 `copies` 보관 비용이 크면 검증한 이미지를 한 개씩 읽고 쓰도록 변경 | 대화 원문 snapshot, 최대 128MiB/256개, 누락 안내, wx·파일 identity·외부 파일 보존 | 상한/중간 쓰기 실패/변조/기존 폴더, 같은 자료 전후 메모리 |
| 원격 기록 검색 반복 | 턴별 `findIndex`가 병목이면 함수 안에 turnId/사용자 itemId 인덱스를 한 번 구성 | 중복 ID 거절·기존 텍스트 fallback의 순서·첨부/말투/목적/이미지 보존 | 같은 문장 반복, ID 없는 과거 기록, review 출력·실패 턴·큰 기록 |
| 내보내기 취소 전 사본 | 사본 비용이 확인될 때만 복사 시점 개선 검토 | 현재 요청 시점 snapshot 의미를 먼저 명문화. 대화상자 중 변경을 새 기록으로 조용히 바꾸지 않음 | 취소/대화 전환/스트림 갱신/삭제 중 결과의 일관성 |
| 동기 기록 읽기·parse | main 지연 원인이 확인되면 해당 읽기/parse를 비동기 또는 저장 경계의 작업으로 처리 | 소유 ID·no-follow·UTF-8·크기 상한·정제·저널·열기 실패 복구 | 읽는 중 교체/손상/초과, 빠른 취소·창 파괴·기록 전환 |
| 저장 data 복사 | postMessage 지연이 크면 필요한 저장 snapshot 범위·반복 전송을 줄이는 방안 검토 | 접수/완료 원자성, registry revision, 직렬 저장·쓰기가 불확실하면 차단 | 연속 접수·저장 실패/시간 초과·worker exit·정상 종료 복구 |
| 숨김/정숙 자원 | 반복 계측에서 timer/IPC/프레임 작업이 원인이면 해당 경로만 조정 | 숨김 복귀·상태 최신성·reduced-motion·읽음 억제·포인터 클릭 통과 | 표시/숨김/잠금/절전 반복과 같은 조건 자원 비교 |

내보내기를 순차 쓰기로 바꾸면 메모리는 줄어도 실패 시 사본 일부가 남을 수 있다. 실제 만든 파일의 이름과 identity를 추적해 안전하게 처리하거나 현재의 부분 사본 안내를 유지한다. 사용자 선택 폴더를 재귀 삭제하거나 외부 파일을 지우는 방식으로 rollback하지 않는다. 출력 Markdown과 이미지 참조의 일치, 데이터 누락 표시가 완료 조건이다.

동기 읽기의 경우 `fs.promises`로 바꾸기만 해도 JSON parse는 main에 남는다. 병목 단계에 맞춰 판단한다. 현재 저장 워커의 단일 요청·응답 수명에 읽기 응답을 무작정 추가하면 쓰기 ACK와 혼동할 수 있으므로, 요청 식별·응답 종류·직렬 순서·종료 정책을 먼저 설계한다. 기존 모듈 내부를 우선하며 다른 검증 책임이 생길 때만 분리한다.

각 후보는 한 변경 단위로 수행한다. 실패 재현 또는 계측 → 최소 수정 → 해당 예외 회귀 → 같은 조건 비교 → 코드·주석 재검토의 순서다. 저장 포맷 변경·SQLite 도입·React/Tauri 전환·worker 풀은 이 계획의 기본 해법에 포함하지 않는다. 별도의 수요·비용 근거가 생기면 재평가한다.

## 8. 후속 5 — CLI 페이지 조회와 기록 보존

**분석.** 현재 [load-older](../src/main.cjs:751)는 이미 메모리에 있는 기록의 화면 표시 범위를 늘린다. [open-conversation](../src/main.cjs:881)은 `thread/read(includeTurns:true)`로 전체 원격 기록을 가져온다. 원격 페이징만 바꾸어도 로컬 JSON 전체 읽기 비용은 그대로 남을 수 있어 C07과 효과를 나누어 측정해야 한다.

설치 CLI에서 생성한 [ThreadReadParams](../artifacts/onboarding-protocol-schema/v2/ThreadReadParams.json), [ThreadTurnsListParams](../artifacts/onboarding-protocol-schema/v2/ThreadTurnsListParams.json), [ThreadTurnsListResponse](../artifacts/onboarding-protocol-schema/v2/ThreadTurnsListResponse.json), [ThreadItemsListParams](../artifacts/onboarding-protocol-schema/v2/ThreadItemsListParams.json)를 확인했다. `thread/read`에는 cursor가 없다. 턴 페이지 조회에는 `cursor/limit/sortDirection/itemsView`가 있고 기본 itemsView는 summary다. 항목 페이지는 별도 cursor/turnId를 사용한다. 해당 설치 스키마가 다른 CLI 버전/제공자의 지원을 보장하지 않는다. 현재 main은 이미 experimentalApi 협상을 사용하므로 협상 옵션을 새로 추가하는 작업으로 착각하지 않는다.

### 구현 전 확정할 계약

- 한 페이지가 전체 대화 완료를 뜻하지 않는다. `notLoaded/summary/full`과 다음 cursor 유무를 구분한다. 요약 항목을 전체 항목으로 간주해 이미지·review·첨부·사용자 원문을 덮지 않는다.
- 초기에는 최신 일부를 읽고 필요한 이전 내용만 가져오는 방식과 `itemsView:full`/항목 페이지 조합을 합성 큰 기록으로 비교한다. 모든 페이지를 한 번에 배열로 모으는 방식은 전체 최고 메모리를 줄였다고 주장할 수 없다.
- 원격 페이지가 부분이어도 소유 로컬 기록을 보존한다. 현재의 전체 기록 건수 비교를 페이지 완료 판단에 재사용하지 않는다. merge는 turnId/itemId 중심으로 하고 중복 제거·시간 순서·같은 문장 반복·기존 metadata 보존을 검증한다.
- cursor는 불투명한 값으로 취급한다. 같은 cursor 반복·빈 페이지와 다음 cursor·방향 변경·겹치는 anchor를 처리하고 호출/메모리 상한을 둔다. turn/items의 서로 다른 cursor 형식을 혼용하지 않는다.
- 페이지 응답은 현재 대화·프로세스·조회 세대에 맞을 때만 적용한다. 대화 전환/삭제/연결 변경/창 종료/취소 후의 응답을 버린다. 페이지 로딩 중 새 질문과 변경 action의 허용 범위를 명시한다.
- 명시적인 API 미지원이면 기존 전체 조회 fallback을 검토한다. 잘못된 데이터·과대 프레임·권한·파일 손상은 무제한 전체 재조회로 우회하지 않고 기존 로컬 기록과 오류 안내를 유지한다.

진행 순서는 **모의 페이지와 병합 회귀 → 설치 CLI의 소유 기록 읽기 지원 확인 → 큰 기록 전후 비교 → UI 이전 내용 요청 연결**이다. 지원 확인만으로 새 모델 턴을 시작하지 않는다. schema와 실제 응답이 다르면 호환 상태·fallback을 남긴다. 개선 효과가 없거나 안전한 기록 보존을 입증하지 못하면 전체 조회 정책을 유지하고 보류 이유를 기록한다.

완료 조건은 로컬/원격 텍스트·이미지·원문·말투·목적·상태의 보존, 중복/순서/누락 회귀 통과, 구형 CLI 실패 대응, 대화 전환 후 오래된 응답 미적용, 최대 메모리/열기 지연 비교다. 디스크 기록을 페이지 포맷으로 바꾸는 일은 별도 설계다.

## 9. 후속 6 — 표시 의미와 입력 상태

**읽음.** 현재 [ACK](../src/ui/renderer.mjs:96)는 최신 완료 답변의 실제 화면 교차와 첫 이미지 미리보기 준비/실패를 확인한다. 모든 이미지와 모든 글을 읽었다는 추적 기능은 아니다. 다른 대화·숨김·설정 탭·잠금·이미지 pending·스크롤 밖에서는 읽음 처리하지 않는 현재 계약을 우선 유지한다. 여러 이미지 수용에서 표현이 오해를 유발하면 안내와 정책을 먼저 정하고 해당 경로만 변경한다. 이미지 실패 안내를 표시한 것과 이미지 원본 확인 성공은 별도로 기록한다.

**입력 전이.** 일반 초안, 첨부 가져오기/제거, 전송 접수, 편집 진입, 편집 중, 편집 저장, 취소, reload, 저장 차단 상태의 허용 action을 표로 만든다. boolean을 새 enum/프레임워크로 일괄 치환하는 작업으로 확대하지 않는다.

| 경계 | 유지해야 할 결과 |
|---|---|
| 편집 진입의 첫 await 전 | 충돌 입력 잠금·대상/예약 소유. 일반 초안 snapshot은 실제 전환 시점 |
| 첨부 가져오기/제거 대기 | 다른 편집/첨부 입력/접수 충돌 차단. 오류 callback이 다른 작업의 잠금을 해제하지 않음 |
| 전송 중 다음 글 입력 | 이미 접수한 질문과 다음 초안 분리. 새 대화 ID 이전 후에도 초안 보존 |
| 편집 대상 취소·대화 변경·reload | 늦은 응답 적용 금지, 자신의 예약만 해제, finally로 UI 잠금 복구 |
| 저장 실패·worker 불확실 | 새 실행 차단·기록/저널 보존. 취소·승인 제어 경로는 검토 없이 함께 막지 않음 |
| 동시 큐 접수 | preparing+queued 합계 10 이하, 순서/모델/자료 snapshot 유지 |

**사용량과 작업 상태.** 한도 조회의 항목별 시점과 stale 표현, 모델/제공자 미지원 상태, 누적/최근 턴 토큰을 확인한다. 누적 토큰을 현재 문맥 점유율로 표시하지 않는다. 지원되지 않는 모델·승인/추가 질문 UI는 모의 성공을 실제 제공자 수용으로 확대하지 않는다. 향후 steer는 FIFO와 동작이 다르므로 별도 기능 요구로 남긴다.

산출물은 전이표·회귀 대응표·표시 의미 정리다. 이미 통과한 회귀를 복제하지 않고 새 조합이나 재현한 오류에만 필요한 검사를 추가한다.

## 10. 후속 7 — 주석·데드 코드·문서·제거

현재 alpha17 변경에 완료된 TODO나 새 lint 억제가 확인됐다는 근거는 없다. 불필요한 helper를 새로 만들어 다시 통합하는 방식도 쓰지 않는다. 수정 함수마다 아래 기준으로 확인한다.

| 대상 | 실제 확인 방법 | 제거/통합 조건 |
|---|---|---|
| 주석 | 구현·호출 순서·예외 처리와 대조, TODO/FIXME·주석 처리 코드·lint 억제 검색 | 끝난 작업 지시/틀린 설명/코드 반복 설명은 삭제. 수명·소유권·OS 제한의 이유는 유지 |
| 함수·지역 변수 | import/export·이벤트·IPC·fixture·패키징 참조 확인 | 실제 미사용 또는 중복일 때만 제거. 호출 수 1개만으로 검증 경계를 합치지 않음 |
| 조건 중복 | 같은 함수의 동기 처리와 책임 비교 | 동일 상태 갱신만 인라인 통합. 다른 await 전후 검사는 시간 경계가 다르므로 유지 |
| 과거 metadata | 저장 포맷·기존 대화 복원·내보내기 회귀 확인 | 과거 기록의 호환 읽기를 현재 UI 미사용만으로 삭제하지 않음 |
| 문서 | 현재 규격/상태/검증 시점/결과 링크 대조 | 현재 목록은 현재 문서에, 날짜별 실패·검사·결정은 이력에 유지. 새 검증 수로 과거 수치를 덮지 않음 |
| 산출물 | 실행 중 프로필·현재 후보·롤백·원자료·개인 자료 식별 | 재생성 가능한 중복만 후보. 최종 증거·실패 로그·개인 이미지·복구 묶음 보존 |

Electron/Markdown 정제/CJK/번들러와 현재 JSON 저장·팩 데이터 경계의 선택 이유는 [제품 검토](BUDDY_PRODUCT_REVIEW_2026-10-10.md)에 유지한다. 계측 근거 없이 dependency 삭제·일괄 버전 상승·저장소 교체를 정리 항목에 넣지 않는다. lint/check 실패나 정제·경로 보안 회귀를 억제 주석으로 숨기지 않는다.

## 11. 후속 8 — 플랫폼과 배포

새 Mac 최초 연결은 후속 1에서 먼저 확인한다. 아래는 해당 대상 환경을 확보했을 때 수행할 나머지 수용이다.

| 대상 | 확인할 사항 | 완료 주장에 필요한 증거 |
|---|---|---|
| macOS Apple Silicon | 실제 후보 실행·IME·클립보드·알림·절전·모니터/Spaces·트레이/타일링 | 실제 OS 버전·앱 버전·실기 수용표 |
| Intel Mac | 대상 런타임 설치·빌드·실행·CLI·팩 decode | 그 아키텍처의 실행/패키지 결과. arm64 결과로 대체하지 않음 |

플랫폼 고유 문제는 기존 프로세스·파일·창 모듈에서 원인을 확인한 뒤 최소 분기를 추가한다. OS 차이를 가리는 범용 추상화부터 만들지 않는다. 설치 프로그램·업데이트 채널·공개 배포는 대상과 배포 정책이 정해진 후 범위를 확정한다.

## 12. 예외 상황의 공통 완료 조건

| 예외 | 필수 결과 | 재검토할 경계 |
|---|---|---|
| 연결/계정 교체 후 늦은 응답 | 이전 기록·한도·모델 응답이 새 수명에 적용되지 않음 | process·account revision·조회 세대 |

예외 처리 뒤 다시 시도할 수 있는지도 확인한다. 정상 성공만 확인한 검사를 전체 예외 수용으로 쓰지 않는다.

## 13. 검증·전달과 첫 작업 묶음

문서만 바꾼 이번 작업에서는 제품 검사를 다시 실행하지 않는다. 계획의 파일/줄 링크, 기존 증거와 현재 소스의 일치, 완료/미검증/조건부 표기를 검토한다.

다음 코드 작업은 해당 범위 검사부터 실행한다. 모의 연결은 `test/connection-images.test.cjs`, 저장/입력 수명은 `test/stability.test.cjs`, 첨부·보관은 `test/attachments.test.cjs`와 기존 fixture를 우선한다. 새로운 비용 검증은 기존 performance/resource 스크립트에 보완하고 실제 필요한 실패 조합만 추가한다.

변경된 범위가 통과하면 `npm run lint`, `npm run check`, `npm test`, 관련 격리 통합을 수행한다. 배포 후보를 만드는 단계에서는 전체 `npm run smoke:integration` 14종, 번들/워커/자산을 포함한 `npm run verify:package`, 해당 플랫폼 서명 검사를 수행하고 소스/번들 해시를 기록한다. 현재 117/14/84는 출발점 수치이며 새 검사 추가 후에도 이 수로 고정해 작성하지 않는다. 실패한 검사와 성공한 재검사를 날짜·소스별로 구분한다.

모델을 호출하지 않는 지원 조회와 실제 모델 질문을 구분한다. `smoke:real`, `codex:attachments`, 실제 modes/persona 검사 등은 기본 회귀 묶음에 자동 편입하지 않는다. 필요한 실제 질문의 모델·내용·횟수·비용 범위를 분명히 정하고 실행 결과를 별도로 남긴다. 성공 프로필은 결과를 보존한 뒤 정리하고, 실패 프로필은 진단 자료로 유지한다. 실제 인증·개인 경로·대화 내용은 공유 보고서에 복제하지 않는다.

**바로 착수할 첫 작업 묶음**은 다음과 같다.

1. alpha17/build33 기준과 기존 앱/복구 경로를 확인하고, 독립 테스트 프로필·합성 자료·OS 수용표를 준비한다. 입력 상태 전이와 기존 회귀 대응표를 작성한다.
2. 기존 테스트 CLI로 최초 연결·첨부/이미지·큐 편집 흐름을 확인하고, 실제 가능한 OS 입력·알림 수용을 진행한다. 환경이 없는 새 계정/다른 OS는 미검증으로 남긴다.
3. 기존 계측 스크립트에 saveAsync의 main 복사 비용·이벤트 루프 지연·대화 내보내기 최고 메모리 수집을 추가한다. 일반 UI와 런타임 의존성을 늘리지 않는다.
4. 같은 환경의 원자료를 분석해 후속 4 후보 중 실제 영향이 큰 한 건을 선정한다. 병목이 입증되지 않으면 제품 코드를 변경하지 않고 측정 결과를 보고한다.

첫 묶음의 산출물은 실행 환경/해시, OS 수용표, 입력 전이·회귀 대응표, 성능 원자료/분석, 최소 수정의 착수 근거다. 새로 재현한 데이터 손실·오접수가 있다면 성능 작업보다 먼저 해결한다. 설치 프로그램·steer·음성·기억·3D 캐릭터를 이 묶음에 함께 넣지 않는다.

무료 에셋 11개 사이트의 적용 판단과 팩 제작 순서는 [기존 버디 로드맵](BUDDY_ROADMAP_2026-10-10.md)에 유지한다. 사이트가 무료라는 이유만으로 개별 자산의 재배포 권한을 가정하지 않는다. 외부 자료를 실제 채택할 때 정확한 자산 라이선스·출처를 확인하고 먼저 데이터형 팩 한 개로 decode·상태·배율·메모리를 검증한다. 팩 오디오와 외부 효과음은 현재 OS 알림 소리 옵션과 별개다.
