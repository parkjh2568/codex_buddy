# 이미지·파일 첨부와 선입선출 적용 기록

2026-10-10, alpha.14/build29, macOS arm64. 이미지/파일 첨부와 작업 중 추가 질문의 대기열을 구현했다. 기존 연결 복구·생성 이미지 표시·사용자 기록 처리를 함께 유지한다.

## 확인한 사항과 작업 순서

기존 일반 대화에는 단일 실행·최대 10개 대기·접수 순서 예약·취소·종료 저장이 있었지만 미니 창의 전송을 막고 있었다. CLI 입력도 사용자 텍스트만 지원했다. 별도 실행 큐를 추가하면 순서·취소·저장이 중복될 수 있어 기존 접수/실행 큐를 확장했다.

1. 설치된 CLI 0.162.0-alpha.2의 스키마와 [공식 App Server 입력 형식](https://learn.chatgpt.com/docs/app-server)을 확인했다. 이미지에는 `localImage`를 사용한다. 일반 파일은 보관 사본의 경로/이름을 추가 텍스트 자료로 전달해 CLI의 읽기 도구가 읽게 한다. 앱/커넥터의 mention을 파일 입력으로 쓰지 않는다.
2. 사용자 선택 파일의 검증·불변 사본·해시 조회를 `AttachmentStore`에 구현했다. 기존 이미지 decode/미리보기 저장 경계를 재사용했다.
3. 선택·미리보기·제거·채팅 표시·저장/재로드를 연결했다. renderer가 임의 원본 경로를 전달하는 API는 추가하지 않았다.
4. 기존 FIFO에서 질문·첨부·모델·말투를 함께 고정하고 미니 창의 전송 제한을 제거했다.
5. 실패·취소·원본 변경·참조 소유권·용량 경계, 실제 CLI 입력, UI 회귀와 패키지를 검증한 뒤 앱을 적용했다.

## 사용 방법

입력창의 `이미지 첨부` 또는 `파일 첨부`로 하나 이상 선택한다. 전송 전 이미지 미리보기와 파일 이름을 확인하고 `×`로 제거할 수 있다. 질문과 함께 보내거나 첨부만 보낼 수 있다. 첨부만 보내면 `첨부한 자료를 확인해주세요.`로 질문한다.

진행 중에도 일반/미니 창에서 다음 질문을 보낸다. 대기줄에 순서·질문·첨부 개수를 표시하며 `1번 취소`처럼 개별 취소할 수 있다. 앞 작업의 완료/중단 저장이 끝난 뒤 다음 질문을 실행한다. 보낸 질문의 첨부는 다음 입력창의 첨부와 분리한다.

채팅의 이미지 카드에서는 `원본 열기`, 파일 카드에서는 `저장본 위치`를 사용한다. 후자는 파일을 실행하지 않고 보관된 파일 위치를 보여준다. 대화를 다시 열어도 참조와 첨부를 유지한다. 체험 모드는 첨부를 실제 모델에 보내지 않는다.

| 한도 | 현재 동작 |
|---|---|
| 첨부 수 | 질문당 최대 8개 |
| 파일 크기 | 각각 16MiB, 합계 32MiB; 빈 파일은 거절 |
| 이미지 | PNG/JPEG/WebP, 한 변 4096px·16MP 이하 |
| 미리보기 | 최대 512px PNG, 원본 바이트는 보존 |
| 대기열 | 실행 중인 질문 외 최대 10개, 접수 중인 예약 포함 |
| 보관 용량 | 일반 파일 사본 512MiB, 이미지 보관 512MiB; 잔여 파일도 계산 |

실제 텍스트 파일 읽기와 이미지 색상 식별을 검증했다. PDF/Office/압축 등 임의 형식 전체의 해석 성공은 보장하지 않으며 CLI 도구·환경·모델의 읽기 결과를 따른다. 보관 사본/생성 이미지 캐시는 대화 삭제 후에도 남는다. 자동 캐시 정리 UI는 구현하지 않았으며 앱 기록 폴더에서 관리할 수 있다. 원본 파일은 변경하거나 삭제하지 않는다.

## 구조·실패 처리

`attachments.cjs`는 선택한 파일의 디스크/검증 경계만 담당한다. 입력창·IPC·접수 예약·실행 순서·취소는 기존 함수 안에 인라인으로 유지했다. 일반 파일은 SHA-256과 확장자로, 이미지는 기존 이미지 라이브러리로 보관한다. 대화에는 파일명·바이트·치수·해시 참조만 기록하고 base64나 사용자의 원본 경로는 기록하지 않는다.

선택창은 메인 프로세스가 열며 임시 ID를 활성 대화에 연결한다. 첫 await 전에 ID와 대기 자리를 예약하므로 동시에 접수해도 같은 첨부를 중복 소모하지 않는다. 저장 후 ID가 생성되는 새 대화에는 첨부 초안을 함께 이전한다. 전송 성공 시 보낸 첨부만 초안에서 제거하고 실패하면 초안을 유지한다.

선택/조회에서 일반 파일·링크·경로·해시·크기 상한을 확인한다. 파일을 읽는 도중 커져도 제한된 버퍼만 읽으며 변경된 사본은 실행 전에 거절한다. 사본 쓰기는 배타 임시 파일과 확정 경로를 사용한다. 이미지 헤더 검사 뒤 격리 decode하며 실패한 입력을 모델에 전달하지 않는다. 폴더 오류·불완전 저장·외부 참조·없는 사본은 오류로 처리하고 텍스트 기록과 원본을 보존한다.

질문마다 첨부/모델/말투를 고정하고 큐에서 앞 항목만 꺼낸다. 종료 저장 중에도 취소를 처리한다. 취소한 대기 질문은 남은 순서에 영향을 주지 않으며 실행하지 않는다. 연결 중단·절전·저장 실패 뒤 대기열은 멈추고 기존 복구 정책을 따른다. 앱 재시작의 불확실한 요청은 중단 상태로 보존하며 자동 실행하지 않는다. 기존 기록 재조회는 자동 첨부 안내가 사용자 원문을 덮어쓰지 않도록 첫 사용자 텍스트와 기존 참조를 병합한다.

UI에서는 첫 작업을 잡아 둔 채 미니 창으로 두 질문을 대기시키고 순서대로 겹치지 않게 실행했다. 추가 대기 질문의 취소, A/B 파일 사본의 분리, 이미지 미리보기, 전송 전 제거, 첨부 단독 전송, 기록 재조회/Store 재로드를 확인했다. 실제 모델 검증에는 자체 생성한 작은 색상 이미지와 임의 표식 파일만 사용했다. 사용자 기존 대화나 파일을 모델에 재전송하지 않았다.

## 전달과 남은 검증

최신 일반 실행 앱은 `dist/OnggiBot-darwin-arm64/OnggiBot.app`, staging도 동일한 alpha.14/build29이다. 실행 중인 OnggiBot이 없는 것을 확인한 뒤 전체 앱을 적용했다. 이전 앱은 `dist/OnggiBot-darwin-arm64/OnggiBot-build28-before29.app`, 그 이전 build26은 `OnggiBot-build26-before28.app`에 보존했다. 사용자 프로필·원본 파일·Codex 인증 파일을 직접 편집하지 않았다. 설치 경로의 최종 일치는 `installed-package-verification.json`을 따른다.

테스트 UI의 OS 파일 선택/외부 열기는 대역을 사용했다. 실제 OS 선택창/파일 연결 프로그램 클릭, Windows 실기·한글/공백 경로의 Windows 동작·DPI/IME·실제 잠금/절전은 미검증이다. 앞선 macOS 네이티브 UI 도구의 시간 초과와 별개로 격리 Electron UI 및 패키지 코드 검사는 완료했다. 서명/공증·설치 프로그램·자동 업데이트, 모든 문서 형식 호환, 원격 캐시/공용 FIFO 서버를 완료했다고 표현하지 않는다.

이전 연결 복구·브라우저 로그인·이미지 수신의 상세 범위는 [alpha.13 적용 기록](CONNECTION_AND_IMAGES_2026-10-08.md)을 참고한다. 해당 기록의 build28 경로는 당시 전달 결과이며 현재 실행 앱은 build29이다.
