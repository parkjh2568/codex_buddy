# Markdown과 모델 설정 확인·반영

2026-10-06, Codex CLI 0.160.0에서 확인하고 alpha.2부터 반영했으며 alpha.5에서 Fast와 자동 갱신, 입력창 밖 배치를 추가했습니다.

사용자 지정 앱 기본값: `gpt-5.6-luna / high`. Codex 전역 설정의 기본값과 별도로 앱 자체 설정에 저장합니다. 기존 alpha.1 기록의 대화·캐릭터 설정을 유지하고 새 모델 설정 필드에 이 기본값을 적용합니다. 이후 사용자가 직접 고른 모델·추론 값은 재실행에도 보존합니다.

## Markdown

기존 alpha.1은 응답을 일반 텍스트로 표시했습니다. alpha.2는 답변에 Markdown을 적용합니다. 원문은 그대로 저장하며 전체 복사도 원문을 사용합니다. 사용자 질문·오류·승인 내용은 일반 텍스트입니다.

지원: 제목, 굵게/기울임/취소선, 순서/비순서 목록, 인용, 구분선, 인라인 코드, 코드 블록, 표, HTTP/HTTPS 링크. 코드 블록에는 코드만 복사하는 버튼이 있습니다. 표와 긴 코드는 가로 스크롤합니다.

markdown-it 15.0.2를 HTML 비활성으로 사용하고 DOMPurify 3.4.16로 허용 태그·속성만 남깁니다. 한국어 괄호·조사 경계의 강조(`**…(…)**는`)를 지원하기 위해 markdown-it-cjk-friendly 3.0.0을 적용합니다. npm 의존성과 렌더러를 esbuild로 묶어 로컬에서 로드합니다. CDN에 의존하지 않습니다. 이미지 자동 로딩, 임의 HTML, JavaScript/file/data URL은 허용하지 않습니다. 웹 링크는 클릭 시에만 시스템 브라우저로 엽니다.

50ms 화면 갱신에서 내용이 바뀐 답변만 다시 렌더링합니다. 미완성 코드 블록도 표시하고 완료 시 다시 해석합니다. 100,000자 응답 상한은 기존 알파와 같습니다. 코드 구문 강조, 수식, 실제 체크박스는 후속 확장입니다.

## 모델·추론 변경법

1. 일반 실행으로 옹기봇의 대화창을 엽니다. 체험 모드에서는 모델 호출과 선택이 비활성입니다.
2. 질문 입력 박스 안쪽 하단 오른쪽의 모델 버튼을 눌러 팝업에서 모델을 선택합니다. 같은 줄 왼쪽은 말투 선택입니다.
3. 추론 선택에는 해당 모델이 지원하는 단계만 표시됩니다. 모델을 바꾸면 추론 선택은 기본으로 돌아갑니다.
4. 속도에서 Standard 또는 CLI가 제공한 Fast를 선택합니다. 앱 기본 속도는 Standard이며 Fast는 사용량이 증가합니다.
5. 질문을 보냅니다. 응답 위에 전송한 모델·추론 단계·Fast 설정이 기록됩니다.
6. CLI 기본 설정으로 돌아가려면 모델을 `CLI 기본값`, 추론을 `기본 추론`으로 선택합니다.
7. CLI 설정을 외부에서 바꿨거나 목록을 다시 읽으려면 `↻`를 누릅니다.

모델 변경은 현재 대화를 유지하고 다음 질문부터 적용합니다. 진행 중이거나 이미 대기 중인 질문은 전송 때의 설정을 유지합니다. 모델 제공자·로그인·API 키는 CLI가 관리하며 앱에서 변경하지 않습니다. 사용자의 전역 Codex 설정 파일도 수정하지 않습니다.

## 기본값 의미

| 선택 | 적용 |
|---|---|
| CLI 기본값 + 기본 추론 | config/read의 모델·추론 설정 |
| 지정 모델 + 기본 추론 | 그 모델의 defaultReasoningEffort |
| 지정 모델 + 지정 추론 | 두 값을 검증해 turn/start에 전달 |
| CLI 기본값 + 지정 추론 | CLI 모델과 지정 추론 |

CLI에 모델 설정이 없으면 목록의 기본 모델, 추론 설정이 없으면 선택 모델의 기본 추론을 사용합니다. 기본값 복귀 때도 실제 값을 명시해 이전 질문의 모델 override가 남지 않게 합니다.

이번 PC에서 CLI 설정은 `gpt-6.1-sol / high`이고 같은 모델의 카탈로그 기본 추론은 `low`였습니다. 따라서 CLI 설정의 기본값과 모델 자체 기본값을 구분합니다. 모델 목록과 지원 단계는 하드코딩하지 않습니다.

모델 목록은 계정·제공자·CLI 버전에 따라 달라질 수 있으며, 목록에 있다는 사실만으로 실제 실행 권한을 보장하지 않습니다. 선택 모델이 사라지거나 추론 단계가 지원되지 않으면 오류를 표시하고 자동으로 다른 모델을 선택하지 않습니다.

## 모델 목록 자동 갱신과 Fast

모델 ID·표시 이름·설명·추론 단계·속도 ID/이름/설명은 `model/list`의 응답에서 가져옵니다. CLI 설정의 모델·추론 기본값은 `config/read`를 읽습니다. 앱에서 사용자가 선택한 `gpt-5.6-luna / high`는 별도 기본값입니다. Standard는 앱의 일반 속도 선택입니다. 모델 목록은 CLI의 카탈로그이므로 사용 권한·서버 제공 상태를 보장하지 않습니다.

기존 버전은 최초 연결과 수동 `↻`만 갱신했습니다. alpha.5는 대화창 열기·포커스·모델 선택 영역 접근·질문 전송 때 캐시가 5분 이상 지나면 다시 조회합니다. `↻`는 즉시 재조회합니다. 백그라운드에서 5분마다 계속 모델을 호출하는 동작은 없습니다. 조회에는 추론 호출이 필요하지 않습니다.

CLI 실행 파일의 경로·파일 ID·크기·수정 시각이 바뀌면 캐시가 신선해도 유휴 상태에서 기존 app-server를 종료하고 새 파일로 연결합니다. 저장된 대화 ID는 유지하고 다음 질문에서 재개합니다. 실행·대기 중인 질문이 있으면 재시작을 미뤄 현재 요청을 보호합니다. 앱이 CLI 소프트웨어 자체를 자동 설치하거나 업데이트하지는 않습니다. 새 목록은 선택한 CLI가 실제로 반환하는 범위 안에서만 표시됩니다.

설치 CLI 0.160.0은 7개 모델에 `serviceTiers: [{id: "priority", name: "Fast", ...}]`를 반환했습니다. UI는 이 ID를 읽어 `turn/start.serviceTierForTurn`에 질문마다 전달합니다. Standard는 스키마가 지정한 `default`를 명시하여 이전 Fast가 남지 않게 합니다. 추론 단계를 낮추거나 모델을 바꾸는 방식이 아닙니다. 미래 CLI가 다른 속도 ID/이름을 반환해도 목록에서 읽습니다. 필드가 없는 이전 CLI에는 Fast를 임의로 표시하지 않습니다.

모델·추론·속도는 질문 접수 시 큐에 고정합니다. 이미 대기 중인 질문에 나중 설정을 소급하지 않습니다. 새 모델에서 기존 속도가 미지원이면 모델 변경 시 Standard로 돌아갑니다. 저장한 속도가 갱신된 목록에서 사라지면 미지원 표시와 오류를 내며 사용자가 속도를 다시 선택합니다.

[공식 Speed 문서](https://learn.chatgpt.com/docs/agent-configuration/speed)는 Fast 사용량 증가와 모델·계정·워크스페이스에 따른 지원 차이를 설명합니다. 실제 응답 속도 향상이나 서버가 사용한 최종 등급을 이 알파에서 측정·보장하지 않습니다.

## 검증 범위

`smoke:models`는 카탈로그/기본값·Fast·질문별 스냅샷·자동 갱신/포커스·대화 유지를, `smoke`는 Markdown 보안/미완성 코드/복사를 확인한다. 실제 Luna/high 응답·Fast 요청과 당시 CLI 모델 7개 조회는 [검증 이력](history/MEASUREMENTS_BEFORE_CLEANUP_2026-10-10.md)에 보존한다. 모든 모델의 실행 권한·최종 서버 등급·속도 향상을 보장하지 않는다.

근거: [OpenAI App Server](https://learn.chatgpt.com/docs/app-server), [markdown-it](https://markdown-it.github.io/markdown-it/), [DOMPurify](https://github.com/cure53/DOMPurify).

캐시를 가진 자동 갱신 중 선택 메뉴를 비활성화하지 않고, 모델 메뉴에 포커스가 있으면 옵션 교체를 나중으로 미룹니다. 포커스를 벗어나면 받은 목록을 반영합니다. 수동 새로고침은 명시적인 재조회로 기존 로딩 표시를 사용합니다.
