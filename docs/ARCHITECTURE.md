# 개발 구조

macOS·Windows 환경 준비, 빌드 명령과 결과물, 플랫폼별 검증·배포 범위는 [빌드 가이드](BUILD_GUIDE.md)를 참고한다.

alpha.15의 [기능 도입 기록](history/BUDDY_EXPANSION_RESULT_2026-10-10.md), alpha.16의 [예외 수정 결과](history/CHANGE_REMEDIATION_RESULT_2026-10-10.md), alpha.17의 [품질 개선과 재검토](history/QUALITY_CYCLE_RESULT_2026-10-10.md)에 첨부 입력·큐 편집·알림·이미지 활용·대화 metadata·목적/스킬·사용량의 수명과 검증을 기록했다. 아래 기존 모듈 경계를 확장했고 별도 큐/클립보드 프레임워크는 만들지 않았다.

계정 사용량 조회는 프로세스와 상태 revision을 확인해 오래된 응답을 적용하지 않는다. 이미지 조회는 검증한 바이트·파일만 반환하고 미리보기 IPC에서만 base64를 만든다. 스킬 목록 파일은 비동기로 제한 읽기하며 조회 중 연결·폴더·목록 변경을 확인한다. 렌더러의 읽음 ACK는 메시지 영역과의 실제 교차·미리보기 준비를 확인하고, 진행 정보와 큐는 값 변경 때만 갱신한다. 예약된 상태 전송은 종료·창 파괴를 다시 확인한다.

alpha20은 시간 ACK도 대화·카드·완료 시각·예약 토큰을 소유하며 대화 reset에서 이전 카드의 image observer를 해제한다. 검색어 변경은 메인 검색 revision을 취소하고 저장 대기를 우회해 이전 결과와 후속 읽기를 버린다. 선택형 캐시 보관/복원은 전체 참조·파일 identity·크기/해시·복구 manifest와 창 generation/작업 revision을 확인한다. 공유 참조·불확실한 기록·사용자 변경·기존 복원 대상은 보존하며 파일 사이에 이벤트 루프를 양보한다. [적용 결과](history/FINAL_IMPLEMENTATION_RESULT_2026-10-13.md)를 따른다.

alpha.17에서는 계정/연결 수명과 같은 계정의 항목별 이벤트를 구분해 사용량을 병합한다. 편집 진입과 첨부 제거가 끝날 때까지 충돌하는 입력을 잠그며 일반 초안은 전환 시점에 보존한다. 저장용 이미지는 대화상자 이후에만 원본을 재검증해 읽는다. 단축키 등록은 명시적 hotkey 요청에서만 수행한다.

alpha.18의 [후속 작업 결과](history/BUDDY_FOLLOWUP_RESULT_2026-10-10.md)는 인증 조회도 process/account revision으로 소유하고 로그인 완료의 계정 변경에는 한 번 재조회한다. 이미지 내보내기는 요청 시점 대화 사본을 유지한 채 원본 하나씩 검증·쓰기한다. 원격 기록의 이전 ID 연결은 함수 안의 지역 인덱스를 사용하며 검증을 마친 병합만 기존 저장 워커로 확정한다.

```text
캐릭터 창 ───┐
안내 말풍선 ─┼─ 좁은 preload IPC ─ main.cjs ─ codex.cjs ─ Codex app-server (stdio)
대화창 ─────┘                      │
                                 ├─ packs.cjs: 팩 검증·이미지 데이터
                                 ├─ connection-setup.cjs: CLI 탐색·버전·인증 시도 수명·정제한 계정 한도
                                 ├─ response-images.cjs: 응답 이미지 검증·원본/미리보기 보관
                                 ├─ attachments.cjs: 선택/드롭 파일과 클립보드 바이트의 불변 사본·조회 검증
                                 ├─ store.cjs: 설정·소유 대화 목록·대화별 파일
                                 └─ storage-maintenance.cjs: 전체 참조 확인·선택형 캐시 복구 보관/복원
```

Electron 44.5.1, 메인 프로세스는 Node 기반 CommonJS. 렌더러는 DOM/CSS/SVG를 사용하고 Node 통합을 끕니다. Electron context isolation과 renderer sandbox를 켜고 preload의 제한된 동작만 노출합니다. 원격 웹 콘텐츠를 로드하지 않습니다. 사용자의 입력은 `textContent`, 모델 출력은 markdown-it 15.0.2 + CJK 강조 플러그인 3.0.0의 HTML 비활성 파싱과 DOMPurify 3.4.16의 태그/속성 허용 목록으로 정제한 DOM fragment로 표시합니다. 렌더러 ESM 소스와 의존성은 esbuild로 로컬 파일 하나에 묶고 앱에 포함합니다. 실행·체험·검증·패키징 명령은 번들을 먼저 빌드합니다.

`models.cjs`는 model/list 페이지 처리, config/read의 CLI 기본값, 모델별 추론 호환성을 담당합니다. 메인 프로세스가 질문 접수 시 모델·추론 단계·서비스 속도를 해석해 큐와 메시지에 고정하고 `turn/start`에 명시합니다. 속도는 CLI의 `serviceTiers`에서 읽고 `serviceTierForTurn`에 요청별로 전달합니다. 모델 정보는 UI 접근 때 5분 캐시를 확인하며 실행 파일 변경 시 유휴 상태에서 연결을 재시작합니다. CLI 설정 파일을 쓰지 않습니다. 모델 목록은 실행 권한 검증을 대신하지 않습니다.

`main.cjs`가 프로세스·창·큐·설정의 소유자입니다. 한 질문을 실행하고 완료 또는 중단 상태가 확정되면 다음 질문을 실행합니다. 승인 응답과 중단 동작은 질문 FIFO에 넣지 않습니다. Codex 요청 ID와 대화/턴 ID를 사용해 응답을 연결합니다. 팩 교체는 이미지 데이터만 바꿉니다.

스토리지가 작아 알파에서 원자적 JSON 파일 교체를 사용합니다. 토큰마다 디스크에 쓰지 않고 질문 접수·완료·설정 변경 시 저장합니다. 스트리밍 화면 갱신은 50ms로 묶고 완료는 즉시 예약하며 큰 캐릭터 이미지는 카탈로그 변경/초기 연결 때만 전송합니다. 변경된 메시지만 Markdown을 다시 파싱합니다. 실행 중 메모리의 부분 응답은 비정상 종료로 손실될 수 있습니다. CLI가 보관한 대화 기록과 화면 기록은 별개입니다. v2는 소유 대화 목록과 대화별 파일을 분리하고 메시지가 바뀔 때만 해당 파일을 씁니다. 설정/위치만 바뀌면 대화 직렬화를 생략합니다. 캐릭터 창에는 전체 대화 대신 필요한 상태만 보냅니다. 목록/대화 교체는 저널로 묶어 프로세스 종료 시 복구합니다. 완전한 DB 트랜잭션·전원 장애 내구성을 보장하지 않습니다. 목록에 있는 threadId에 한해서 `thread/read`로 텍스트 기록을 확인하고, 다음 질문 때 `thread/resume`합니다. 자세한 저장·이관 범위는 [이전 대화](CONVERSATIONS.md)에 있습니다.

## 창 동작

기본 캐릭터 창은 120×143, 안내 창은 별도 196×52 논리 픽셀입니다. 상세 대화창은 460×740에서 시작하고 4모서리로 크기를 조절합니다. 최소 390×580을 사용하되 작은 작업 영역에서는 그보다 줄이며, 숨김·재열기 동안 상세 bounds를 메모리에 유지합니다. 심플은 기본 폭 360, 최초 높이 약 210에서 답변·입력에 따라 기본 최대 410까지 맞춥니다. 안내의 표시/숨김은 캐릭터 창 크기를 바꾸지 않습니다. 안내 전용 페이지는 Markdown 라이브러리나 캐릭터 이미지를 로드하지 않고 짧은 텍스트·팔레트만 표시합니다. 작은 화면에서는 대화창 크기를 줄입니다. 마우스 이동 시 즉시, 정지 상태에서는 80ms 간격으로 각 창의 실제 클릭 영역을 확인하고 여백의 클릭은 뒤쪽 앱으로 통과시킵니다. 보이지 않는 하단 버튼은 클릭 영역에서도 제외합니다. 안내 창에는 대화 열기·클릭 영역 갱신만 허용하며 설정/세션 작업은 거절합니다. 예전 250×270 위치 기록도 같은 캐릭터 기준점으로 변환합니다. 드래그는 시작 지점부터의 절대 마우스 좌표를 사용하고 포인터 캡처를 유지합니다.

참고: [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)의 `setBounds`와 `setIgnoreMouseEvents` 동작을 확인했습니다. 대화창은 화면 작업 영역 안에서 캐릭터 옆에 배치합니다. 캐릭터는 화면 경계의 강제 제한 없이 이동하며 안내 창 크기 변경에서도 캐릭터 앵커를 유지합니다. 재시작·화면 구성 변경에서 보이지 않는 캐릭터만 기본 위치로 복구하고 트레이에서 직접 초기화할 수 있습니다. macOS 전용 패널 옵션과 공통 동작의 구분, 실제 검증 범위는 [플로팅 보완](FLOATING_PET_UPDATE.md)을 참고합니다.

## 아이콘 재생성

`npm run icons:generate`는 사용자 원본 `assets/tray-source.png`를 보존하고 투명 여백만 제외해 그림을 중앙에 배치합니다. 앱 PNG·Windows ICO는 밝은 바탕에 같은 그림을 사용하고, 메뉴 막대 PNG는 투명을 유지한 18px/36px로 생성합니다. 앱 상단 로고는 이 이미지의 마스크와 스킨 색상을 사용합니다. 템플릿 표시는 macOS에서만 검증합니다. macOS에서는 `npm run icons:icns`가 sips와 iconutil로 필요한 해상도를 생성하고 `.icns`로 변환합니다.

현재 제공된 `.icns`는 이미 생성되어 있어 일반 빌드에서 다시 만들 필요 없습니다.

## 다음 확장

Slack 수신은 로컬 Socket Mode부터 시작할 수 있습니다. 지정 채널의 멘션·키워드를 먼저 필터링한 뒤 필요한 메시지만 의미 판단에 사용합니다. 알림 이벤트는 작업 큐와 별도로 전달해 긴 Codex 작업 뒤에 밀리지 않게 합니다. 아직 실행 가능한 Slack 모듈이나 서버 코드는 만들지 않았습니다.

캐릭터 팩 규격은 안정적으로 버전 관리하지만, 미래 확장을 위한 범용 플러그인 프레임워크는 만들지 않습니다. 새 입력 채널이 생길 때 실제 요구에 맞춰 경계를 확장합니다.

선택형 응답 측정은 메인 수신·CLI stdin 전송·첫 텍스트·턴 완료와 보이는 대화창의 프레임 ACK를 연결합니다. [측정 기준](RESPONSE_TIMING.md), [구조/코드 검토](PROJECT_REVIEW.md)를 참고합니다.

## 긴 기록 전송

패널에는 최근 최대 100개/256KiB 텍스트부터 보여 주고 ID 순서와 변경된 메시지만 전송합니다. 렌더러는 메시지/카드 Map을 유지하고 이전 내용을 요청하면 추가합니다. alpha22부터 등록된 원격 대화를 열 때 metadata ID를 확인하고 최신 full 25턴 한 페이지만 가져옵니다. `이전 내용`은 먼저 이미 보관한 로컬 표시 범위를 늘리고 이후 원격 과거 25턴을 명시적으로 요청합니다. 안정된 turn/item ID로 연결하며 기존 로컬 메시지·첨부·목적을 보존합니다. 시간·연결 위치를 판단할 수 없는 레거시 페이지는 원본을 유지하고 거절합니다. 최초 페이지의 명시적 미지원(-32601)만 legacy 전체 조회로 돌아갑니다.

검증된 페이지를 저장 워커로 확정한 뒤 cursor를 전진시킵니다. 취소·프레임/연결/작업 폴더 변경에서 늦은 결과를 버리며 저장 시작 뒤에는 취소를 제한합니다. 취소는 진행 중 RPC를 물리 중단하지 않습니다. RPC는 최대 10초와 남은 조회 시간을 사용하지만 연결·이미지 처리·저장까지 전체 15초를 보장하지 않습니다. 전체 JSON 읽기·복사·페이지별 전체 저장은 남으며 끝까지 확장할 때 누적 I/O가 증가할 수 있습니다. CLI stdout은 조각 배열과 프레임별 UTF-8 64MiB 한도를 사용합니다.

현재 저장 워커·실패/복구 순서는 아래 저장 수명과 [로컬 안정화](LOCAL_STABILITY.md)에 있습니다. renderer 의존성은 번들에 포함되어 배포의 node_modules 원본은 제외합니다. 전체 라이선스 고지는 빌드 시 THIRD_PARTY_NOTICES.txt로 모아 앱에 포함합니다.

## 저장·화면 수명

`Store.saveAsync()`는 한 번에 하나의 저장만 실행한다. `store-worker.cjs`가 기존 Store의 직렬화·해시·저널·파일 교체를 수행하며 저장 성공 후 메인 등록부를 반영한다. 저장 중 상태를 바꾸는 IPC는 저장 완료를 기다리고, 포인터·창 열기·복사 같은 조작은 계속 처리한다. 접수·thread 연결·완료·측정·취소·정상 종료의 큰 대화 저장을 맡기며 작은 설정/초기 읽기/대화 전환/삭제 복구는 동기 경로를 유지한다. 정상 종료는 진행 중 저장과 중단 상태 저장을 마친 뒤 워커를 정리한다. 워커 비정상 종료/시간 초과에서는 원본·저널을 보존하고 쓰기를 막는다. 구조화 복사의 비용과 동기 읽기/일부 전환은 남는다.

목록은 저장 변경 버전으로 정렬·전송을 캐시한다. 숨겨진 패널은 네이티브 창 표시와 페이지 표시를 함께 확인하고 변경분을 기억해 다시 보일 때 화면을 갱신하며, 심플은 현재 assistant 또는 마지막 전달 assistant 하나만 만든다. 빈 대기 취소 카드는 전달 답변을 밀어내지 않는다. 같은 메시지의 텍스트 JSON 바이트 수를 캐시해 질문 접수 용량 계산의 반복 비용을 줄인다. CLI 스트림은 답변 총량·항목 개수·승인 데이터의 상한을 두고, 불완전한 변경 미리보기로는 허용할 수 없다.

응답 도착 상태는 메인에서 통일한다. renderer 종료 시 UI만 한 번 자동 재로드하며 재실패는 트레이의 화면 복구로 안내한다. 로딩/종료된 프레임에는 상태를 보내지 않고 모델 질문은 자동 재전송하지 않는다.


## 버디·팩 경계

`packs.cjs`는 data-only schema와 immutable byte snapshot/revision을 읽는다. `asset-validator.cjs`는 Node/preload/network 없이 숨긴 sandbox 창의 실제 decode 수명·timeout을 맡는다. `pack-library.cjs`는 팩 폴더·선택 설정·새 persona 템플릿의 단계 기록/소유 해시/복구/폴더 export를 맡는다. 별도 모듈로 분리한 이유는 실제 검증·디스크 실패 경계가 다르기 때문이며 단일 필드 변경이나 UI 문자열을 범용 helper로 추출하지 않았다.

목록은 metadata/썸네일, 선택한 팩만 자산/프레임을 보내고 revision으로 렌더러 재로드를 구분한다. 프레임 timer는 이미지 src만 바꾸며 창 bounds·포인터 IPC·디스크 상태와 분리한다. 캐릭터 envelope는 배율/팩 변경에서만 갱신하고 안내 표시/숨김은 별도 notice 창만 갱신한다.

사용자 말투 registry와 생성 복구 journal은 PersonaLibrary에 둔다. 질문은 접수 당시 instructions/hash를 유지하므로 이후 편집·팩 교체가 이미 접수된 질문을 다시 해석하지 않는다. 팩 구조 변경은 진행 중/대기 작업이 끝난 뒤 수행한다. 절전은 실행을 중단하고 큐를 보존하되 자동 재전송하지 않는다. 화면 잠금은 표시/animation/렌더 ACK를 억제하며 저장된 사용자 reduced-motion 설정을 바꾸지 않는다.

## 접수·턴·복구 경계

질문 접수는 첫 await 전에 문맥·이름·말투를 캡처하고 대기 자리를 예약합니다. queue와 아직 저장되지 않은 preparing의 합은 10 이하입니다. 접수 확정 Promise, 단일 모델 실행 큐, Store 쓰기 워커는 각자의 순서를 보장하며 새 큐 모듈이나 범용 dispatcher를 추가하지 않았습니다.

CodexConnection은 turn/start RPC 응답으로 소유 턴을 확정합니다. 그 전에 오는 턴/item 알림은 128개·256KiB 이내에서 보류하고 응답 ID와 맞는 알림만 순서대로 적용합니다. 다른/옛 턴은 현재 interrupt 대상을 덮어쓰지 않습니다. 메인은 job의 thread/turn을 명시해 중단하며 완료 저장은 해당 job의 종료 Promise가 한 번 소유합니다. 저장 중에도 cancel/respond의 제어 경로는 처리합니다.

Store는 canonical 폴더·파일 링크를 검사하고 staged 파일을 배타 생성합니다. 저널 없는 일반 잔여 파일은 고유 이름으로 보존하며 링크를 따라 쓰지 않습니다. 삭제는 기록된 pending scope와 같은 CLI/작업 폴더의 소유 ID만 확정합니다. pet/notice renderer 복구는 noticeHitRevision을 증가시키고 안내창이 같은 사각형도 다시 등록하도록 합니다. renderer는 성공 ACK를 받은 사각형만 캐시합니다.

composer는 submit을 동기적으로 잠그며 새 대화 ID가 만들어질 때 제출 중 작성한 다음 초안을 그 대화로 옮깁니다. 숨긴 panel은 상태·메시지 캐시를 갱신하고 DOM 갱신은 표시할 때 수행합니다. 자세한 회귀와 미검증 조건은 [수정 결과](history/ISSUE_REMEDIATION_RESULT_2026-10-08.md)에 기록합니다.

## 연결·응답 이미지

`connection-setup.cjs`는 인증 확인·로그인 시도 ID·5분 취소 타이머·공식 URL 검증의 수명을 담당합니다. `main.cjs`는 기존 연결/큐의 소유권을 유지하고 연결이 끊긴 뒤 유휴 상태에서 한 번만 자동 복구합니다. 연결·인증·모델 목록 준비를 구분하고, 중단된 질문을 재전송하거나 대기 큐를 자동 재개하지 않습니다. 탐색된 다른 CLI는 initialize 확인 후 기존 기록을 보존하며 새 대화와 설정을 확정합니다. 기존 캐시를 먼저 확인하고 공용 CLI 인증 토큰을 앱에 복제하거나 로그아웃하지 않습니다.

메인은 이미지 완료를 job의 순차 Promise에 추가하고 종료 저장 전에 기다립니다. 대화에는 최대 8개의 메타데이터만 저장하고 base64는 저장하지 않습니다. renderer는 화면에 가까운 이미지의 작은 미리보기만 읽고, 원본 열기는 활성 소유 대화의 참조를 다시 검사합니다. 원격 Markdown 이미지 로딩 정책은 유지합니다. 기존 기록 조회는 텍스트와 이미지 결과를 함께 병합하며 새 모델 턴을 시작하지 않습니다. 초기 turn/start RPC 전 알림은 기존 128개·256KiB 제어 한도와 별도로 이미지 payload 32MiB 한도를 적용합니다.

이미지 저장 폴더·decode·파일 크기 오류는 해당 이미지의 실패 안내로 처리하며 텍스트 기록을 유지합니다. 생성 중단/재시작 후 pending은 실패로 확정하고 기존 CLI 원본을 다시 확인할 수 있습니다. 상세 범위와 현재 검증은 [연결·이미지 적용 기록](CONNECTION_AND_IMAGES_2026-10-08.md)을 참고합니다.

## 첨부·대기열

파일 선택창은 메인에서 열고 선택한 일반 파일만 `AttachmentStore`로 읽습니다. renderer는 원본 경로 대신 메인이 발급한 대화별 임시 ID를 사용합니다. 파일은 해시 이름의 불변 사본, 이미지는 기존 응답 이미지 저장·격리 decode·미리보기 경계를 재사용합니다. 파일/이미지 조회는 링크·해시·바이트 상한을 다시 검사하고 읽는 도중 크기가 늘어도 제한된 버퍼만 읽습니다. 대화에는 이름/치수/해시 참조만 남기며 원본 경로나 base64를 저장하지 않습니다.

일반 첨부의 용량 조사는 기존 전체 파일 검사를 유지하며 128개마다 이벤트 루프에 제어권을 돌려줍니다. 양보 후와 마지막 부분 구간에서 폴더의 realpath·dev/ino·mtime/ctime을 다시 확인해 검사 중 폴더 교체나 목록 변경을 거부합니다. 메인의 첨부 선택 경로가 가져오기와 보관 작업을 직렬화하며, `AttachmentStore` 자체의 동시 가져오기나 외부 프로세스의 기존 파일 내부 변경에 대한 원자적 스냅샷을 보장하지 않습니다. I/O 횟수 감소나 이미지 decode 최적화로 해석하지 않습니다.

접수는 첨부 ID를 첫 await 전에 예약하고 질문·첨부·모델·말투를 같은 FIFO에 고정합니다. 선택·접수 실패는 초안을 유지하며 전송 성공 시 해당 첨부만 초안에서 제거합니다. renderer의 입력/첨부 초안은 대화 ID별로 분리하고 새 대화의 첫 접수 시 ID를 이전합니다. 첨부 데이터의 저장 실패 경계만 모듈로 분리했고 질문 실행 큐·예약 순서·UI 상태는 기존 함수에 인라인으로 유지합니다.

CLI 입력은 이미지의 `localImage`와 사용자 원문 텍스트입니다. 일반 파일은 파일명·보관 경로를 추가 텍스트 자료로 전달해 기존 read-only CLI 도구가 읽게 합니다. app mention을 파일 입력으로 사용하지 않습니다. 원격 기록을 다시 읽을 때 첫 사용자 텍스트와 기존 첨부 메타데이터를 병합하므로 자동 자료 안내가 사용자의 원문을 덮어쓰지 않습니다. 취소된 대기 질문·재시작/연결 중단의 불확실한 질문은 자동 재실행하지 않습니다. 실제 모델/테스트 CLI 검증과 남은 조건은 [첨부·대기열 적용 기록](ATTACHMENTS_AND_QUEUE_2026-10-10.md)에 있습니다.

## alpha21 표시·리사이즈·기록 읽기

심플의 표시 세대는 시간 측정 옵션과 독립적이다. main은 대화·답변·renderer 세대와 표시 상태를 확인해 30초 deadline을 소유한다. renderer는 현재 답변과 이미지 미리보기 준비/실패, 초안·IME·팝오버 상태를 보낸다. 진행·대기·저장·첨부·승인·중요 오류 동안 유예하고 보호가 끝나면 다시 30초를 준다. X는 즉시 전체 창을 숨기며 초안이나 작업을 지우지 않는다. 초기 자동 높이 조절이나 창 resize에서는 열린 팝오버를 현재 버튼·viewport에 맞춰 재배치하며 임의로 닫지 않는다.

리사이즈는 main의 세션 token·현재 frame·작업 영역으로 검증하며 RAF와 한 번의 진행 요청으로 묶는다. 문서의 현재 pointer ID로 종료를 받으므로 창 이동으로 대상이 달라져도 종료한다. 시작 IPC 응답보다 먼저 정상 pointerup이 오면 마지막 좌표를 해당 token으로 적용한 뒤 종료한다. cancel/lost에서는 마지막 변경을 추가하지 않는다. 단순 필드 처리를 별도 모듈로 추출하지 않았다.

readHistory는 확인한 FD 크기+1의 Buffer만 읽으며 후속 파일 identity·크기·수정 시각을 확인한다. 상한은 32MiB+1이고 finally에서 FD를 닫는다. alpha22는 state/저장·삭제 journal 및 복구 대상 여섯 경로에도 제한 FD 읽기·엄격한 UTF-8·변경 감지를 적용했다. 읽기/JSON parse의 worker 이전과 전체 스냅샷 비용은 남는다.
