# 개발 구조

macOS·Windows 환경 준비, 빌드 명령과 결과물, 플랫폼별 검증·배포 범위는 [빌드 가이드](BUILD_GUIDE.md)를 참고한다.

```text
캐릭터 창 ─┐
           ├─ 좁은 preload IPC ─ main.cjs ─ codex.cjs ─ Codex app-server (stdio)
말풍선 창 ─┘                      │
                                 ├─ packs.cjs: 팩 검증·이미지 데이터
                                 └─ store.cjs: 설정·소유 대화 목록·대화별 파일
```

Electron 44.5.1, 메인 프로세스는 Node 기반 CommonJS. 렌더러는 DOM/CSS/SVG를 사용하고 Node 통합을 끕니다. Electron context isolation과 renderer sandbox를 켜고 preload의 제한된 동작만 노출합니다. 원격 웹 콘텐츠를 로드하지 않습니다. 사용자의 입력은 `textContent`, 모델 출력은 markdown-it 15.0.2 + CJK 강조 플러그인 3.0.0의 HTML 비활성 파싱과 DOMPurify 3.4.16의 태그/속성 허용 목록으로 정제한 DOM fragment로 표시합니다. 렌더러 ESM 소스와 의존성은 esbuild로 로컬 파일 하나에 묶고 앱에 포함합니다. 실행·체험·검증·패키징 명령은 번들을 먼저 빌드합니다.

`models.cjs`는 model/list 페이지 처리, config/read의 CLI 기본값, 모델별 추론 호환성을 담당합니다. 메인 프로세스가 질문 접수 시 모델·추론 단계·서비스 속도를 해석해 큐와 메시지에 고정하고 `turn/start`에 명시합니다. 속도는 CLI의 `serviceTiers`에서 읽고 `serviceTierForTurn`에 요청별로 전달합니다. 모델 정보는 UI 접근 때 5분 캐시를 확인하며 실행 파일 변경 시 유휴 상태에서 연결을 재시작합니다. CLI 설정 파일을 쓰지 않습니다. 모델 목록은 실행 권한 검증을 대신하지 않습니다.

`main.cjs`가 프로세스·창·큐·설정의 소유자입니다. 한 질문을 실행하고 완료 또는 중단 상태가 확정되면 다음 질문을 실행합니다. 승인 응답과 중단 동작은 질문 FIFO에 넣지 않습니다. Codex 요청 ID와 대화/턴 ID를 사용해 응답을 연결합니다. 팩 교체는 이미지 데이터만 바꿉니다.

스토리지가 작아 알파에서 원자적 JSON 파일 교체를 사용합니다. 토큰마다 디스크에 쓰지 않고 질문 접수·완료·설정 변경 시 저장합니다. 스트리밍 화면 갱신은 50ms로 묶고 완료는 즉시 예약하며 큰 캐릭터 이미지는 카탈로그 변경/초기 연결 때만 전송합니다. 변경된 메시지만 Markdown을 다시 파싱합니다. 실행 중 메모리의 부분 응답은 비정상 종료로 손실될 수 있습니다. CLI가 보관한 대화 기록과 화면 기록은 별개입니다. v2는 소유 대화 목록과 대화별 파일을 분리하고 메시지가 바뀔 때만 해당 파일을 씁니다. 설정/위치만 바뀌면 대화 직렬화를 생략합니다. 캐릭터 창에는 전체 대화 대신 필요한 상태만 보냅니다. alpha.7은 목록/대화 교체를 저널로 묶어 프로세스 종료 시 복구합니다. 완전한 DB 트랜잭션·전원 장애 내구성을 보장하지 않습니다. 목록에 있는 threadId에 한해서 `thread/read`로 텍스트 기록을 확인하고, 다음 질문 때 `thread/resume`합니다. 자세한 저장·이관 범위는 [이전 대화](CONVERSATIONS.md)에 있습니다.

## 창 동작

기본 캐릭터 대기 창 120×143, 안내가 보일 때 196×195, 말풍선 창 430×최대 690 논리 픽셀입니다. 작은 화면에서는 말풍선 높이를 줄입니다. 마우스 이동 시 즉시, 정지 상태에서는 80ms 간격으로 실제 클릭 영역을 확인합니다. 캐릭터·표시 중인 안내·표시 중인 버튼 밖에서는 `setIgnoreMouseEvents`로 뒤쪽 앱의 클릭을 통과시킵니다. 보이지 않는 하단 버튼은 클릭 영역에서도 제외합니다. 네이티브 창을 줄일 때 캐릭터의 화면 좌표를 유지하고 예전 250×270 위치 기록도 같은 기준점으로 변환합니다. 드래그는 시작 지점부터의 절대 마우스 좌표를 사용하고 포인터 캡처를 유지합니다.

참고: [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)의 `setBounds`와 `setIgnoreMouseEvents` 동작을 확인했습니다. 대화창은 화면 작업 영역 안에서 캐릭터 옆에 배치합니다. 캐릭터는 화면 경계의 강제 제한 없이 이동하며 안내 창 크기 변경에서도 캐릭터 앵커를 유지합니다. 재시작·화면 구성 변경에서 보이지 않는 캐릭터만 기본 위치로 복구하고 트레이에서 직접 초기화할 수 있습니다. macOS 전용 패널 옵션과 공통 동작의 구분, 실제 검증 범위는 [플로팅 보완](FLOATING_PET_UPDATE.md)을 참고합니다.

## 아이콘 재생성

`npm run icons:generate`는 기본 캐릭터 SVG를 렌더링해 앱 PNG·Windows ICO를 만들고, 사용자 원본 `assets/tray-source.png`에서 18px/36px 메뉴 막대 PNG를 생성합니다. 템플릿 표시는 macOS에서만 검증합니다. macOS에서는 `npm run icons:icns`가 sips와 iconutil로 필요한 해상도를 생성하고 `.icns`로 변환합니다.

현재 제공된 `.icns`는 이미 생성되어 있어 일반 빌드에서 다시 만들 필요 없습니다.

## 다음 확장

Slack 수신은 로컬 Socket Mode부터 시작할 수 있습니다. 지정 채널의 멘션·키워드를 먼저 필터링한 뒤 필요한 메시지만 의미 판단에 사용합니다. 알림 이벤트는 작업 큐와 별도로 전달해 긴 Codex 작업 뒤에 밀리지 않게 합니다. 아직 실행 가능한 Slack 모듈이나 서버 코드는 만들지 않았습니다.

캐릭터 팩 규격은 안정적으로 버전 관리하지만, 미래 확장을 위한 범용 플러그인 프레임워크는 만들지 않습니다. 새 입력 채널이 생길 때 실제 요구에 맞춰 경계를 확장합니다.

선택형 응답 측정은 메인 수신·CLI stdin 전송·첫 텍스트·턴 완료와 보이는 대화창의 프레임 ACK를 연결합니다. [측정 기준](RESPONSE_TIMING.md), [구조/코드 검토](PROJECT_REVIEW.md)를 참고합니다.

## alpha.7 전송·복구

패널에는 최근 최대 100개/256KiB 텍스트부터 보여 주고 ID 순서와 변경된 메시지만 전송합니다. 렌더러는 메시지/카드 Map을 유지하고 이전 내용을 요청하면 추가합니다. 로컬 기록 파일과 CLI 전체 기록을 메모리에서 분할 읽는 구현은 아직 없습니다. CLI stdout은 조각 배열과 프레임별 UTF-8 64MiB 한도를 사용합니다.

저장 저널 검증·JSON 저장은 동기 방식입니다. 상세한 실패/복구 순서는 [로컬 안정화](LOCAL_STABILITY.md)에 있습니다. renderer 의존성은 번들에 포함되어 배포의 node_modules 원본은 제외합니다. 전체 라이선스 고지는 빌드 시 THIRD_PARTY_NOTICES.txt로 모아 앱에 포함합니다.
